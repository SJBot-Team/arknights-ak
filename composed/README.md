# composed/ —— 组合知识区（T3）

> **性质**：从 knowledge（T1/T2）基础知识**组合推导**出的应用/方案知识。**绝对正确性无法保证**——它是"推导链 + 来源 + 假设"的记录，不是权威结论。
> **谁可写**：所有任务执行者（任何会话/agent）。记录或修改成型的组合知识，须遵守本 README 规则并登记任务台账。
> **谁可改 T1/T2**：仅主会话（AK 知识库会话）与解包程序可修改 `knowledge/`（基于代码/解包的确定性知识），防止未检验内容污染权威知识或影响知识权重。
> 详细规范：`meta/流程规范.md`。

## 与 knowledge/ 的区别

| | knowledge/（T1+T2） | composed/（T3） |
|---|---|---|
| 性质 | 权威知识（✅/🟡/🔴） | 组合推导（❌ 未验证为主） |
| 来源 | 代码/解包/高信度社区（多源） | knowledge 条目的组合 + 推导过程 |
| 写权限 | 仅主会话/解包程序 | 所有执行者 |
| 进 AI skill 权威速查 | ✅ | ❌（可作为参考但不入权威表） |
| 验证升级 | — | 模拟验证/实战复核后 → 主会话审议升 T2 并入 knowledge |

## 条目格式

每个组合知识一个文件，头部必须包含：

```markdown
# 标题（组合知识）
> 类型：T3 组合知识（非代码验证） | 创建：<会话/agent> | <日期>
> 引用：[knowledge/目录 条目/来源] ×N        ← 推导所依据的知识（每源标注）
> 推导链：<步骤式说明如何组合出本结论>
> 假设/未验证项：<哪些环节未经代码/实战验证>
> 验证状态：❌ 未验证 / 🟡 模拟验证（sim/xxx）/ ✅ 实战复核（待主会话升 T2）
> 更新记录：<每次修改追加一行：谁/何时/改了什么>
```

## 内容分类建议（积累后按主题建子目录）

- 应用战术类（如"阻挡偏移入坑"摆位）
- 关卡解法推导类
- 数值方案类（输出轴/费用轴排布）
- 模拟参数假设类（搭 sim 时用到的 T3 假设）

## 流转规则

1. 执行者生成组合知识 → 写入本区 → 任务台账登记（引用条目）。
2. knowledge/ 引用本区内容时必须标 "T3 假设"。
3. 模拟验证通过（sim/reference）或实战复核 → 主会话审议 → 可升 T2 并入 knowledge 主题区并标注来源。
4. 长期未被验证/被推翻 → 标记废弃（保留记录便于追溯），不删除。
