# 数据源导航（Data Source Navigation）

> 本知识库获取游戏数据的全部外部渠道清单。**优先级原则**：本地解包验证 > 解包数据仓库（ArknightsGameData）> 网页数据站 > PRTS 文档。能标准流程本地获取的，不依赖网页。
> 用途：①解决问题时选择数据源；②了解各源能提供什么知识、与解包对比哪些更快由代码获得。
> 更新：2026-09-02 首版（T-025）；2026-09-02 二版（T-026：地图/干员/敌人解包标准流程建立 + 敌人逐级数值本地补齐）；2026-09-02 三版（T-027：露托 API 探明 + 出怪时序本地化 + 指标词条 tag 机制）。

## 四、全量信息处理方案（干员/敌人/地图大数据量）

**原则：knowledge 只存"简要知识"，全量精确数据随用随取（标准流程），不复制进知识笔记。**

1. **干员/敌人全量** → `data/gamedata_akgd`（原始表：character/skill/enemy_handbook/enemy_database/range/token）+ `code/unpack` 提取脚本；需要时按 ID 取数，不落 knowledge。
2. **地图 tile 全量** → 客户端 scenes AB（E 盘 client_res 按需补副本）`extract_level_map.py`；MAA Tile-Pos（本地 4177 关）可交叉验证。
3. **简要知识层**（knowledge）：存"关系/规则/索引"（如：职业分支表、伤害公式、机制规则、数据源导航），帮助 agent 知道**去哪里取什么**，而非存全部数据。
4. **少人/极限记录** → 网页实时查询（arkrec API）或本地缓存近期记录；作为"最优解参照"而非权威数据。
5. **随用随取的标准流程**（skill 中给出）：问"干员 X 属性" → character_table 提取；问"敌人 Y 数值" → enemy_database_full（基值）；问"关卡 Z 地图" → 关卡场景 AB；问"关卡 Z 出怪/路线/坐标" → 主仓 levels（fetch_level.py + parse_level_spawns.py）；新活动/指标词条 → 露托 API（fetch_level_lutonada.py / fetch_lutonada_tag.py）。
