## 二、三处必须回修的认知（最重要）

### 2.1 K-003：「0.4 / 0.2」涉及**两套不同机制**（本条曾被改错，已更正）

> ⚠️ **2026-09-13 更正**：本条初版写成"0.4/0.2 不是胶囊碰撞箱而是阻挡间距"，**这个改法本身是错的**——它把玩家术语里的**碰撞**与**阻挡**混为一谈。详见 `37_阻挡与阻挡偏移_代码核验.md`。

**玩家术语的区分**：
- **碰撞** = 敌方单位 ↔ 高台/墙体（推拉失衡时撞墙）→ 用**物理碰撞箱：宽 0.2 × 高 0.4 × 向下偏移 0.1 的胶囊**
- **阻挡** = 敌方单位 ↔ 我方单位（能否被挡住）→ 用**阻挡半径 0.7071** + **阻挡偏移**

**因此正确结论是**：

| 数值 | 归属 | 说明 |
|---|---|---|
| **0.2 × 0.4（下偏 0.1）** | **碰撞** | 物理碰撞箱尺寸，**断言正确**；在 prefab 序列化 |
| 0.005 / 0.01 | **碰撞** | `Consts.TILE_COLLIDE_DISTANCE` / `_WIDE`（停靠 / contactOffset） |
| 0.4 / 0.2（`BlockBalancer`） | **阻挡偏移** | 另一套机制：`CLOSE_DIST_BTW_BLOCKEERS=0.4`、`MERGE_FACTOR_OF_SEPARATION=0.2`；**与碰撞箱无关，数值相同纯属巧合** |

`BlockBalancer`（dump 388256）：

```
MIN_DIST_BTW_BLOCKEES_SQR   = 0.010000001   // 0.1²   ← 阻挡偏移里 C 点半径 0.1
CLOSE_DIST_BTW_BLOCKEERS    = 0.4
CLOSE_DIST_BTW_BLOCKEES_SQR = 0.16000001    // 0.4²
MERGE_FACTOR_OF_SEPARATION  = 0.2           ← 修正向量固定长度 0.2
```

`CalculateBlockOffset`（RVA 0x7C1050）内的常量已全部定位，与 cv25694535 描述的算法逐项吻合（含 ×50、1e-05、`Enemy.get_stableBlockPosition()`）—— **完整算法见 `37_阻挡与阻挡偏移_代码核验.md`**。

`0.0327872`（磕墙角）与胶囊几何仍属 prefab/实测 ⇒ 🔴，需解敌人 prefab 的 `CapsuleCollider2D`。

### 2.2 K-010：「选敌时检查 hp>0」**不存在**

真实闸门是 `TargetOptions._VerifyAdvanced`（RVA 0x6DEF10）→ **`Entity.get_isTargetFree()`**（RVA 0x360BAA0），判据为 `m_isLocated`(0x88) 与 `BObject.isDisappeared`(0x26) + 异常标记（`TARGET_FREE=2` / `INVINCIBLE=5` / `INVISIBLE=9`）——**全程不读 `Entity.m_hp`(0x40)**。
⇒ 模拟时不要把 `hp>0` 写进通用选敌条件（会与 `isTargetFree`/异常掩码语义冲突）。

### 2.3 K-002：力度是**查表**，不是多项式

`BattleFormula.CalculatePullForce(int pullForceLevel, int massLevel)`（RVA 0x3586760）：

```
index = pullForceLevel + pullForceZeroIndex − massLevel
index = clamp(index, 0, pullForces.Length − 1)
return GameDataConsts.pullForces[index]
```

`CalculatePushForce(int, int, Vector2Int pushForceRange, out int pushForceIndex)`（0x3586840）同构，且**二次钳位到 `pushForceRange`** 并回写 out。
表宿主 `GameDataConsts`：`pushForces // 0x1D0`、`pushForceZeroIndex // 0x1D8`、`pullForces // 0x1E8`、`pullForceZeroIndex // 0x1F0`。
⇒ 复刻**必须拿表**（数据侧）；用多项式拟合会引入不可控误差。

## 六、`read_cpp.py` 已知缺陷（本次暴露）

1. **`m <类>.<方法>` 对"存在同名嵌套类"的类会失败**：`find_class_range` 的正则会把 `public struct RebornTalent.AdvancedRebornData` 之类误当目标类（前缀匹配）。
2. **`who` 的 RVA 索引在高区段有错标**：如把 `BattleController.FinishGame` 的调用点标成 `Map.GenerateRuntimeRoute`。**高 RVA 的标签需交叉验证**。
3. `call` 命令遇到第一个 `ret` 即停，对多返回块的大方法（如 `LoadGame`）会漏调用点。
