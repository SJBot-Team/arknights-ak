## 二、可吸取的经验（按价值排序）

### ★ 经验 1：把"判定口径"显式化为可执行断言（A1~A9 / L0~L9）

该会话最重要的工程实践是**把口径做成断言**：

- **语义断言 A1~A9**（`verify_semantics.py`）：如 "A1 碰撞体积不参与索敌"、"A5 AoE 只看目标中心所在格"、"A6 远程敌人触及 = `rangeRadius ± 0.25`"。**断言全绿才允许继续**。
- **问题分层登记 L0~L9**（`60_问题登记_按工作层级.md`）：数据层 / 几何层 / 判定层 / 数值层 / 调度层 / 记录层 / 校验层 / 打图识别层 / 执行层 / 合规层，每层带编号与状态。

**为什么值得学**：这两样把"我以为对"变成了"可检查"。**我们此前的知识库只有结论、没有可执行断言**——建议把这套做法吸收进知识库：每个机制结论旁边附一条**可复现的判定式**。

### ★ 经验 2：双观测联合判据（M2 的对策）

`40_错误总结与反思.md` 的 M2 指出"**用一个错误补偿另一个错误**"出现过 **3 次**，并给出对策：

> **单一观测几乎总能被某个错误参数"对上"** ⇒ 必须要求"阻挡帧 + 伤害帧"**同时**满足。

实例：`margin 1.0 + 吸附` 能让伤害对上（2.19），但阻挡偏差恒定 −32/−31；`margin 0.1` 让阻挡对上（−4/−1）但伤害退化。**只有单观测时，两种错法都"看起来成立"**。

**这是本项目最值得固化的方法论**：任何机制模型，至少要有两个独立观测同时成立才算通过。

### ★ 经验 3：建立"可信数据源通道"，用实测取代拟合

K9：打通客户端 AB 实测通道（UnityPy + LZ4AK）后，**一轮就推翻了两个长期假设**（受击半径、阻挡判据）。
⇒ 教训与我们的做法一致：**能实测就不反推**。

### ★ 经验 4：把"共用轴表"作为跨工具的对齐基准（K1）

`ak/axis/<stage>.yaml` 同时驱动**模拟器 / 打图端 / 校验器**，帧号一律用游戏帧 ⇒ 三方天然对齐。
**这是把"对齐问题"从工程问题降级为数据问题的漂亮做法。**

### 经验 5：错误台账要记"根因 + 已加机制"，不记流水账

`40_错误总结与反思.md` 每条错误都给"错误 / 根因 / 后果 / **已加机制**"四列。例如 E4（切片字段假补全）→ 加 `test_slice_fields.py`（**有值**回归）；E9（开关没接进 `__init__`）→ 加"开关对比冒烟要求"。
⇒ **把教训转成机制**，而不是转成文字。

### 经验 6：卡住时收敛到单线深挖

流程反思里有一条实证观察：**用户指示暂停打图线后，模拟线两轮内解决了 3 个长期 OPEN 项**。
