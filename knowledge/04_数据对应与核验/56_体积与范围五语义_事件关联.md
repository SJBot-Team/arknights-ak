## 一、用户原话要点（★作为实现约束）

### 第一批（2026-09-15）

1. **攻击索敌应为方格范围**：索敌（选取攻击目标）时，应以**方格**为单位进行范围判定。
2. **索敌时需要考虑受击判定的体积**：单位具有一个「受击判定体积」，在**索敌阶段**应被纳入考量。
3. **体积的主要用途是完成索敌**：在大多数情况下，这个判定体积是用来完成一次（目标）索敌的，
   而**不是**用于判断是否被范围攻击命中。
4. **范围攻击的命中判定方式**：部分范围攻击判定的是「**目标中心是否位于选定的格子内**」，
   因此这类攻击的命中**不依赖受击体积**，而是依据**目标中心点所在的格子**。

### 第二批（2026-09-15，★核心：**两个阵营的范围表示不同**）

5. **我方（近战干员，如芬）索敌 = 方格范围**：
   - 芬的索敌范围 = **2 个方格**（自身格 + 朝向前方 1 格，表驱动 `range_table.json`）；
   - **无阻挡时**，**敌人的 0.1 圆**进入该范围 ⇒ 芬索敌、**开始前摇**。
6. **敌方（远程敌人）索敌 = 半径圆**：
   - 远程敌人的攻击范围通常是**一个确定半径的圆**（`enemy_database.rangeRadius`）；
   - **干员的 0.25 圆**处于该圆内 ⇒ 敌人开始攻击。

⇒ **两侧不要互相套用**：我方是"**格 + 目标体积**"，敌方远程是"**圆 + 我方面积**"。

## 三、索敌（② + ③）的精确定义 —— **两侧分别实现**

### 3.1 我方（干员）索敌 = **方格范围 + 敌人受击圆**

```python
targetable_ally(op, e)  ⇔  cell(e.center) ∈ cells_in_range(op)                    # ③ 方格范围
                         ∨  dist(e.center + e.hit_offset, 某个范围格) ≤ e.hit_radius   # ② 受击判定体积
```

- **`dist(点, 格)`** = 点到**方格区域**的最短距离（点在格内 = 0）
  ⇒ "受击圆与范围格相交" ⇔ `dist ≤ 受击半径`（几何等价）。
- **近战干员的 2 格**（1-1 芬：`range_grids=[[0,0],[1,0]]` 朝左 ⇒ 世界格 `{(3,5),(3,4)}`）。
- **敌人受击半径默认 0.1**（客户端 prefab 实测小怪碰撞体 0.1）。
- **判据会被写进事件**：每次索敌成功记一条
  `target_select {side:'ALLY', unit, target, judge:'grid'|'hit_volume', hit_radius}`。
- **`hit_offset` 的必要性**：客户端 prefab 实测敌人的判定体**不是"以位置为心的圆"**，
  例如 `CapsuleCollider2D m_Size=(0.2, 0.4) m_Offset=(0.0, −0.1)`
  ⇒ 判定体的触及范围**与方向有关**。`hit_offset` 就是为逐单位填入该偏移而设（当前默认 `(0,0)`）。

### 3.2 敌方（远程敌人）索敌 = **半径圆 + 干员受击圆**

```python
enemy_reach(e)  = rangeRadius ± ally_hit_radius(0.25)      # 见 Battle.enemy_reach
targetable_enemy(e, o)  ⇔  dist(e, o) ≤ enemy_reach(e)
```

- 数据：`enemy_database` 的 **`rangeRadius`**（近战为 0）+ **`applyWay`**（MELEE / RANGED）。
  实测样例：猎狗/猎狗pro/源石虫/暴徒 `rangeRadius=0`（MELEE）；**`enemy_1028_mocock` = 1.75（RANGED）**。
- 两种取交方式（`options={'enemy_range_mode': …}`）：
  - **`'intersect'`（默认）**：两圆**相交**即算"进入范围" ⇒ 有效触及 = `rangeRadius + 0.25`；
  - `'contain'`：干员圆需**完全落在**该圆内 ⇒ 有效触及 = `rangeRadius − 0.25`。
- **近战敌人**不走圆判据：打"当前阻挡者"，无阻挡时按**相邻格（切比雪夫 ≤1）**。
- 事件：`target_select {side:'ENEMY', judge:'blocked'|'melee_adjacent'|'circle_intersect'|...,
  range_radius, reach, ally_hit_radius}`。

> ⚠️ 不要把两条规则合并成一条：干员侧**不**用"以自身为心的圆"，敌方远程**不**用"方格表"。

## 四、与"旧口径"的关系（★必须知道的历史）

模拟器早期用**一条混用语义的近似**：

```
dist(e.center, op.center) ≤ 1.5        # 把"攻击范围"当成了"以自身为心的圆"
```

- 这个 1.5 是 §47（1-1 标定）里**拟合出来**的值：为让"帧 432 芬命中猎狗"对齐而起。
- **1-1 标定的最终成绩（16/16、平均 1.81 帧、最大 7 帧）是在该旧口径下取得的。**
- 用户 2026-09-15 明确该口径**语义不对** ⇒ 已改为"方格范围 ∪ 受击圆∩范围格"，并保留开关：

```python
options={'targeting_model': 'legacy_center_distance', 'range_distance_tol': 1.5}   # 复现历史 16/16
options={'targeting_model': 'grid_plus_hit_volume',
         'hit_volume_enemy': 0.1}                                                   # ★默认（语义正确）
options={'targeting_model': 'grid_only'}                                            # 纯方格范围
```

### 两种口径在 1-1 上的实测（同一复刻、同一严格口径）

| 口径 | 关键参数 | 可对齐 | **平均偏差** | ≤6 帧 | 最大 |
|---|---|---|---|---|---|
| 旧：中心距 ≤ 1.5（语义混用） | `targeting_model='legacy_center_distance'` | 16/16 | **1.81** | 15 | 7 |
| 新：方格范围 ∪ 敌人 0.1 圆 | 阻挡 1.0（旧） | 16/16 | 4.56 | 13 | 18 |
| **新：方格范围 ∪ 敌人 0.1 圆** | **阻挡 1.5（★当前默认）** | **16/16** | **2.56** | **15** | **7** |
| 新：方格范围 ∪ 敌人 0.1 圆 | 阻挡 `cell_3x3`（进入格或 8 邻格） | 16/16 | 3.27 | 14 | 7 |
| 新：方格范围 ∪ 敌人 0.1 圆 | 阻挡 0.5 | 16/16 | 6.44 | 8 | 18 |

`hit_radius` 细网格（0.00~0.60，步长 0.05）：**越大越差，最优 0.0** ⇒ 体积项不是 1-1 残差缺的拼图。

### ★★残余定位与修正（本轮的关键结论）

### ★★补 1（2026-09-15，补惯性后新增）：**两个观测（伤害帧 / 阻挡帧）之间的张力**

把"阻挡帧"也作为判据后（`sweep_block_frames.py`、`probe_block_combo.py`）：

| 配置 | 阻挡帧（模拟器） | 阻挡误差 | **伤害平均** |
|---|---|---|---|
| 直线 + `cell_3x3_round` margin 1.0 + 吸附（★当前默认） | [204, 412] | 31.5 | **2.19** |
| navmap 逐格 + 同上 | [203, 414] | 31.0 | **1.88** |
| 直线 + margin **0.1** | [232, 442] | **2.5** | 4.50 |
| 直线 + margin **0.0**（进入阻挡者所在格） | [**235**, 459] | 8.5 | 4.50 |
| navmap + `collision_pair`（碰撞体积相触 0.35） | [240, 465] | 13.0 | 4.56 |
| navmap + `capture_distance` 1.0 + 无吸附 | [219, 436] | 12.5 | 2.93 |

**读法**：
- **margin 0.0 让第 1 只的阻挡帧 = 235（标定 236，差 1 帧）** ⇒ 强烈提示实机规则是
  「**敌人进入阻挡者所在格 ⇒ 被阻挡**」；
- 但**同一规则下伤害帧变差**（4.50）⇒ 说明**"被阻挡的位置"与"能被芬打到的位置"之间还有缺失的一环**：
  最可能是**实机不做"吸附/瞬移"**，而是**停在接触点**，而芬的攻击范围恰好覆盖该接触点；
- 当前默认（margin 1.0 + 吸附）之所以伤害最好，是因为**吸附把敌人提前搬进了芬的范围**（一种补偿）。

### 补 1b（本轮新增）：偏差是**恒定**的 ⇒ 规则形状对，只是阈值差一档

`analyze_block_offset.py`（对两只敌人分别算偏差）：

| 配置 | 阻挡帧 | 偏差（相对 236 / 443） | 是否恒定 |
|---|---|---|---|
| 默认 `margin 1.0` + 吸附 | [204, 412] | **−32 / −31** | ★**恒定** |
| **`margin 0.1`** | [232, 442] | **−4 / −1** | ★**恒定（≈0）** |
| `margin 0.0` + 无吸附 | [235, 459] | −1 / +16 | 随敌人变 |
| `capture_distance 1.0` | [220, 434] | −16 / −9 | 随敌人变 |
| navmap 逐格 | [203, 414] | −33 / −29 | 随敌人变 |

⇒ **偏差恒定**说明：判据的**形状**是对的，只是**阈值**整体早了一个"档位"。
`margin 1.0` = "进入阻挡者周围 3×3 邻域"（**早 ~31 帧**）；
**`margin 0.1` = "（近似）进入阻挡者所在格" ⇒ 阻挡帧与标定只差 −4 / −1 帧**。
