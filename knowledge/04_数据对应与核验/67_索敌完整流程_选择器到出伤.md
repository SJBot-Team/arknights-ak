## 一、一句话总览

**成立，但要划边界。** 代码里「干员找攻击目标」这一件事的**唯一入口是 `SelectorTrigger.Search(bool force)`（RVA `0x714210`）**，它把活整包交给 `TargetSelector.FindTargets_DISPOSE(ILocatable)`（RVA `0x6DFDD0`）——即**触发选择器 ⇒ 能力选择器**的两级结构。因此**「索敌始于选择器」在"找攻击目标"口径下成立**。

**两个必须写明的例外**（PRTS 原话的边界）：

1. **阻挡扫描不走选择器家族**：`Character._SearchBlockee`（`0x703FC0`）→ `FilterUtil.FilterWithVolume`（`0x6BF800`），它**直接调过滤器、不经过 `TargetSelector`**。所以"选择单位"不等于"过选择器"。
2. **选择器不只用于索敌**：`TileSelector` / `SelfSelector` / `RootTileSelector` 选的是**地块/自身**，与攻击目标无关。PRTS 原文也承认这一点（"选择地块、选择单位的行为均由选择器控制"）。

**对 PRTS 表述的补强**：PRTS 的「触发选择器 / 能力选择器」二分**在代码里有硬对应**——`TargetTrigger.Search(bool)` 是 **abstract Slot 13**（抽象接口层），`SelectorTrigger` 是它的具体实现；而「能力选择器」就是 `Ability._selector : TargetSelector // 0x28`（RVA 见 §2.11）。

### 2.1 ① 「索敌」的入口方法

**答：`SelectorTrigger.Search(bool force)`，RVA `0x714210`（Override Slot 13）。**

关键指令实证：

| 地址 | 指令 | 含义 |
|---|---|---|
| `0x7142CF` | `mov rcx, [rbx + 0x48]` | 取 `SelectorTrigger.m_findTargetTicker // 0x48` |
| `0x7142DE` | `call 0x1805CF2F0` | `CompoundPeriodicTicker.get_isReady()` |
| `0x7142E5` | `jne 0x1807142F0` | 已就绪 ⇒ 直接往下走 |
| `0x7142E7` | `test dil, dil` / `je 0x180714515` | 未就绪 **且** `force==false` ⇒ **返回 false，不索敌** |
| `0x7142FF` | `call 0x1805CEC10` | `CompoundPeriodicTicker.Next()` |
| `0x714337` | `call 0x1806DFDD0` | **`TargetSelector.FindTargets_DISPOSE`** ← 交接给选择器 |
| `0x714363` | `cmp eax, [rbx + 0x24]` | `List.Count` vs `_minTargetNum // 0x24` |
| `0x714366` | `jl 0x18071448D` | 目标数不足 ⇒ 失败分支 |
| `0x71436C` | `cmp byte ptr [rbx + 0x20], sil` | `_keepTarget // 0x20` |

⇒ **`Search` 是"节拍闸门 + 委派"**：自己只做 tick 判定、最小目标数判定、保目标判定，**真正的选人逻辑全在 `TargetSelector` 家族**。

### 2.2 ② 每 3 帧一次的索敌扫描

**答：`CompoundPeriodicTicker`，挂在 `SelectorTrigger.m_findTargetTicker // 0x48`；周期默认 3，可在 `Reset` 里被 `_overrideSearchTargetTick` 覆盖。**

| 环节 | 类.方法 + RVA | 实证 |
|---|---|---|
| 常量 | `SelectorTrigger.SEARCH_TARGET_TICK = 3`（`dump.cs` 375086） | `protected const int SEARCH_TARGET_TICK = 3;` |
| 覆盖字段 | `SelectorTrigger._overrideSearchTargetTick // 0x28` | `[Tooltip("Override internal search tick's period if this is >= 0")]` |
| 每帧推进 | `SelectorTrigger.FixedUpdate()` `0x713EE0` → `CompoundPeriodicTicker.Tick()` `0x5CF010` | `0x713F2C jmp 0x1805CF010`（尾部调用） |
| 闸门 | `CompoundPeriodicTicker.get_isReady()` `0x5CF2F0` | 见 §2.1 |
| 消费 | `CompoundPeriodicTicker.Next()` `0x5CEC10` | 见 §2.1 |
| **周期注入** | `SelectorTrigger.Reset()` `0x714030` | 见下 |

`SelectorTrigger.Reset` 的**分支实证**（`0x71414A`–`0x7141D4`）：

```
0x71414A  mov  rdi, [rbx + 0x48]          ; rdi = m_findTargetTicker
0x71414E  cmp  dword ptr [rbx + 0x28], 0  ; _overrideSearchTargetTick
0x714159  jge  0x1807141A4                ; >= 0 ⇒ 分支 B
--- 分支 A：_overrideSearchTargetTick < 0（默认）---
0x71416B  call 0x183563CE0                ; BattleController.get_isDeterministic()
0x71417F  movzx edx, al                   ; arg2 = isDeterministic
0x71417C  xor  r8d, r8d                   ; arg3 = waitFirstPeriod = false
0x714185  call 0x1805CEDB0                ; CompoundPeriodicTicker.Reset(bool,bool)  ← 不传 period
--- 分支 B：_overrideSearchTargetTick >= 0 ---
0x7141BE  mov  r8d, [rbx + 0x28]          ; arg3 = period = _overrideSearchTargetTick
0x7141D4  call 0x1805CEEF0                ; CompoundPeriodicTicker.Reset(bool,int,bool)
```

⇒ **`_overrideSearchTargetTick < 0`（默认）时周期保持构造期的 3；`>= 0` 时才被覆盖**，与 Tooltip 语义逐字吻合。`isDeterministic` 来自 `BattleController.get_isDeterministic()`（RVA `0x3563CE0`）——**注意**：`CompoundPeriodicTicker` 备有 `m_tranditionalFindTargetTicker // 0x10` 与 `m_deterministicFindTargetTicker // 0x18` 两条通道（`0x20` 是当前生效引用），确定性模式下走 `PeriodicTickerNoUpdateNeeded`（**不依赖每帧 Update**）。

🔴 **PRTS 该页「索敌冷却」写的是"（待补充）"** ⇒ 本条可**回填给 PRTS**（见 §4）。

### 2.4 ④ 过滤器与选择器的先后顺序

**答：选择器先、过滤器后；串联点是 `AdvancedSelector.OnPostFilter(List<Entity>)`（RVA `0x6A2790`，Slot 37）。**

`call AdvancedSelector.OnPostFilter` 的目标清单里出现 **`0x6A2A39 → RVA 0x6BFC40` = `FilterUtil.Filter`**，即：

```
Range 产出候选集 → 虚调用 OnPostFilter(候选) → FilterUtil.Filter(cands, source, maxNum, FilterType) 0x6BFC40
```

**"可选性判定"在过滤器之前**（PRTS 明述"过滤器的输入是已过可选性筛选的列表"）——代码侧对应 `TargetSelector.ValidateTarget` RVA `0x6E0160` 与 `AdvancedSelector.ValidateTarget` RVA `0x6A2E70`。

`OnPostFilter` 内的可确证片段：

| 地址 | 指令 | 含义 |
|---|---|---|
| `0x6A2881` | `movzx eax, byte ptr [rbx + 0xA0]` + `and al, 1` | `get_isAlly` 内联 = `_targetSide // 0xA0` 的 **bit0**（`ALLY` 位）|
| `0x6A28B8` | `cmp byte ptr [rbx + 0xD4], 0` | `_excludeOwner // 0xD4` ⇒ 我方选择器排除发起者 |
| `0x6A2938` | `call 0x1806A2F30` | `AdvancedSelector._CheckAbilityInputTargetValid()` |
| `0x6A2A39` | `call 0x1806BFC40` | **`FilterUtil.Filter`** |

排序确定性（沿用 `04/38`，本轮未重核）：`WeightedTarget.CompareTo` RVA `0x4553F60`（`priorWeight` → gap 分桶 → `Entity.CompareTo` RVA `0x35F7BD0` = `instanceUid`），gap 常量在 `FilterUtil..cctor` RVA `0x6C9BE0`。

### 2.5 ⑤ 触发选择器 vs 能力选择器

**答：有硬对应，两处。**

| PRTS 语 | 代码对应 | RVA / 偏移 | 置信度 |
|---|---|---|---|
| **触发选择器** | `TargetTrigger.Search(bool force)` —— **abstract，Slot 13** | 无 RVA（抽象） | 🟢T1 |
| 触发选择器（实现） | `SelectorTrigger : TargetTrigger`（TypeDefIndex **9584**），`Search` 覆写 | `0x714210` | 🟢T1 |
| 触发选择器（聚合） | `GroupTrigger : TargetTrigger` 持 `private TargetTrigger[] _triggers; // 0x20` | `dump.cs` 374649 | 🟢T1 |
| **能力选择器** | `Ability._selector : TargetSelector` | **`// 0x28`** | 🟢T1 |
| 能力选择器（取用） | `Ability.get_selector()` Slot 14 / `Ability.UpdateSelector()` Slot 28 | `0x34F8B20` / `0x34F7970` | 🟢T1 |
| 触发选择器→选择器引用 | `SelectorTrigger.m_selector : TargetSelector` | `// 0x30` | 🟢T1 |
| 选择器基类 | `TargetSelector`（abstract，TypeDefIndex **9537**） | `FindTargets_DISPOSE` `0x6DFDD0` | 🟢T1 |

⇒ **「触发选择器」= 挂在 `TargetTrigger` 上、负责"要不要打/打不打得到"的节拍化搜索**；**「能力选择器」= 挂在 `Ability` 上、负责"这个弹道/技能能不能选它"的单次选取**。`SelectorTrigger.m_selector // 0x30` 与 `Ability._selector // 0x28` **是两个不同对象的引用，勿混**（`0x28` 在两个类里含义不同）。

## 四、对既有认知的修正

### 4-1 ❌ **改 `04/36 K清单反汇编核验结果.md` 第 37 行（K-023）**

*原句*：「选择器 `targetOptions` 含"强制无视迷彩"标志 —— `AdvancedSelector._forceIgnoreCamouflage // 0xBE`，`ValidateTarget` 在 `0x6E043B` 整段跳过迷彩判定」

### 4-2 🟡 **改 `07_名词对照/01_机制与概念.md` 第 19–20 行（`选择器` / `筛选器` 词条）**

*原句（第 19 行）*：「…**绑定触发器**，与筛选器共享 **`targetOptions`**；**受迷彩制约**」

### 4-4 🟡 **补 `04/33_cpp层战斗类结构与字段速查.md` 第 426 行（`SelectorTrigger` 行）**

*原句*：「`SelectorTrigger` | 9584 / 375083 | `SEARCH_TARGET_TICK = 3`（索敌节拍）、`_overrideSearchTargetTick 0x28`、`m_findTargetTicker 0x48`」
