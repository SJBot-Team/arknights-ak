### 7.1 新增：逻辑帧时钟插件 `code/vision/plugins/clock/cost_ruler.py`

| 时钟源 | 说明 | 依赖 |
|---|---|---|
| `ruler` | 费用尺 ArknightsCostBarRuler 本机 API（`127.0.0.1:2606`）：HTTP 快照轮询 / WS 推送 | 需尺子在跑 |
| `cost_bar` | 自研费用条识别器 + 周期回绕计数（兜底） | 仅截图 |
| `virtual` | dry-run / 单测用（按墙钟 × 加速倍率） | 无 |

- **纯 stdlib WebSocket 客户端**（`MiniWS`：握手 + 文本帧 + ping/pong），环境无 `websockets` 包也可用；
- **帧内插值**：`frame_now() = totalElapsedFrames + min(收到快照后的墙钟 × 30, 2 帧)`，
  把「某逻辑帧的快照」推进到「现在」，实现亚帧到点判定与同帧多操作；
- **绝对帧免疫费用满**：尺子的 `totalElapsedFrames`（战斗内累计逻辑帧）由费用条循环维护，
  费用条永远 0→1 循环、与消耗无关 ⇒ 需求 2.1 后半「费用条满以后如何取得精确帧」**由费用尺直接解决**；
  费用数字只用于锚点校验与消耗记账；
- **丢帧诊断**：`sampleIndex` / `droppedSincePrevious` / `timingDebug.advancedFrames` / `cursorBlocked`；
- **精度保障**：主循环 `timeBeginPeriod(1)`（Windows 定时器 15.6ms → 1ms）+ 分级休眠。
- 协议依据：`ZeroAd-06/ArknightsCostBarRuler` 的 `docs/API.md`（apiVersion=2，HTTP+WS 同构快照）。

离线自检 `apps/test_ruler_clock.py`（假尺子 HTTP + 假 WS 服务器，无需游戏）：**4/4 通过**
（A 读数与插值、B WS 推送路径、C 轴表帧计划、D 虚拟时钟全轴 dry-run；
虚拟时钟 60× 下最大迟到 0.032 真实帧）。

### 7.2 轴表语义修正（本轮最重要的发现）

对 `axis.py::parse_cyberplastic / resolve_frames` 的复核发现两处问题，均已修正：

| # | 问题 | 证据 | 修正 |
|---|---|---|---|
| 1 | 空「费用」列被**顺延上一读数**作为部署行锚点 | xlsm 仅 8 行有费用读数（第 2/3/18/19/20/24/33/42 行），召唤物行费用列为空却被赋成上一条的 20 | 空 B 行 = **按「帧数」列相对上一行计时**（PRTS+ 使用须知第三条：费用与费用条是唯一时间参照） |
| 2 | `resolve_frames` 换算漏掉**累计已消耗**（且未计撤退返还） | 旧式：`abs += (读数 − 上一条读数) × 30` → 第 2 条算出 315 帧；正确（含消耗记账）= 600 帧，与轴表绝对时间列 20.0s 一致 | 改为 `绝对帧 = (读数 − 初始费用 + 净累计消耗) × 每费帧数 + 费用内帧`，撤退按 50% 返还 |

同时新增**顺序语义夹紧诊断**：锚点算出的时刻若早于上一条，夹紧并记录 `clamped_from`。
h12-4 全轴仅 1 处触发（第 23 条 弦惊，锚点 18，原始 4710 → 夹到 4762，差 52 帧 ≈ 1.73 费），
指向「撤退返还/小额费用单位的取整」这一处细节，可作为费用模型的下一个校正点。

**两端公式一致性已交叉校验**：`ak_sim.axis.resolve_frames` 与
`plugins/clock/cost_ruler.build_frame_schedule` 对 h12-4 全部 50 条给出**相同帧计划**。

### 7.4 执行的「费用不足顺延」语义（`retry_on_cost`）

轴表把召唤物行按相对帧排在**费用尚未足够**的时刻（第 6 条 弦惊：相对链落在 632 帧 ≈ 21.1s，
此时模拟费用仅 1.0，而弦惊需 23）⇒ 真实打图脚本必然要**顺延到费用足够的那一帧**。
`Battle.run_axis(retry_on_cost=True)` 实现了该语义：

| 指标 | retry=False | retry=True |
|---|---|---|
| 操作成功 | 26/50 | **32/50** |
| 与计划最大帧差 | 4599 | **2593** |
| 重试次数 | 0 | 5150 |

### 7.6 两端时序交叉验证（本轮收尾，执行端 ≡ 模拟器语义）

把执行器改成与模拟器 `Battle.run_axis` **完全同构**的调度语义：

| 语义 | 模拟器 | 执行端（`axis_runner` v2） |
|---|---|---|
| 费用锚点行 | `int(cost) == 锚点 && frame % 30 ≥ foff` | 同一判据（`anchor_ready`：显示费用 + 费用内帧相位） |
| 无锚点行 | 上一条**实际**触发帧 + foff | 同（游标 = 上一条实际触发帧） |
| 部署费用不足 | `retry_on_cost`：不推进轴，逐帧重试 | `cost_gate`：到点但 `估算费用 < 单位费用` 时顺延 |
| 撤退返还 | `cost += u.cost × 0.5` | `spent -= 单位费用 × 0.5` |

**验证方法**：`sim/draft/compare_retry.py` 导出模拟侧逐条触发帧（`data/derived/sim_axis_frames_retry.json`），
执行端用**确定性步进时钟**（每次 read 逻辑帧 +1，等价模拟器逐帧推进）跑同一轴表，逐条比对：

```
可比区间（前 19 条，模拟侧尚无费用相关操作失败）：±2 帧内 19/19，最大帧差 1 帧
#1 45/45  #2 601/600  #3 605/605  #4 610/611  #5 633/634
#6 1291/1290（首次召唤物） #7 1981/1980 #10 2671/2670
```

两侧独立实现（Python 定点模拟器 vs 截图/时钟执行器）却在**同一条物理时间线**上一致 —— 这同时反证了：
①「费用不足顺延」是该轴唯一可行的执行语义（首批召唤物落在 43.0s / 66.0s，而非轴表相对帧链的 21s）；
②费用消耗记账（含 50% 返还）与每费 30 帧的回费模型与轴表读数自洽。

区间之外的分歧**全部来自模拟器保真度缺口**（首个分歧点 `#20 retreat char_4091_ulika`：
模拟器里 U-Official 已在 f2671 阵亡 → 撤退失败 → 未返还费用；其后 `#33 deploy 艾拉` 地块判定失败），
而非两端调度语义差异 —— 这正是「继续补齐技能/buff 保真度」的下一步依据。

### 7.7 录像费用轨迹自动读取（工具 + 全片结果）

新增离线工具 `code/vision/apps/video_cost_timeline.py`（仅 numpy+cv2，不接触游戏）：

```
bootstrap  --video X --labels L.json --templates T.json    # 用少量人工读数自举 0~9 数字模板
scan       --video X --templates T.json --t0 --t1 --step --out tl.json
montage    --video X --templates T.json --t0 --t1 --out m.png   # 人工复核拼图
```

实现要点（都为踩坑后加的护栏）：
1. **ROI 投票锁定**：右下带内白色连通域按 y 聚「行」，取**最上面一行**（费用行在「剩余可放置角色」之上），
   多帧投票取众数框 → 同一录像全程复用（UI 布局固定）；
2. **数字区学习**：费用图标在锁定 ROI 内位置固定 → 统计跨帧重复出现的字形框，判为图标并剔除
   （h12-4 1600×900 实测：图标稳定在 `x∈[1459,1495]`，16/16 帧命中）；
3. **自举模板**：用 20 个人工读数（2~62s 每 3s）建立 0~9 全部数字模板，19/20 帧解析正确；
4. **消耗事件检测**：相邻样本下降量扣除**局部**回费速率（避免倍速切换误判）。

**全片前 90s 结果**（`data/derived` 之外的中间产物在 `ak/.tmp/video_cost_scan.json`；样本有效率 96~99%，
匹配置信度 0.98~1.00）：

**结论（重要）**：
- **没有任何一个候选录像在前 90s 呈现本轴签名**（令 10 → 蕾缪安 20 → 弦惊 23×N）。
  结合 `(128)` 待部署区约 11 张卡、剩余可放置角色 7 ⇒ 这些「双」目录录像**是多种不同队伍的解**，
  不能直接当作 `赛博塑料h12-4.xlsm` 的逐帧基准；
- `(128)` 的 17.2s 处 **20 费**骤降与「开局 2 倍速 + 令先落地」量级吻合，可作为**开局段**的旁证；
- 曲线里出现长时间持平（如 21~29s 恒为 5）⇒ 录像包含**暂停/倍速切换**，逐帧锚定必须先做
  「暂停检测 + 倍速判定」，否则逻辑时间换算会漂移（下一步）。
- 费用数字 ROI 实测已可用于 `cost_bar.roi` 标定（同一分辨率下直接复用上表数值）。

### 7.9 时基的独立判据：SP 合法性检验（重要）

技能"必须 SP 足够才能放"是一条**与费用无关的独立约束**，可用来判定轴表两种时基哪一种物理可行。
新增 `sim/draft/check_axis_sp_legality.py`：按各时基算出每条技能行的时刻，再用表值 SP 曲线检验合法性
（含令的天赋 +4 SP/召唤物损失）。

| 时基 | 技能行 | SP 合法 | 典型不合法量 |
|---|---|---|---|
| `cost-relative`（相对帧链） | 21 | **4** | 首条蕾缪安技能 SP=32.1/38，早 5.9s；令技能 SP=34.6/40，早 5.4s |
| `abs-seconds`（表内绝对时间列） | 21 | **12** | 剩余多为"技能仍在激活中"或早 0.9~7s |

**结论**：在**不依赖费用读数**的独立判据下，表内「绝对时间」列明显更接近真实时间轴
（12/21 vs 4/21）。这提示此前 §7.3 中 `cost-relative` 与模拟执行的"±2 帧内 16/50"存在**自洽性假象**——
模拟器本身就在实现同一套相对帧语义，因此那组吻合不足以证明时基正确。

**仍未解决的矛盾（需实机判定）**：两种时基下首批召唤物（23 费）都排在费用不足的时刻
（相对链 21s→DP 1、绝对列 29s→DP 9）。即"SP 说得通的时间轴"与"费用说得通的部署时刻"无法同时成立，
除非：①召唤物实际扣费低于 23（天赋/模组/潜能）；②该行的"帧数"另有语义；
③实机复跑（费用尺 + 逐帧记录）直接测出真实时刻。**这正是实机验证的第一优先项。**

**两端交叉验证的口径修正**：加上 SP 门槛后，模拟器会把技能行顺延（全轴 50 条只落到 **23 条**，

因此 §7.6 的两端比对改为**隔离变量**：模拟侧关闭 `Battle.skill_gate`（只比较费用/调度语义），
实测仍为**前 19 条 ±2 帧内 19/19、最大帧差 2 帧**；SP 门槛的影响单独用 §7.9 的判据衡量。

### 7.10 轴表时基的联合求解与参数反解（本轮结论：**表内两列互不自洽**）

新增两个分析工具：
- `sim/draft/solve_axis_timeline.py`：在 `时基 × 召唤物扣费 × 返还率` 的组合上，用三类**独立约束**打分
  （①费用读数一致性 ②技能 SP 合法性 ③部署可负担性/顺延量）；
- `sim/draft/fit_axis_cost_model.py`：用 8 个记录读数**反解**作者的消耗记账模型（召唤物费用 c、返还率 ρ）。

**判据①（把 8 个读数放到表内「绝对时间」列上）**：没有任何 (c, ρ) 能拟合好——
最优是 c=20 DP、ρ=0，**RMSE 仍有 16.5 DP**；6/8 行残差 10~21 DP，末行模型读数甚至为 **−3.4（负数，物理不可能）**。
⇒ **「绝对时间」列不是可信时间轴**（与表内自带提示一致），因此它也不能当作基准时间轴。

**判据②（技能 SP 合法性）——需下调结论强度**：上一节按"每行 = 一次技能释放"比较，得到
`abs-seconds` 12/21 优于 `cost-relative` 4/21。但本轮发现轴表里**同一干员的技能行相隔仅 0.2~3s 成对出现**
（如第 3/4 行、第 8/9 行），任何技能模型（S1 弹药型 / S3 充能型）都不可能如此——说明
**「技能」行不必然等于一次技能释放**（很可能包含"点干员 → 点技能按钮"的多次点击，或含冗余点击）。
故该判据只能作为**弱证据**，不能据此定案。

**判据③（部署可负担性，含"顺延到合法"语义）**：一旦允许"费用不足则顺延"（实机脚本必然如此），
整个轴**是可执行的**——全轴只有 **1 次部署**因费用不足顺延（弦惊，DP 21/23，顺延 2.0s），
但代价是时间被拉长到 **490s**（表内时间列约 380s）。

**本轮总结论**：
1. 轴表在「费用读数列」与「绝对时间列」之间**互相矛盾**，单一解释无法自洽；
2. 只有加上「不足则顺延」的运行时语义，轴才成为可执行剧本（这正是执行端 `cost_gate` / 模拟端 `retry_on_cost` 的语义）；
3. 想定案「行间的真实时刻」，**必须**用实机（费用尺 + 逐帧记录）或与轴对应的录像测一次，
   离线推断到此为止——这一步已列为实机验证的第一优先项（§五）。
