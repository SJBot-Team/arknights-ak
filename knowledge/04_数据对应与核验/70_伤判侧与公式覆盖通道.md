## §1 一句话结论

1. **Q1（真伤的伤判侧）**：**真伤不跳过伤判环节**。`DamageType` 在伤判侧**不是"免检牌照"，而是一张可配的过滤掩码**——`Nodes.DamageScale` / `Nodes.BlockDamage` / `Nodes.DamageFixedValueResistance` / `Nodes.DamageValueModify` 等施加点都有 `_filterDamageType`（默认 `false`）开关；**开启时用的判据是 `1 << (int)damageType & mask`，而 `PURE(3)` 对应 bit 8，恰好落在 `ANY_ATTACK(46)` 与 `ANY_ATTACK_EXCEPT_ELEMENT(14)` 里**。
   ⇒ 从代码与官方数据两侧都能确证：**真伤可以被增伤/减伤/格挡/闪避影响**，是否真被影响**取决于每条 buff 的掩码配置**，不取决于伤害类型本身。
   真伤**唯一**"免检"的是**抗性结算**（`CalculateDamageInternal` 的 `PURE/HEAL` 分支只有恢复寄存器 + `ret`，已确证）。
   库里还有一条**显式**豁免通道：`_damageWithoutModify=true` → `Modifier.SetSharedFlag(4)`（=`IS_NOT_CHANGEABLE_VALUE_MODIFIER`）→ `Modifier.set_value 0x5DAD20` 拒改值 ⇒ 这才是"字面意义上的不参与伤判"，且它是**逐节点开关**，与伤害类型无关（6 条模板在用）。

2. **Q2（`+0x68` 是什么）**：`BattleFormula` 静态字段 `+0x68` = **`private static DelegateBridge __Hotfix0_CalculateAttackInterval`**（dump.cs **L322666**），即 **xLua 的 iFix 热更槽**（不是业务字段）。`BattleFormula` 一共 17 个这样的槽（`__Hotfix0_CalculateDamage // 0x20`、`__Hotfix0_CalculateDamageInternal // 0x30`、`__Hotfix0_CalculateDamageNoEvent // 0x28`、`__Hotfix0_CalculatePenetrateRatio // 0x70` …）。
   ⇒ **公式存在被 Lua 覆盖的通道，且 `CalculateDamage` / `CalculateDamageNoEvent` / `CalculateDamageInternal` 三个出伤公式各自都有独立槽**；但**本体程序集里不存在任何写点**（见 §3-③ 的三条判据），覆盖只在**运行时热更脚本**装入时发生。⇒ **模拟器可以按本体公式实现，无需为 Lua 覆盖留分支**（标 🟡，见 §4-1）。🔴 **未取到**具体赋值者（`DelegateBridge` 生成类的 `.ctor` 地址不在 dump 中）。

### 2.3 modifier 的施加点：**统一判据 `1 << (int)damageType & mask`**

**判据指令（本轮逐条读出）**——`Nodes.DamageScale.Execute` **`0xBBCD70`**：

```
0x00BBCEFB  cmp  byte ptr [r14 + 0x10], 0     ; _filterDamageType // 0x10
0x00BBCF00  je   0x180bbcf39                  ; false ⇒ 跳过整段过滤（对任何类型都生效）
0x00BBCF17  xor  edx, edx
0x00BBCF19  lea  rcx, [rsp + 0x40]            ; rcx = Modifier*
0x00BBCF1E  call 0x1805d90c0                  ; Modifier.get_damageType 0x5D90C0 → eax
0x00BBCF23  mov  edx, dword ptr [r14 + 0x14]  ; edx = _damageMask   // 0x14
0x00BBCF27  xor  r8d, r8d
0x00BBCF2A  mov  ecx, eax                     ; ecx = (int)damageType
0x00BBCF2C  call 0x1855238f0                  ; ★掩码判据★
0x00BBCF31  test al, al
0x00BBCF33  je   0x180bbcfe3                  ; 不匹配 ⇒ 直接 return false（本节点不生效）
```

**判据本体 `0x55238F0`**（24 处调用；`1 << n & mask == 1 << n`）：

```
0x055238F0  83e11f        and  ecx, 0x1f      ; ecx = (int)damageType
0x055238F3  41b801000000  mov  r8d, 1
0x055238F9  41d3e0        shl  r8d, cl        ; r8d = 1 << damageType     ★
0x055238FC  418bc0        mov  eax, r8d
0x055238FF  23c2          and  eax, edx       ; eax = bit & mask
0x05523901  413bc0        cmp  eax, r8d
0x05523904  0f94c0        sete al             ; return (bit & mask) == bit
```

⇒ **`DamageTypeMask` 的位序 = `1 << DamageType`**，与枚举值**逐一对齐**（`NONE=0→bit0`、`PHYSICAL=1→2`、`MAGICAL=2→4`、**`PURE=3→8`**、`HEAL=4→16`、`ELEMENT=5→32`），从而数据侧的字符串掩码可直接当常量用：

| 数据侧掩码 | 值 | 位分解 | **含 PURE？** |
|---|---|---|---|
| `PHYSICAL_AND_MAGICAL` | 6 | 2+4 | ❌ |
| `ANY_ATTACK_EXCEPT_ELEMENT` | 14 | 2+4+**8** | ✅ |
| `ANY_ATTACK` | 46 | 2+4+**8**+32 | ✅ |
| `PURE` | 8 | **8** | ✅（仅真伤） |
| `ELEMENT` | 32 | 32 | ❌ |
| `ANY_HEAL` | 16 | 16 | ❌ |

**带该判据的 7 个节点**（对 `0x55238F0` 在 `Nodes.*` 段的 E8 全扫）：

| 调用点 RVA | 节点（类.方法 + RVA） | `_filterDamageType` 默认 |
|---|---|---|
| `0xBB6AF7` | `Nodes.BlockDamage.Execute` **`0xBB6960`** | `false`（`[r14+0x10]`） |
| `0xBBBE03` | `Nodes.DamageFixedValueResistance.Execute` **`0xBBBC90`** | `false` |
| `0xBBC49D` | `Nodes.DamageScaleAccordingToHpRatio.Execute` **`0xBBC330`** | `false` |
| `0xBBC93E` | `Nodes.DamageScaleBaseOnDistance.Execute` **`0xBBC700`** | `false` |
| `0xBBCF2C` | `Nodes.DamageScale.Execute` **`0xBBCD70`** | `false` |
| `0xBBE7DD` | `Nodes.DamageValueModify.Execute` **`0xBBE680`** | `false` |
| `0xBC8665` | `Nodes.ApplyElementDamageBasedOnDamageValue.Execute` **`0xBC8420`** | （元素专线） |

**结论（🟢T1）**：**没有任何一处按 `damageType == PURE` 做特判跳过**。唯一的类型分流就是这张掩码表，而 `PURE` 在两张"通用攻击"掩码里**都被包含**。

### 2.4 数据面独立确证（🟢T1，`buff_template_data.json`）

- 全库带 `_damageMask` 的模板中：`_filterDamageType=true` **333 次**、`false` **310 次**（`false` ⇒ 对含真伤在内的所有类型一律生效）。
- **`PURE` 掩码模板 9 条**：`damage_scale[pure]`（`_filterDamageType=true, _damageMask="PURE", _isOneMinus=false` ⇒ **真伤增伤**）、`damage_reduce_pure`（`Nodes.DamageFixedValueResistance`，`_damageMask="PURE"` ⇒ **真伤定值减伤**）、`damage_scale[not_block_by_source]`、`damage_scale[type]`、`damage_scale[unblocked]`、`enemy_ltniak[side_shield]`、`trap_condtr[side_shield]`、`sandbox_v3_process[dmg-sp]`、`sandbox_v3_xb2txtl2[ele-pure-damage-scaleup]`。
- **`ANY_ATTACK_EXCEPT_ELEMENT`（含 PURE）16 条**，含**通用增伤入口** `damage_scale[input]`（`_filterDamageType=true, _damageMask="ANY_ATTACK_EXCEPT_ELEMENT", _isOneMinus=false`）与 `weak[aura]` 派生链（`weak[inf]`/`damage_scale[input]`）⇒ **脆弱类增伤对真伤生效**。
- **`ANY_ATTACK`（46，含 PURE）18 条**，其中 `damage_resistance[IncludePure]` 的模板名与掩码**语义自洽**（`_isOneMinus=true` ⇒ 真伤减伤）。
- 对照 `damage_resistance`（默认减伤）用 `PHYSICAL_AND_MAGICAL=6` ⇒ **默认减伤不含真伤**，含真伤必须显式挂 `[IncludePure]` 或 `ANY_ATTACK_EXCEPT_ELEMENT`。⇒ 这解释了 PRTS「不指定伤害类型的伤判效果可以对真实伤害生效」的**实现口径**：不是"真伤穿透"，而是"**通用掩码恰好把真伤算进去**"。
- ⇒ **K-012（`04/36 L26`：脆弱/干扰地雷不对元素伤生效）与本次结论不冲突**：脆弱掩码是 `ANY_ATTACK_EXCEPT_ELEMENT=14`，**排除的是 ELEMENT(32)，保留 PURE(8)**；元素伤另有 `epDamageResistance` 独立结算（`04/63b D5`）。

### 3.3 谁会给它赋值？（🟡 部分结论 + 🔴 卡点）

**已确证的三条（🟢T1）**：

1. **它是 xLua iFix 的桥槽，不是业务字段**。同类基础设施：`XLua.DelegateBridge : DelegateBridgeBase`（dump **L18020 / L57530**）、`DelegateBridgeBase.AddDelegate(Type,Delegate)` **`0x331DDC0`**、`XLua.HotfixDelegateBridge.Set(int,DelegateBridge)` **`0x331E320`** / `Get(int)` **`0x331E2B0`**（dump **L57554**）。全库共 **108746 个** `__Hotfix0_*` 字段 —— 只有热更框架会生成这个密度。
2. **本体程序集里没有写点**。三条判据：① `find "__Hotfix0_CalculateAttackInterval"` 全 dump **仅 1 处命中**，就是字段声明本身（**无任何 `.cctor` / `SetXXX` 方法引用它**）；② `CalculateAttackInterval` 的 E8 调用者**只有 1 个**（`Entity.OnAttributeDirty 0x35FD87E`），说明该槽**只被读、不被业务代码写**；③ `Dis` 收到的 `rcx` 是**运行时从 `Il2CppClass->static_fields` 取的指针**，生成类 `.ctor` 内的常量存储地址**不在 dump.cs / 不在 `script.json`**，无法静态定位 ⇒ **无法从静态层枚举写点**。
3. **覆盖是"运行时脚本装入"语义**。槽为 `null` ⇒ 走本体 IL（`static[0x8]=600`/`static[0x10]=10`/`static[0x18]=100` 三个 `readonly` 常量参与运算）；非空 ⇒ 整函数体被 Lua 委托顶替。⇒ **不装热更脚本 = 本体公式 100% 生效**。

**判定（🟡，含推断成分，已在 §4-1 列为待证）**：

- **本体的 `AttackInfo`/`FP` 公式不会被"数据热更"改写**：`MIN_ATK_FACTOR=0.05`、`MAX/MIN_ATTACK_SPEED=600/10`、`ATTACK_SPEED_DIVIDER=100` 都是 `static readonly`，由 `BattleFormula..cctor 0x3586D00` 写入，**Lua 改不到**（只能整体替换函数）。
- **覆盖条件是"热更脚本存在且注册了 `BattleFormula`"**，而热更脚本的**装载清单本身走资源/网络**（`35_Lua层定位与解密链路`：`LuaManager` + `IConverter m_decrypter` 解密脚本）。⇒ **模拟器按本体公式实现即可**；若日后发现对局数值与本体公式系统性不符，**第一顺位怀疑对象就是这条通道**（它是唯一能让公式"整体变形"的机制）。
- 🔴 **仍未取到**：`+0x68` 的**具体赋值者**（生成 `DelegateBridge` 子类 `.ctor` / `xlua.hotfix` 注册点）与**本版客户端是否随包携带 `BattleFormula` 相关热更脚本**。前者需要 `Il2CppClass` 的 `static_fields` 运行期地址（本轮禁止启动游戏）；后者需要解 Lua 资产包（超出 T-200b 只读取数范围）。
