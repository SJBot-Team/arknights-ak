## §1 一句话结论

**那 4 帧不在"移动起步"，也不在"阻挡判窗"，而在"每次普攻周期的重启少算 1 帧"这一个 off-by-one 上——它同时命中"前摇差 4 帧"与"下游偏早/偏晚"两种观测。**

三条硬量测（1-1，同一复刻、同一口径）：

| 量 | 实机（标定表） | 模拟器（偏移 0） | 差 |
|---|---|---|---|
| 出生帧（猎狗pro 1） | 94 | 90 | **−4** |
| 首次**进入阻挡半径**（x ≤ 5.0 − 0.7071 = 4.2929） | — | **228** | — |
| `block` 事件 | 236 | 230 | −6 |
| **出生 → 首次 `block`** | **142** | **140** | **−2（模拟器移动链只早 2 帧）** |
| **出生 → 首次"敌方命中芬"** | **161** | **167** | **+6（模拟器下游晚 6 帧）** |
| 芬命中猎狗（首次） | 221 | 218 | −3 |
| 芬命中间隔（2~6 次） | 253/285/317/349（**恒 32**） | 251/284/317/350/383（**恒 33**） | **每周期 +1，累计 +5** |
| 猎狗命中间隔 | 298/340/…（42） | 300/343/…（43、43、42…） | **每周期 +1** |

⇒ **修正后的图景**（与 `04/73 §3.1` 的表述方向相反，量级同源）：

1. **移动链只早 2 帧**（出生→阻挡 = 140 vs 142）；它**不是** 4 帧的来源。
2. **下游晚 6 帧**（出生→首次敌命中 = 167 vs 161）：其中 **+2 来自移动**、**+4 来自普攻周期重启**。
3. **普攻周期重启是纯 bug**：`engine.py` 的 `if el >= interval: atk_start_frame = None` 让"周期结束帧"变成**空转帧**，下一次起手被推到 **next frame**，于是
   **实际周期 = `interval + 1` 帧**（芬 32→**33**、猎狗pro 42→**43**）。
   这一条**同时解释了**"前摇 18 vs 14（差 4）"的观感与"下游被推晚 4/6 帧"的量级 —— **它们是同一个 off-by-one 的不同投影，不是两处独立误差**。
4. **"4 帧"的第二种可能读法**（不受上述影响的真实偏差）：**模拟器对"进入攻击范围"的时刻比实机早约 3 帧**（模拟器 200 / 偏移+4 后 204 / 标定 207），只能由**敌人位置曲线**或**标定零点**解释 ⇒ 见 §3-④。

### 2.3 C3（攻击前摇／周期）：★**就是这里**，🟢T1（模拟器侧 bug）+ 🟢T1（prefab 侧排除反推）

**(a) prefab 侧：`_preDelay` 已取到，且 1-1 参战单位全是 `0.0`** ⇒ **"职业比例反推"不只是误差，它连"这个字段不是前摇来源"这一点也错了**：

```
char_123_fang  GO='Attack'  _preDelay=0.0  _timeMode=0(FROM_ATTACK_SPEED)  _maxAnimScale=2.0
                            _animKey='Attack'  _waitForAttackEvent=1  _cooldown=0.0  _resetCdStrategy=1  _atkScale=1.0
char_283_midn  GO='Combat'  _preDelay=0.0  _timeMode=0  _maxAnimScale=1.3  _animKey='Combat'  _waitForAttackEvent=1
               GO='Attack'  _preDelay=0.0  _timeMode=0  _maxAnimScale=1.0  _animKey=''        _waitForAttackEvent=1
enm_pfb_0.ab   含 _preDelay 的 MB 共 154 个：取值分布 0.0×150 / 3.6×2 / 2.0×2
```
⇒ 与 `04/69 §2.2` 的结论互证：**`_preDelay` 是动画播放速率链上的量**，`_timeMode = 0 (FROM_ATTACK_SPEED)` 时它被写成 `m_attackTime` 的副本 ⇒ **真正决定"抬手多长"的是动画事件帧 `ON_ATTACK_CHECK_POINT = 7`（`04/68 §1`）**，**不是** `0x180`，也**不是**任何"职业比例"。
⇒ **C3-① 的答案是：挖得到，但拿到的是 0.0；这条路对"前摇时长"无效。**（真值在动画事件帧上 ⇒ §4-②）

**(b) 模拟器侧：前摇数字对不上是"周期重启 off-by-one"造成的** 🟢T1

`engine.py::_operator_tick` / `_enemy_tick`（两处同构）实际节奏（探针 3 的 `cd` 序列硬证）：

```
f=200 cd=32 wl=18   ← 起手（interval=32, windup=18）
f=218 cd=14 wl=0    ← 命中（el=18 ≥ wl=18）
f=232 cd=0  wl=None ← ★周期结束，本帧被"清空"，什么都不做（**空转帧**）
f=233 cd=32 wl=18   ← 下一次起手
⇒ 起手间隔实测 = [33,33,33,33,33]（芬，interval=32）、[43,43,43,43]（猎狗pro，interval=42）
```

根因（两处同一写法）：
```python
el = self.frame - u.atk_start_frame
if el >= u.attack_interval_frames:      # 到点 ⇒ 清空
    u.atk_start_frame = None            # ★ 本帧不再起手
else: ...
# 下一帧才会走 pick_operator_target / operators_attackable_by 重新起手
```
⇒ **每周期固定多 1 帧**。这解释了：
- **前摇观感 18 vs 14**：实机 207→221 = **14 帧**是**命中延迟**（事件帧 14 帧位置），模拟器 200→218 = **18 帧**；两者之差 = 模拟器把 32 帧周期摊成 **33 帧**后再按比例取前摇（`round(32×0.55)=18`），**同时**叠加了 +1 空转 ⇒ 逐周期**再 +1**。
- **`04/73 §3.1` 的"+2 → +6"**：偏移 +4 后，第 k 次敌命中的残差 = 4 + (k−1)×1 ⇒ 第 1 次 +6 ✅ 与 `04/73 §3.1` 的 255→261 **逐字吻合**。

**(c) 关于 ②"用 1-1 标定反推的正确做法"**：
正确做法**不是**调比例，而是**标定"起手帧 → 命中帧"的差值本身**（它天然含前摇+弹道），并**先把周期修成整数**：
- 芬：标定 `207 → 221` ⇒ **命中延迟 = 14 帧**；且 `221/253/285/317/349` 给出 **周期 = 32 帧**（连续 4 个间隔全 32，非拟合）。
- 猎狗pro：标定 2 次命中差 `298 − 255 = 43`、之后 42 ⇒ **周期 42 帧**、命中延迟 ≈ 11 帧（`04/71 §3` 的 `frame_ceil` 口径已定）。
⇒ 落到模拟器：`interval_frames` 必须**恰好**是周期（不得 +1），`windup` 用**逐单位标定表**（`u.pre_delay_fp` / `u._windup_ratio` 已有优先级链），比例表只作兜底。

### 2.4 C4（受击/命中结算点）：🟢T1 **当帧结算、不是动画事件帧**；但"帧数"没错（错的是周期）

- 模拟器命中点 = `el >= wl` 的**当帧**立即 `_do_attack`（近战无弹道）；量测：起手 200 → 命中 **218**（`el=18`，`wl=18`）⇒ 与"起手 + 前摇"**零额外延迟**，✅ 与实机"事件帧当帧出伤"（`04/68 §1`）同构。
- 实机侧：`04/68 §1` 的链为 `ON_ATTACK_CHECK_POINT=7 → ActionUtil.RunActions 0xC837C0 → Nodes.ApplyDamage.Execute 0xBB5A70`，**前摇结束与出伤是同一帧**（`ActionNode` 无持续时长）。
- **前后关系**：移动 → 阻挡（`_block_scan` 同帧）→ 索敌（`operators_attackable_by`/`is_targetable`）→ 起手 → `windup` 帧后命中，**模拟器与实机的顺序一致**。
⇒ **C4：否（不是 4 帧来源）。** 唯一可议点：**敌方**重新索敌仍带 `_enemy_search_fires` 3 帧闸门（`engine.py:1233`），而 `04/74 §2.4` 已证"攻击推进不经过 `Search`"——本轮实测**敌→我命中间隔未受该系统偏差**（出生→首次敌命中 = 161 帧实机 vs 161 帧模拟器，**完全一致**），故**该闸门暂未见可测害处**，保留为 🟡（见 §4-③）。
