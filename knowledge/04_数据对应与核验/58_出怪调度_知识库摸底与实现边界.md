## 三、本轮实现：加权随机出怪组

### 3.1 语义（依 cpp `ActionData` 字段 + `IItemWithWeight.get_weightValue` 0x210D850）

- 同一 `randomSpawnGroupKey` 内的动作**互斥**：整组按 `weight` **加权随机抽一条**执行；
- `key` 为**空串** = 抽到该分支则**不刷怪**（肉鸽 1-1 中确实存在该分支）；
- `randomType` / `refreshType` 的刷新语义**仍属推断** ⇒ 本实现采取
  **"每次战斗开局抽一次"**，并把结果**记进事件**，便于日后按素材校正。

### 3.2 实现（`sim/draft/ak_sim/engine.py`）

```
Battle.__init__:
  self.random_seed = level.randomSeed
  self.rng = AKRandom(seed or random_seed)      # ★先建 RNG
  self.schedule = build_schedule(level, rng=self.rng)   # 抽签消耗 RNG
  → 抽签结果写事件 `spawn_random_pick {group, key, weight, weights, wave, frag}`
```
- ★**关键顺序约束**：RNG 必须在 `build_schedule` **之前**建立、且**之后不得重建**
  （否则抽签与后续随机序列脱节；已在代码中加断言）。
- 抽签用**可控随机数**（`.NET System.Random` 复刻，纯 `knowledge/04/34`）⇒
  **同 seed 完全可复现**，满足需求"随机数可控且尽量与客户端一致"。

### 3.3 验证（`sim/draft/test_spawn_random.py`，全部通过）

| 断言 | 结果 |
|---|---|
| 同 seed 两次运行出怪列表逐条一致 | ✅ 37 条一致 |
| 抽签事件被记录 | ✅ 5 条：`g1→trap_051_vultres#1`、`g2→trap_051_vultres#2`、`g1→enemy_1007_slime`、`g3→enemy_1007_slime_2`、`g1→(空=不刷怪)` |
| 不同 seed 会改变抽签结果 | ✅ 6/6 个 seed 均产生差异 |
| 主线 1-1 / h12-4 无随机组（不受影响、无回归） | ✅ 0 条 |

**回归**：1-1 标定对局仍为 **16/16、平均 2.19 帧、最大 7 帧**。
