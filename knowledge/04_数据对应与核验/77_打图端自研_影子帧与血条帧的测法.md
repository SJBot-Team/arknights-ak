# 77 打图端自研探索：**影子生成帧**与**血条变化帧**怎么测
> 主题：**04D 模拟环境**（本域按主题的虚拟分组，索引见 `04/00_目录.md §三之二`；文件路径未变）

> 用户原话：
> > 打图端先进关时缓，**步进过帧确定敌人影子生成的时间**（这在 prts+ 和 MAA 中没有现成的识别可供参考，你自己尝试探索可行实现），
> > 再部署干员尝试**定位不同单位血条**，步进过帧**确认血量变化的具体帧数**。

## §1 结论（先说要能用的两条路线）

| 路线 | 精度 | 代价 | 适用 |
|---|---|---|---|
| **A. 暂停步进 + 逐帧截图**（在线） | **7~15 帧/步**（受 adb 往返延迟限制，**到不了逐帧**） | 每步 ~0.6~1.2s | 只需要"区间定位"时 |
| **B. 1X 录像 + 离线逐帧差分**（推荐） | **≤1 逻辑帧**（30 逻辑帧/s；本机 `screenrecord` 实际 **56.84fps** ⇒ 1 逻辑帧 ≈ **1.89 视频帧**） | 一次录像 + 解码 | **要精确帧号时用这条** |

⇒ **精确帧号必须走 B**；A 只能用来"粗定位到 ~10 帧内"，然后交给 B 精修。

## §2 实测数据（2026-09-29 21:1x~21:3x，1-1 演习）

### 2.1 暂停 = 完全冻结（这是所有测量的前提）
```
暂停态 1.0s：帧 141 -> 141（Δ=0）
点选卡片后 1.0s：Δ=0     拿住卡片 1.0s：Δ=0
```
⇒ 暂停后**画面与逻辑时钟都不动**，截图不会糊、帧号不会漂 ⇒ 可以放心比对。

### 2.2 步进的真实粒度（为什么 A 到不了逐帧）
```
拿牌+恢复 0.20s：141 -> 148   Δ=7
拿牌+恢复 0.35s：148 -> 160   Δ=12
拿牌+恢复 0.60s：160 -> 209   Δ=49
```
`resume`/`pause` 两次 adb 往返本身就吃掉 ~0.3~0.5s（≈9~15 帧），**与 sleep 时长无关地**叠加在步进上。
⇒ 想要"逐帧"，只能**少动停**（一次恢复跑完一整段，用录像离线切帧）。

### 2.3 录像里的"进关转场"帧（可作为帧原点的锚）
对 `1-1复刻_20260929_芬D6朝左_费用-8.mp4` 在出生点 ROI 做相邻帧差分：
```
帧 743 t=13.071  changed=0      mean=194.6
帧 746 t=13.124  changed=0      mean=189.3
帧 747 t=13.142  changed=21773  mean=171.5   ← 转场开始（黑场淡入）
帧 755 t=13.283  changed=14764  mean=10.2
帧 756 t=13.300  changed=0      mean=1.0     ← 全黑
```
⇒ **该录像的战斗起点在 ~13.3s**（`OPERATION START` 在 ~5s、战斗画面 ~10s 起）。
**★这解释了"标定表帧轴 ≠ 录像时间轴"**（见 `04/73 §3.0`）：用录像做帧级核对前，
**必须先找到"转场/黑场"这一锚点**，否则会得到几百帧的假偏差。

### 2.4 出生点变化曲线（同一录像，左出生点 ROI `(110,300)-(330,470)`，t=14~40s）
变化最大的若干帧：`14.13s(37400)`、`20.07s(36653)`、`15.48s(20581)`、**`31.84~31.95s(18356/20562/5474/3513/3622/2642)`**。
最后那一串**连续 6 帧的变化簇**就是"**某个单位在出生点出现**"的典型指纹（单帧突变=转场，多帧连续=实体/影子生成）。
⚠️ 但**这段录像中间被我暂停过多次**，视频时间 ≠ 游戏时间 ⇒ 帧号不能直接换算（见 §3-③）。

## §3 方法细节（可直接复用的两份脚本）

1. **在线步进抓图**：`ak\.tmp\t200_shadow_probe.py`
   `ensure_paused()` → 循环{读帧 → 截图存 `sh_<帧号>.png` → `resume` 一小步 → `pause`} → 落 `frames.jsonl`。
   · **读帧**用 `Deployer.read_cost()`（`{cost, fill_px, tick}` → `frame_of()`），这是目前唯一可靠的帧号来源。
2. **离线逐帧差分**：`ak\.tmp\t200_video_events.py`
   对任意 ROI 做 |帧差|>18 的像素计数，输出曲线并自动找"由静到动"的起点；单帧突变=转场，多帧连续=实体。
3. **要让录像能换算帧号，必须满足**：①**中途不暂停**（或记录每次暂停的起止）；
   ②用**费用条的相位**给每一段视频帧打上逻辑帧标签（`read_cost` 的思路可离线复用到录像上）。

## §4 本轮踩到的四个坑（都影响可重复性）

| # | 坑 | 现象 | 规避 |
|---|---|---|---|
| 1 | **中途截图会打断"按住"状态** | 我按着牌截图核对面板 → 松手时**不再部署** | 一次 `DOWN→MOVE×3→UP` **一气呵成**，不要把截图插在中间 |
| 2 | **中间点不足** | 只给 1 个中间点时常不触发 | `04/49` 的协议要求 **≥2 个中间点**（本轮又踩一次） |
| 3 | **暂停连点偶数次=又恢复运行** | 战斗空跑十几秒，帧号全乱 | 点一次 → `ensure_paused()` 读数校验 |
| 4 | **`keyevent 4`(ESC) 会退出暂停/关面板** | 想"清输入状态"反而把暂停解了 | 不要用 ESC 清状态；用一次 `motionevent UP` 收尾即可 |
