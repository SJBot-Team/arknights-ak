## 〇、结论速览

| 问题 | 结论 |
|---|---|
| 同帧多单位死亡顺序 | ✅ **= 实体 tick 序 = `(BObject.priority 降序, instanceUid 升序)`**，而基类 `priority` 恒 0 ⇒ **实际就是创建序** |
| 伤害→死亡是否入队 | ✅ **完全同步、无任何队列**（死亡**不**经过 `TrigOrQueueFixedEntityEvent`） |
| 同帧多 buff 的 tick 顺序 | ✅ **`(BuffData.OnEventPriority 降序, 加入序升序)`** |
| `Buff.priority`(0x204) 的作用点 | 🟡 只在 `Buff.CompareTo` 里生效，**不参与容器插入**；其消费者未定位（`xref` = 0） |
| 本帧新增的 buff 是否本帧 tick | ✅ **会** |
| `TrigOrQueueFixedEntityEvent` | ✅ `isDeterministic==false` → 本帧立即同步；`==true` → 入 `m_fixedEventHandler`(0x140)，**下一固定帧**统一分发 |
| `EventPool<BattleEvent>`(0x60) | ✅ **是"枚举键→回调集合"的注册表，不是 FIFO 队列**；同步派发；集内按 **HashSet 枚举序**（≠ 注册序）🟡 |
| **`m_modules`(0x58) 是否参与帧内执行** | ❌ **完全不参与**（见 §五，推翻原有假设） |

## 一、★ 校准基线：从 `Slot` 反查虚方法（对后续所有虚调用定位都有用）

dump.cs 里每个虚方法标 `Slot: N`。实测关系（多点验证）：

```
函数指针位于  klass + 0x138 + Slot*0x10
MethodInfo*  位于  该地址 + 0x8
```

验证点：`Entity.OnHpZero` Slot 117 → `0x888`；`Entity.FinishMe` Slot 113 → `0x848`；`Entity.OnFinish` Slot 119 → `0x8A8`；`BObject.get_priority` Slot 23 → `0x2A8`；`BObject.OnTick` Slot 27 → `0x2E8`。

`Il2CppClass` 布局：`static_fields` @ +0xb8、`rgctx_data` @ +0xc0、`initialized` 位 @ +0x132。
尺寸：`ObscuredInt` = 0x14 字节、`ObscuredFP` = 0x28 字节。

## 二、伤害 → 死亡：完全同步，顺序 = 实体 tick 序

### 2.1 链路（全虚调用，无队列）

```
Entity.SetHpInternal(FP,bool,bool,bool)   0x3602FA0 / Slot 107
   ├─ (免死/护盾钩子) BuffContainer.OnBeforeTrySetHpZero(ref Modifier, out Buff)   0x35A8520
   └─ call [rax+0x888]  →  Entity.OnHpZero(bool noSource, bool skipReborn)   0x35FF2F0 / Slot 117
          ├─ edx=2 → FinishReason.HP_ZERO
          ├─ edx=8 → FinishReason.HP_ZERO_WITH_NO_SOURCE
          └─ Unit.OnHpZero(bool,bool)   0x76B840
                ├─ Unit.CheckReborn(out RebornData)   0x767990   （转生成功则不走死亡）
                └─ base Entity.OnHpZero
          └─ jmp [rax+0x848]  →  Entity.FinishMe(FinishReason)   0x35F97C0 / Slot 113
                └─ call [rax+0x8A8]  →  Entity.OnFinish    / Slot 119
```

**"立即 vs 入队"的决定性判据**：`xref 0x35FF2F0` 的**唯一调用者**是 `Unit.OnHpZero`；死亡只从 `SetHpInternal` 末尾的虚调用进入，**链路中不存在列表/池/协程**。

> ⚠️ **重要否定结论**：死亡**不**经过 `BattleController.TrigOrQueueFixedEntityEvent`（`xref 0x3556E90` 的 8 个调用者全是光环进出场与碰撞反弹，无伤害致死路径）。

`Entity.FinishReason`：`NONE=0, REACH_EXIT=1, **HP_ZERO=2**, FALLDOWN=3, WITHDRAW=4, DEADLIKE_WITHDRAW=5, SILENT_WITHDRAW=6, OTHER=7, **HP_ZERO_WITH_NO_SOURCE=8**, REPLACED=9, RESPAWN_SELF=10 …`

### 2.2 ★ 顺序 = `ObjectManager` 的 `PriorityQueue<BObject>` 序

`ObjectManager`：
```csharp
private PriorityQueue<BObject> m_objects;   // 0x10
private List<BObject> m_cachedList;         // 0x18
```

`ObjectManager.OnFixedUpdate(FP)` **RVA 0x5F8280**：
```
① 循环 i=0..n-1：get_Item(i) → BObject.get_validAndBorned() → 通过者加进 m_cachedList
② 循环 j=0..cachedList.Count-1：call [r9+0x2e8]  ← 虚 Slot 27 = BObject.OnTick(FP)
```
`OnLateFixedUpdate` **0x5F8450** 同构，调槽 `0x2f8` = Slot 28 = `BObject.OnLateTick(FP)`。

**排序键**（`BObject.CompareTo` **RVA 0x3582670 / Slot 17**）：
```
priority 不等 → Int32.CompareTo(this.priority, another.priority) → neg eax   ★ 降序
priority 相等 → UInt32.CompareTo(this.instanceUid(0x18), another.instanceUid) ★ 升序
```
`BObject.get_priority()` **RVA 0x54A780** = `xor eax,eax; ret` ⇒ **基类恒返回 0**；全 dump 中 `get_priority() { }` 仅 3 处，只有 `BObject` 是 virtual ⇒ **未发现任何子类覆写**。

> **⇒ 实体每帧 tick 顺序 = `instanceUid` 升序 = 创建序（≈ 出怪/召唤先后）**
> **⇒ 同帧多个单位同时受到致命伤害，死亡按此顺序依次发生**
> **⇒ `PriorityQueue.Add` 是有序插入（`List.Insert`），不是二叉堆** ⇒ `get_Item(i)` 的整个下标序列都是有序的，**复刻时不能只实现"取堆顶"**。

### 2.3 击杀计数 🟡

`Scheduler.MarkEnemyKilled(Enemy, bool)` **0x624DD0**：在**同一个方法体内、无插入点**地把 `m_finishedEnemiesCnt`(0x24) 与 `m_killedEnemiesCnt`(0x38) **连续各 +1**（两个 `ObscuredInt` 解包/写回）。

⇒ 不存在"A 的 killed 与 B 的 finished 交错"；多杀同帧时计数严格按 `MarkEnemyKilled` 调用序递增，而调用序 = 死亡序 = `instanceUid` 升序 ⇒ **确定可复刻**。

**待查**：`m_validKilledEnemiesCnt`(0x60) / `m_validMissedEnemiesCnt`(0x74) 的递增点未定位（`xref 0x624DD0` 只得到 3 个调用者且都在关卡脚本侧；主线上游是虚/委托分派）。

## 三、buff：容器序 = `OnEventPriority` 降序，**不是 `priority`**

### 3.1 容器与遍历

```csharp
Buff.BuffContainer
  m_buffs           : Buff.SortedDoubleBufferedBuffList  // 0x18  ★不是 List/ListDict
  m_buffOverrideMap : Dictionary<string, OverrideGroup>  // 0x20
  m_buffUidMap      : Dictionary<uint, Buff>             // 0x28
```

`BuffContainer.Tick(FP)` **0x35B4360**：
```
遍历 m_buffs：
    if (buff.get_needRemove())  → _FinishAndRemoveBuff(buff)     0x35B7D70
    else                        → Buff.OnTick(deltaTime)          0x3592320
```
**唯一调用者**是 `Entity.OnTick`（+0xD7），且是 `Entity.OnTick` 的第 3 步（之前有 `get_buffContainer()`，之后是 `_UpdateHpRecovery` / `_UpdateEpRecovery`）。

⇒ **buff tick 的宏观顺序 = 实体序（`instanceUid` 升序）× 实体内部 buff 列表序**。

### 3.2 ★ 列表序由 `BuffData.OnEventPriority` 决定

`Buff.SortedDoubleBufferedBuffList.Add(...)` **0x35BFFA0**：从尾部向前扫描，比较 **`get_onEventPriority()`**（0x35989D0），**降序维护**；同值时新 buff 插在已有同值者**之后** ⇒ **先加入者先 tick（稳定）**。

> **⚠️ 关键区分**：容器用的是 **`BuffData.OnEventPriority`**，而 **`Buff.priority`(0x204) 不参与容器插入**！
> `Buff.CompareTo`（**0x358BC90** / Slot 16）= `(priority 降序, instanceUid 升序)`（与 `BObject.CompareTo` 同构），但 `xref 0x358BC90` = **0 处 E8 直接调用**（接口/虚分派）⇒ **它的消费者未定位 = 🟡 待查**。

### 3.3 本帧新增的 buff **会**在本帧被 tick

`DoubleBufferedList<T>.Add` **0x48330D0** 直接 append 到 `m_internalList`（无 pending 缓冲）；
`ForwardEnumerator.MoveNext` **0x3E69700** **每步重读 `Count`** ⇒ 游标之后新增的元素会在**同一帧的同一轮循环**里被访问到。

"DoubleBuffered" 的语义落在 **移除侧**：`Buff.DoubleBufferedBuffList.Remove`（按 `instanceUid` 从后向前定位）+ `ClearInvalidElementsIfNotLoop()` **0x35BEE20**（**循环中标记失效、循环结束后压缩**）。

> ⇒ **新增 → 本帧生效；移除 → 下一帧（或下两帧）**。

## 四、事件系统

### 4.1 `TrigOrQueueFixedEntityEvent` **0x3556E90**

```csharp
void TrigOrQueueFixedEntityEvent(Entity target, uint secondaryCompareUid,
                                 uint thirdCompareWeight, Action<Entity> callback)
```
分水岭在 `BattleController.get_isDeterministic()`（**0x3563CE0**）：

| 模式 | 行为 |
|---|---|
| `isDeterministic == false` | **本帧立即同步执行** `callback(target)` |
| `isDeterministic == true` | 包装成 `Action<IPtrObject>` 后 **`m_fixedEventHandler`(0x140).QueueEvent(target, secUid, thirdWeight, action)`** |

**不入 `m_eventPool`(0x60)** —— 两条通道无关。

### 4.2 `FixedEventHandler<T>` 的四键排序与 +1 帧分发

`PendingEvent<T>` 布局：`callback`@0x00 / `target : ObjectPtr<T>`@0x08 / `secondaryCompUid`@0x18 / `thirdCompareWeight`@0x1c / `seqNum`@0x20

`_CompareEvent` **0x3E67330**：
```
键1：target 自身的 uint 键         → 升序
键2：secondaryCompUid              → 升序
键3：thirdCompareWeight            → neg eax（★ 降序）
键4：seqNum                        → 升序（FIFO 兜底）
```
`seqNum` = **入队前 `m_pendingActions.Count`**（`QueueEvent` 0x3E67170 中 `mov [rsp+0x50], eax`）。

**分发时机**（链路完整打通）：
```
QueueEvent 0x3E672F4
 → AsyncUtil.InvokeNextFixedFrameGlobal 0x3529190
 → AsyncUtil._InvokeNextFixedFrame<object> 0x3B2E1F0
 → BattleController.StartBattleCoroutine 0x3555EB0
 → CoroutineSimulator.StartCoroutine 0x3536B00（立刻首次 MoveNext，消耗 yield null）
 → 状态机 MoveNext 0x41E4D20 =「yield return null; cb();」
 → 下一固定帧：CoroutineSimulator.SimulateTick 0x3536990 → RuntimeHandler.MoveNext 0x3538620
 → _DealPendingActions 0x3E67410（Count>1 时 Sort，再按下标顺序调用）
```
⇒ **入队的事件一律推迟到"下一个 `SimulateTick` 边界"（通常即下一固定帧）**。

### 4.3 `EventPool<BattleEvent>`(0x60) **不是事件队列**

`EventPool<TEnum>` 只有 `On / Once / Emit / EmitWithArgs / Remove` 五个方法 —— 它是**"枚举键 → 回调集合"的注册表**。
`AddOrRemoveSafeCallbackSet`：`m_iterCounter` + **`HashSet<EventCallbackDelegate> m_internalSet`**(0x18) + `m_pendingAddOrRemove`。
`Emit` **0x54FF6A0**：先 `eventsMap`（常驻）后 `onceEventsMap`（一次性），集内走 **`HashSet.GetEnumerator`** ⇒ **顺序 = HashSet 枚举序，不等于注册序**；`m_iterCounter` 保证 Emit 期间的 On/Remove 被推迟合并。

> 🟡 **本项存在分歧，建议动态复核**：另一份并行分析判为"委托链顺序 = 注册顺序"。以字段声明 `HashSet<EventCallbackDelegate>` + `HashSet.GetEnumerator` 为准，**本报告判为 HashSet 枚举序**。这对复刻有实质影响（HashSet 序依赖委托哈希，跨后端不保证一致）。

## 五、★ 推翻：`m_modules` **完全不参与单帧执行**

- `IBattleModule` 只有 **5 个方法**：`OnGameReset` / `OnGameInit` / `OnGameReady` / `OnGameStart` / `OnGameOver`（Slot 0–4）——**没有 `OnTick`，也没有 `priority`**。
- 在 `OnTick`(0x354F880) / `FixedUpdate`(0x35487E0) / `ManualFrameTick`(0x354CB60) / `Update`(0x3557AA0) 内读取 `m_modules` 的次数 = **0**。
- 遍历形态：正序索引 `for (i=0; i<Count; i++)`，**无 enumerator、无 `_version` 检查、无 try/finally** ⇒ 不是 foreach。
- 填充 = `RegisterModule(IBattleModule)` **0x3552080** → `List.Add`（尾部追加），无排序、无优先级。
- `BattleController.Awake` **0x3540730** 硬编码注册序：`Scheduler`(#1) → `GridRangeDrawer`(#2) → `m_externalPluginHost`(#3)；另有 `UIController.Awake`、`BattleLogger`（受 `gameModeType==2` 门控）、Lua 运行时追加。

> ⚠️ **勘误（重要）**：`BattleController` 有**两个 0x58 偏移**——
> - `private static ListPool<Entity> s_entityListPool; // 0x58`（静态区）
> - `private List<IBattleModule> m_modules; // 0x58`（实例区）
>
> 判别法：静态字段访问是 `mov rax,[rip+klass]; mov rax,[rax+0xb8]; mov rcx,[rax+0x58]`；实例字段是 `mov rcx,[this+0x58]`。
> 不区分会在 `ResetAll` / `AllocateEntityList_DISPOSE` / `RecycleBuffNextFrame` 三处误判。

## 七、跨帧延后机制清单（完整）

| # | 机制 | 延后 |
|---|---|---|
| 1 | `RecycleBuffNextFrame` → `m_delayToRecycleBuffContainer[fixedFrameCnt+1]` | **+1 帧** |
| 2 | buff `needRemove` 置位 → `_FinishAndRemoveBuff` → 汇入 #1 | **+1 帧**（置位早于本帧 tick）/ **+2 帧**（晚于） |
| 3 | `FixedEventHandler.QueueEvent` 批次 flush | **+1 固定帧**（视入队时机可能 0 帧） |
| 4 | `AuraAbility` 进出场回调（经 `TrigOrQueueFixedEntityEvent`） | **+1 固定帧**（仅确定性模式） |
| 5 | `RecycleAsyncByBattleCoroutine(Component, float delay)` | `delay` 秒 |
| 6 | `Entity.RecycleSelfWithDelay()` | 取虚属性槽 `[vt+0x558]` 后转 #5 |
| 7 | `CoroutineSimulator` 的 `yield return null` | **+1 固定帧 / 每个 yield** |
| 8 | `CoroutineSimulator` 嵌套 `yield return IEnumerator` | 0 帧（本 tick 深度优先压栈） |
| 9 | `EventPool.Emit` | **0 帧（同步）** |
| 10 | `OnFixedUpdate` ↔ `OnLateFixedUpdate` | 0 帧，但分两阶段（全部 `OnTick` 后才跑全部 `OnLateTick`） |

> ⚠️ **确定性相关的附带发现**：`CoroutineSimulator.SimulateTick` **只在 `isDeterministic == true` 时被调用**（`OnTick` 里的门控），与 `TrigOrQueueFixedEntityEvent` 的入队门控自洽。
> ⇒ **`isDeterministic == false` 时，整条"排序 + 跨帧"的 fixed 通道停用，事件全部当帧同步执行** —— 同一逻辑帧的事件序在两种模式下会不同。复刻时必须按模式分叉。

## 九、★ 三条最需要记住的结论

1. **实体帧内序 = `PriorityQueue<BObject>` 的全序 = `(priority 降序, instanceUid 升序)`，而基类 `priority` 恒 0 ⇒ 实际就是"创建序"**。这一条同时决定了伤害/死亡顺序、`Entity.OnTick` → `BuffContainer.Tick` 的宏观顺序、`OnLateTick` 阶段。
   **且 `PriorityQueue.Add` 是 `List.Insert` 有序插入（不是二叉堆）** ⇒ 复刻时不能只实现"取堆顶"。

2. **`BuffContainer` 用 `BuffData.OnEventPriority` 降序维护列表；`Buff.priority` 只在 `Buff.CompareTo` 里生效——两者是不同的键，切勿混用。** buff 的"本帧新增 → 本帧可被 tick"，但"移除 → 下一帧或下两帧"。

3. **`FixedEventHandler` 是游戏显式用来消除同帧顺序歧义的机制**：确定性模式下把事件排序为 `(target uid ↑, secUid ↑, thirdWeight ↓, FIFO)` 并在**下一固定帧**统一分发；非确定性模式下当帧同步执行。**复刻确定性模拟时必须实现这条通道及其 +1 帧延迟**，否则光环进出场/碰撞反弹的帧序会错。
