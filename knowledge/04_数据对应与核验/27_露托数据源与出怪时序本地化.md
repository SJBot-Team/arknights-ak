## 一、露托（lutonada.online）访问方法与 API 全景（✅ 探明）

- **可达性**：仅 HTTP(80) 开放，HTTPS(443) 未开 → 之前 T-025/26 连接失败因误用 https。
  静态站 http://lutonada.online = Vite SPA「方舟地图模拟器」；后端 API = `http://152.136.189.98:3000`。
- **关卡索引**：`GET /json/story{CN|EN|JP|KR}.json`（1MB）—— 全部关卡树（活动/主线/肉鸽/合约/指标复刻，
  levelId 与客户端一致，如 `activities/a001/level_a001_01`）。
- **关卡完整数据**：`GET /levels/{levelId}.json` —— 与主仓 levels json **逐字段同构**：
  options / mapData(map 编号矩阵+tiles 定义) / routes(27 条, checkpoints) / waves(SPAWN 出怪) /
  enemyDbRefs / runes / predefines / randomSeed 等。
- **敌人实例数值**：`POST /enemy/data` body `{language:"CN", enemyRefs:[关卡json的enemyDbRefs]}` →
  关卡实例敌人属性（**经关卡等级/覆盖修正后的实际值**，如主线 1-7 暴徒 1700HP/250ATK/50DEF、
  拾荒者 5000HP/500ATK；与 enemy_database 基值不同）。
- **指标词条（tag）**：`POST /recalRune/getData` body `{levelId:"<关卡尾段>", language:"CN"}` →
  词条数据。关卡类型为 `obt/recalrune/level_recalrune_*`（story 索引中 id 带 "Mat" 后缀）。
- 其他：`/ccb/getData`(演出/背景)、`/recalruneTags/*.png`(词条图标)、`/assets/getTrapsKey|getTokenCards|getMeshsKey`(模型)。

## 二、「选 tag 看敌方属性」= recalRune 指标词条系统（✅ 用户点名功能）

- 露托模拟器中可选词条组合查看敌方属性变化，底层即 recalRune 数据 + 前端 runesHelper 应用。
- **数据结构**（fetch 样例 `tag_level_recalrune_01-01.json`，对应主线 7-18「#爱国者之死」指标复刻）：
  - `fixedRuneSeriesName` = 词条系列名（如「指标·死而不朽」）；`levelName`/`levelCode` 映射原关卡。
  - `parsedRunes[]`：17 组词条，每组 `{runeId, essential(必选/可选), exclusiveGroupId(互斥组), runeIcon,
    description[](中文词条文本), runes:[{key, selector{职业/敌人类别/阵营过滤}, blackboard[{key,value,valueStr}]}]}`。
  - 词条键示例：`enemy_leveltype_attribute_a`（精英敌人生命+200%…）、`enemy_patrt_5`、`enemy_movespeed_2`
    （移速-40%）、`char_cost_2`（我方部署费+7）、`char_highp_2`（高台生命-1500）、`enemy_sotiab_2` 等。
  - **敌方属性修正应用**（露托前端 runesHelper，黑盒）：rune 类型决定 calMethod =
    `add`/`addmul`/`mul`/`set`（enemy_attribute_add/additive_mul、ebuff_weight→add、默认 mul），
    按 blackboard 中 attr 键（key 经映射如 range_scale→rangeRadius、value→massLevel）修正敌方实例属性。
  - 词条描述中的 HTML 彩色数值 `<span style="color:#ff2020">` 即「改变后数值」高亮，可直接解析为中文展示。
- 本地模拟如需复刻"选 tag 敌人属性变化"：抓 recalRune 词条数据 + 解析 description 文本 +
  复刻 calMethod 应用（需对照露托前端 runesHelper 完整逻辑，或直接引用其处理结果）。

## 三、出怪时间/坐标本地化（✅ 核心修正：本地可解）

### 1. 来源：ArknightsGameData 主仓 `zh_CN/gamedata/levels/`
- **3868 关卡 json，约 500MB**（obt 2043 含 main 401 + roguelike 等 + activities 1823）。
- 每关含：mapData（map 编号矩阵 + tiles 定义 tileKey/height/buildable/passableMask）、
  **routes**（敌人路线：startPosition/endPosition row+col、checkpoints[] MOVE/WAIT + position + reachOffset 小数坐标）、
  **waves**（波次：fragments[].actions[] SPAWN + preDelay/interval/count/routeIndex + managedByScheduler）、
  enemyDbRefs（敌人 id+level+overwrittenData）、runes/optionalRunes、randomSeed、operaConfig、cameraPlugin。
- **完整版敌人基值**：`levels/enemydata/enemy_database.json`（14.7MB，2130 敌人形态组，
  **比 tomimi 精简版 1718 更全**：保留 m_defined 结构 + applyWay/motion/enemyTags/talentBlackboard/skills/spData）。
  源石虫 550HP/130ATK 与 PRTS/tomimi 一致 ✅。存 `E:\ak_kb\gamedata\enemy_database_full.json`。

### 2. 时间轴算法（✅ 露托 parseWaves/parseActions 核验，本库脚本已实现）
```
waveStart = wave.preDelay
fragments 串行: fragStart = 上一frag结束时刻 + frag.preDelay（首 frag: waveStart + preDelay）
每只怪 c: 时刻 = fragStart + action.preDelay + action.interval * c   (c = 0..count-1)
frag 结束时刻 = 本 frag 全部动作的最大时刻（h=max）
```
- 产出示例（主线 1-7，`spawns_main_01-07.json`，44 条逐怪展开）：t=6s 源石虫α×1 route1 →
  t=12/13s 源石虫α×2 route2 → … t=94s 弩手 → 99s 拾荒者…（自动 routeIndex 定位出生点/路线）。
- **坐标精度**：routes.checkpoints.position 为 (row,col) 网格整数 + reachOffset (x,y) 小数偏移
  （如 route[0] `(5,4) reachOffset(0,0)`）；引擎物理坐标另有 TILE_SIZE=6/相机旋转等变换（露托常量：
  TILE_SIZE:6, TILE_HEIGHT:3/7, MAP_ROTATION:.5, GROUND_ENEMY_YOFFSET:-.15, SIMULATE_STEP:1）——
  高精度模拟若需 3D 坐标可参考露托前端坐标变换，或直接用 row/col+offset 网格坐标。
