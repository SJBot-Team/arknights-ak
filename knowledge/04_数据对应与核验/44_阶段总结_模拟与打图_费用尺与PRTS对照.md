### 2.3 与赛博塑料（PRTS+）的对照（本阶段最大突破）
- **运行方式**：`prts+.exe --xlsm <ASCII路径> [--debug] [--autoenter]`；**中文路径会被打坏**，需 ASCII；
- **它抓 render_wnd(7801904)**，与我们独立发现一致；
- **轴表自带它的计时列**：`费用 | 帧数(tick) | 绝对时间(time)` ⇒ 精确时刻 = time + tick/30；
  与模拟器逐条吻合（令 1.50s、蕾缪安 20.00s）；
- **`--debug` 暴露其机制**：`Setting initial tick to N`（**从费用条相对长度读秒内帧**）、
  `frame threshold 2.0`、`bullet threshold 15.0`、`resuming and entering bullet time`（**核心手段=暂停**）；
- **现场验证**：在"费用必然封顶"的 H12-4 里，它**等不到 tick=0 ⇒ 计时停住 ⇒ 卡死判负**，
  完全复现用户所说"费用满后条停跳、游戏时间流逝而它计时器停止"。

## 三、本阶段新增的关键认知（可复用）
1. **费用条每满一次 = 30 帧（精确）**，但"**满 N 次 = N 秒**"只在**未封顶**时成立；封顶期间计时停住；
2. **上限突破事件**（平民进点 / 箱子被摧毁）是"费用重新流动"的**精确锚点**
   （模拟器实测：48.97s 上限 20→22、53.03s 22→24）；锚点后**相位会被重置**（首个 +1 间隔 26 帧而非 30）；
3. **相位可做绝对计时**（速率精确、无漂移、抖动有界 ±2 帧），**最佳采样间隔 ≈0.5~0.9s**；
4. **图像识别只应用于"确定事件发生在哪一帧"**（用户口径）：单位出生/血条变动/面板变化的精确帧；
   **坐标的实机检验不可行**（动画层与逻辑层不对齐）；
5. **PRTS+ 的机制与我们的方案同源**（暂停 + 费用条 tick + 轴表），
   它的 `frame threshold = 2` 与我们的 ±2 帧判据一致。

## 四、未完成 / 存疑（断点清单）
1. **实机"暂停 → 读相位 → 同帧多操作 → 按相位恢复"的闭环未跑通**；
   `paused_protocol` 只有离线测试（5/5 PASS），**无实机验证**；
2. **与 PRTS+ 的并排逐帧对照未完成**：最近一次已能同帧读到它的
   `initial tick / Getting current action at row 2 / Too much time, resuming…`，
   但它的**操作未能生效**（费用未被扣、费用涨到 20/30 封顶），且它**从 row 2 开始（跳过 row 1 令）**
   ⇒ 与用户所说"开局暂停次数错误导致操作顺序有误"吻合，**具体纠正方式待定**；
3. **费用封顶边界的 ±1 秒方向未定**（用户猜"多记一秒"）：需要一局**不会立刻封顶**的场景才能观察；
4. **"与模拟共用轴表"** 只在离线对齐过（里程碑测试），**未在实机闭环中验证**。

## 五、效率问题（诚实反思）
- **环境类问题吃掉了大量轮次**：桌面抓屏≠帧缓冲坐标、抓屏被遮挡抓到 DSH 文本、
  MuMu 被遮挡即停止渲染、低置信度误判（把按钮笔画当费用数字）、
  **判据用像素差异导致误判**（地图动画/静止界面）、**公式方向写错导致自证陷阱**。
  这些**本可以更早用"强制自检 + 手算样例"收敛**（后来才补上，如 `render_guard`、`bar_sanity`、`frames_between` 测试）。
- **实机导航反复试错**：坐标随界面变化，早期靠硬编坐标 ⇒ 多次空点；
  后来才改用 **OCR 定位 + MAA 模板判定（`UiState`）+ 点击生效校验**，这些应**一开始就做**。
- **单轮动作偏碎**：多次出现"先截图确认→再决定"的串行消耗，缺少把多步合并成一个可自检脚本的习惯。

## 六、方向问题（供用户定夺，我不擅自改）
1. **费用尺这条线已做得过深**：精度到 ±2 帧、锚点、时间轴都齐了，
   但**它只解决"读时间"，不解决"在同帧精确注入多操作"** —— 而后者才是打图的关键；
   ⇒ 建议**下一步优先验证"暂停驱动的同帧多操作"**（有 PRTS+ 做对照，风险低）。
2. **"坐标实机检验"已被用户判定不可行**，我们此前的验收口径里仍留着相关项，
   ⇒ 建议改成**事件帧口径**（出生/伤害/面板变化的精确帧）。
3. **与 PRTS+ 的关系值得重新定位**：它已具备"暂停 + tick + 轴表"的完整实现，
   ⇒ 可选"**参照/复用它的机制**"而非全套自研；我们自研的价值应集中在
   **模拟器侧（解包数据、寻路、伤害）**与**可离线验证的部分**。
4. **实机依赖过重**：多轮被"渲染冻结/界面漂移/编队不匹配"卡住 ⇒
   建议把工作切成"**离线可验证**"与"**必须实机**"两类，前者做扎实，后者集中时段做。
