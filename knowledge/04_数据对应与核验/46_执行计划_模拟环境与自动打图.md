## 三、分阶段计划（按价值排序）

### P0 —— 重建打图工作流（用户点名痛点：昨天关卡识别/进入效率低）
参照 **MAA 的任务流水线**（`tasks.json`：recognition(template/ocr/color) + roi + action + next + 多候选重试）
与 **prts+ 的"0 帧暂停/过帧"**，实现：
1. **`pipeline` 引擎**：一份 YAML/JSON 描述"识别→动作→下一步"，取代 if-else 试错；
2. **步进优先**：**操作前先步进（暂停）→ 定位目标帧 → 再执行**，给识别留足时间；
3. **界面识别用模板+OCR 双通道**（复用 `maa_anchor`/`ui_state`，扩到"启动→主界面→终端→选关→编队→出战"全链路）；
4. **每次动作都带生效校验**（语义判定，非像素差异）。

### P1 —— 模拟环境标准化
1. **关卡驱动**：任意关卡同一套加载流程（地图/单位/机制/波次/路线）；
2. **外部输入**：练度、模组、敌方 tag 加成等做成配置；
3. **逐帧切片补全**（操作/血量/坐标/攻速/移速/随机判定）+ 可选落盘；
4. **事件帧钩子**（可查询的事件时间线）。

### P2 —— 事件帧验证（模拟 ↔ 实机/视频）
1. 从视频逐帧提取**事件**（单位出生、血条变动、面板变化、费用变化、上限突破）；
2. 与模拟器事件时间线**逐帧比对**，输出差异表（这是用户认可的准确性判定方式）；
3. 先在**弧光/净罪**（费用没满、有精确轴）上做，再回到 H12-4。

### P3 —— 费用条满后的帧识别（探索）
- 已知：封顶时条静止 ⇒ 相位失效；需靠**上限突破锚点**（平民进点/箱子被摧毁）续接；
- 要探索：**锚点之间**（可能长达十几秒）如何精确计数——候选：其他 UI 计时元素、
  敌人/单位的周期性动画、画面内**帧计数可靠**的元素（如技能 SP 条、敌人行动循环）。

### P4 —— 案例验证
- H12-4 双人解（视频 + 轴表）、弧光 7 人、净罪 7 人；产出"事件帧对照表"。
