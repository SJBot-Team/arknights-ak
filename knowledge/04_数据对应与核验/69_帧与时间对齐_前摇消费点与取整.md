### 2.2 写点：`AbstractAnimatedAbility.UpdatePlaybackSpeed` `0xA6E070`（🟢T1）

签名：`protected override bool UpdatePlaybackSpeed(AbilityStandard.UpdatePlaybackSpeedTiming timing, out float animSpeed)`（Slot 102，`AbstractAnimatedAbility` 11023）。
`AbilityStandard.UpdatePlaybackSpeedTiming`（**8429**）= `FORCE_UPDATE=0` / `ON_CAST_START=1` / `RECOVER_FROM_INTERRUPT=2`。

关键指令（+0x 相对方法入口，`rdi`=`this`）：

```
+0x0AD  mov  [rdi+0x1A8], rax          ; m_attackTime = F(animDuration, ...) 的一路
+0x0B7  mov  dword [rdi+0x1B0], 0x3F800000   ; m_animScale = 1.0f
+0x102  mov  r10, [rax+0x798] ; +0x115 call r10        ; 虚分派取"动画时长/曲线"（桩无方法名，🟡）
+0x149  divss xmm0, xmm7                               ; xmm7 = 动画时长(秒)
+0x14D  maxss xmm0, [rip+0x52F8B93]                    ; 下限夹取（常量未解析→🟡）
+0x155  movss xmm1, [rdi+0x198]                        ; _maxAnimScale
+0x160  movss [rdi+0x1B0], xmm0                        ; m_animScale = 夹取后比例
+0x16A  minss xmm0, xmm1 ; +0x16E movss [rdi+0x1B0], xmm0
+0x193  mulss xmm6, xmm7
+0x19C  call FP.op_Implicit(float) 0x54E4420           ; ★ float 秒 → FP（截断，见 §3-①）
+0x1A1  mov  [rdi+0x1A8], rax                          ; m_attackTime = animScale × 动画时长
+0x1AD  call 0x5090                                    ; 虚分派桩（🟡 槽名未定）
+0x1B2  mov  rsi, [rdi+0x1A8]                          ; rsi = m_attackTime
+0x1BB  jne  0x219                                     ; 分支：直接取 m_attackTime
+0x1C4  movss xmm7, [rdi+0x180]                        ; _preDelay（float，秒）
+0x1CC  movss xmm6, [rdi+0x1B0]                        ; m_animScale
+0x1E2  mulss xmm6, xmm7
+0x1EB  call FP.op_Implicit(float) 0x54E4420
+0x211  call 0x4A95170                                 ; FP 缩放/夹取（🟡）
+0x216  mov  rsi, rax
+0x219  mov  [rdi+0x1A0], rsi                          ; ★★★ m_preDelay 写入点 ★★★
+0x222  movss xmm0, [rip+0x52F88DE] ; +0x22A divss xmm0, [rdi+0x1B0]   ; 常量 / m_animScale
+0x241  mulss xmm0, [rsp+0x34]
+0x247  movss [r14], xmm0                              ; ★ out animSpeed
```

**读法（🟢 指令实证 + 🟡 语义推定）**：

- `UpdatePlaybackSpeed` 同时产出三样东西：`m_attackTime // 0x1A8`、`m_animScale // 0x1B0`、**`m_preDelay // 0x1A0`**、以及 `out animSpeed`。
- **`m_preDelay = m_attackTime`**（同一条 `rsi` 走 `+0x1BB` 分支直达 `+0x219`），或 `= m_attackTime × m_animScale ÷ _maxAnimScale` 经 `0x4A95170` 处理。
- ⇒ **`m_preDelay` 在数值上被定义成 `m_attackTime` 的一个（缩放）副本**，与 67a/68 记的 `_preDelay // 0x180`（配置的秒数）**不是一条链**。

### 2.3 读点：`AuraAbility.OnTick` `0xA71020`（🟢T1）

`AuraAbility : AbilityStandard, IAuraAbilityControl`（**11037**）。

```
+0x070  call AbilityStandard.OnTick(FP) 0x34F3300     ; 先跑基类每帧
+0x09C  rsi = [rdi+0x130]                             ; 该 aura 持有的 ability（ObjectPtr）
+0x0B9  call Object.op_Inequality 0x5964E30 ; je 跳过
+0x0E3  rax = [rsi]                                   ; ★ ability 的 vtable
+0x0E6  rdx = rbx                                      ; rbx = FP deltaTime（本方法第 2 参）
+0x0E9  rcx = rsi                                      ; this = 该 ability
+0x0EC  r8  = [rax+0x1A0]                              ; ★★ m_preDelay 由 vtable 偏移 0x1A0 直读
+0x0F3  call qword ptr [rax+0x198]                     ; ★ 虚分派
```

- 槽偏移 `0x1A0`（即 Slot 52）× 8 = **Slot 52**；`0x198/8 = Slot 51`。
- `AbstractAnimatedAbility` 的 Slot 51 是 `OnCastEnd`，Slot 52 **不在** `AbstractAnimatedAbility` 的 Slot 列表里 ⇒ 该 aura 持有的 ability 是**另一个类**（`[Character+0x130]` 取得），其 Slot 52 的签名按调用约定是 **`(FP) -> ?`**。
- 按 `AbilityStandard` 侧同名签名对齐，**最可能就是 `AbilityStandard.UpdatePlaybackSpeed(UpdatePlaybackSpeedTiming, out float) 0x34F3B50`**（`timing` 走 `edx`=`rdx` 低 32 位 = `deltaTime` 的低位，明显不是枚举语义）—— **🟡 槽名未静态定名，不做硬断言**。
- **确定的部分（🟢）**：`m_preDelay // 0x1A0` 被当作**一个 `FP` 实参**传进一次虚分派调用，并且**每帧**发生在 aura 的 tick 上。**它不是被比较、不是被递减、不是被清零。**

### 2.4 与 `AbilityStandard.Event` / `OnEvent 0x34F26A0` 的关系

- `AbilityStandard.Event`（**8426**）：`ON_ATTACHED=0 / ON_DETACHED=1 / ON_CAST_START=2 / ON_CAST_END=3 / ON_SPELL_ON=4 / ON_SPELL_END=5 / ON_ATTACK_FINISH=6 / ON_ATTACK_CHECK_POINT=7 / ON_OVERLOAD=8`（沿用 68 §2.3，本轮未重核）。
- 本轮新增（🟢T1，调用点实测）：
  - `AbstractAnimatedAbility.OnCastStart 0xA6DEF0` 在 `+0xD2` 调 **`0x10400`** —— 该目标共 43 个 E8 调用者，全是**播动画**用途（`OnCastStart`/`OnCastEnd`/`AnimationEmitBehaviour`/`Character.States.Blackboard._PlayAnimation`/`Character.PlayBornAnimationAndEffect`/`CycleThreePartAnimation`/`Enemy.States.BasicState._PlayAnimation`），此处带 `xmm0`(秒) + `ecx=0x63` + `r9b=1` 的 7 参调用。
  - **`AbilityStandard.DoUpdatePlaybackSpeed 0x34F0810` 的全部 4 个 E8 调用者（🟢T1）**：`AbstractAnimatedAbility.ApplyAttackTime +0xA2`、`AbstractAnimatedAbility.OnAttackTimeChanged +0x64`、`AbilityStandard.OnCastStart +0xE0`、`AbilityStandard.OnAttached +0x47` ⇒ **`0xA6E070 UpdatePlaybackSpeed` 在"装配 / 开始施放 / 攻速变化"三种时机都会被驱动**，因此 `m_preDelay // 0x1A0` 也随之刷新（§4-5 的疑点部分消解）。
  - 尾段（`0xA6DFE3` 起）与 `m_animScale // 0x1B0` 相关（`+0x1C3 divss xmm0, [rbx+0x1B0]`）。**`OnCastStart 0xA6DEF0` 全函数再次确认不含 `[+0x1A0]`/`[+0x180]`**，印证 68 §2 与 67a §9-2 的反证。
- **判定**：
  1. 「前摇结束 = 事件帧到达」**在"出伤时刻"这一问上成立**（68 已给链），但**不能解释"前摇窗口多长"**——那个口径的代码载体**不是 `m_preDelay`**。
  2. **`m_preDelay` 既不是"上限窗口"也不是"精确倒计时"，它是"动画播放速率计算的一个输入/缓存"**（见 §2.2 的写点语义）。
  3. 「无动画/无事件帧时前摇的保底」**不在 `m_preDelay` 上**（本轮未定位）⇒ 🔴 见 §4-2。

### 3.2 唯一的取整指令：`FP` 浮点转换用截断（🟢T1）

```
0x054E4420  f30f590574b9af00  mulss   xmm0, dword ptr [rip+0xAFB974]   ; ×2^32
0x054E4428  f3480f2cc0        cvttss2si rax, xmm0                      ; ★ 截断（toward zero）
0x054E442D  c3                ret
0x054E4440  f20f590548b9af00  mulsd   xmm0, qword ptr [rip+0xAFB948]   ; ×2^32 (double)
0x054E4448  f2480f2cc0        cvttsd2si rax, xmm0                      ; ★ 截断
0x054E444D  c3                ret
```

- 常量已解析：`0x54E4440+8+0xAFB948 = 0x5FDFD90` 处为 `f64 = 4294967296.0 = 2^32`（`000000000000f041`）⇒ 与 `FP.FRACTIONAL_PLACES = 32` 一致。
- 方法名：`FP.op_Implicit(float)` **`0x54E4420`**（`dump.cs` 1236316）；`FP.FromFloat(float)` `0x54E23C0`（1236358，**E8 调用者实测仅 1 处** = `ReloadAnimatedAbility.DoSetData`）。
- ⇒ **任何 float 秒 → FP 的转换都会丢小数位（向零截断）**。**这是整个"时间→帧/时间量化"链上唯一确定性存在的取整指令。**

### 3.3 整数帧计数器：`s_fixedFrameCnt`（🟢T1）

```
BattleController.OnTick 0x354F880   (+0x133)
0x0354F9AC  mov rcx, qword ptr [rcx+0xB8]     ; rcx = BattleController.Il2CppClass.static_fields
0x0354F9B3  inc dword ptr [rcx + 0x14]        ; ★ s_fixedFrameCnt++（uint @ static+0x14）
```

- ⇒ **帧计数器是"每 tick 恰好 +1"的整数，不含任何时间换算/取整**。
- `BattleController.s_fixedFrameCnt // 0x14`（`uint`，`get_fixedFrameCnt 0x3563340`）的 **33 个 E8 调用者**里，与"帧对齐"直接相关的是：
  - **`PeriodicTickerNoUpdateNeeded`**（**9142**：`m_tickPeriod // 0x10`、`m_nextReadyFrame // 0x14`，均 `uint`）—— **纯帧计数 ticker**；`get_isReady 0x5DB550 / get_remainingTick 0x5DB630 / ctor 0x5DB5A0 / Reset 0x5DB460 / 0x5DB4D0 / Next 0x5DB3C0`。确定性索敌（`SEARCH_TARGET_TICK = 3`，67 §2.2）走这条。
  - `CompoundPeriodicTicker._InitIfNot 0x5CF2F0` 附近（`PeriodicTicker m_tranditionalFindTargetTicker //0x10` + `PeriodicTickerNoUpdateNeeded m_deterministicFindTargetTicker //0x18`）—— **时间制 vs 帧制两条索敌节拍并存**，`bool isDeterministic` 选路。
- ⇒ **"帧"在代码里有两种载体**：① 纯整数帧号（`s_fixedFrameCnt` / `m_nextReadyFrame`，**无取整问题**）；② 连续 `FP` 秒（计时器/攻击间隔，**不取整**）。

### 3.4 唯一的"秒→整数个"取整：`PrecisePeriodicTimer.UpdateMultiple`（🟢T1）

```
PrecisePeriodicTimer.UpdateMultiple(FP deltaTime)   0x1AFBF80
+0x05F  mov rbx, [rsi+0x18]                 ; m_remainingTime
+0x05F  call FP.op_Addition 0x54E23A0       ; m_remainingTime += deltaTime
+0x0F  call PrecisePeriodicTimer.get_isReady  虚分派 [rdx+0x178/0x180]
        └ 若 ready：
+0x31  call FP.op_Division 0x54E4490        ; (剩余时间 / periodTime)
+0x40  call FP.op_Multiplication 0x54E4080  ;   × ...
+0x62  call TSMath.FloorToInt 0x54E79F0     ; ★★★ 唯一的 floor ★★★
+0x69  test eax,eax ; cmovs eax, 0           ; 负数夹到 0
+0x6E  inc eax                               ; return floor(...) + 1
```

- ⇒ **"秒 → 整数个周期"用 `FloorToInt`（向下取整），结果 +1 作为本帧应补的次数。**
- **但它只被一处调用**：`Entity.SpController.OnTick` **`+0xB5`**（`t200a_callers.py 0x1AFBF80` 实测 **1 处**）⇒ 这是 **SP 回复的逐帧补算**，**与攻击间隔无关**。
- 另注：`PrecisePeriodicTimer` 也是**费用计时器**的载体（`BattleController.m_costTimerDict // 0xC8 : ListDict<PlayerSide, PrecisePeriodicTimer>`，`get_CostTimer 0x353…`）——**费用回复是否也走 `UpdateMultiple` 本轮未核**（`UpdateMultiple` 的 E8 调用者只有 SP 一处，费用侧大概率走 `Update`+`isReady`，§4-3）。

### 3.5 攻击间隔链的完整判定（回答 K-004）

```
Entity.OnAttributeDirty 0x35FD87E                    （68/67a 已证：唯一 E8 调用者）
  └─ BattleFormula.CalculateAttackInterval 0x3584F10  = base / (clamp(S,10,600)/100)   ← 2 次 FP.op_Division，0 取整
       └─ AbstractAnimatedAbility.ApplyAttackTime 0xA6CD40
            ├─ 0xA6CDC6 mov [rbx+0x1A8], rdx          （写 m_attackTime，FP）
            ├─ 0xA6CDB0 call FP.AsFloat 0x54E1710    （FP→float，供动画用）
            └─ 0xA6CDE2 call AbilityStandard.DoUpdatePlaybackSpeed 0x34F0810（改动画播放速度）
                 └─ AbstractAnimatedAbility.UpdatePlaybackSpeed 0xA6E070
                      └─ +0x19C / +0x1EB call FP.op_Implicit(float) 0x54E4420   ← ★ 此处截断
```

**判定**：

1. **攻击间隔本身（FP）不取整**；`GetDuration 0xA6D720` 直接返回 `[rbx+0x1A8]`，进出的都是 `FP`。
2. **"帧对齐"意义上的取整（把间隔变成整数帧）在代码里不存在**：没有任何一处把 `m_attackTime` 交给 `FloorToInt/RoundToInt/CeilToInt`（三个函数的全部 E8 调用者已逐一归属，见 §3.1）。
3. **真正存在的一次取整，是 `FP` 与 `float` 之间的转换用 `cvttss2si` 截断**（§3.2），它作用在"动画时长/播放速度"与"`_preDelay` 秒值入 FP"上，**不是"间隔→帧"**。
4. ⇒ **`04/36 K-004` 的「攻击间隔向上取整」在本层不成立（反证）**，并且方向也不是"上"：唯一带方向的取整是 `FloorToInt`（向下）且只在 SP 回复上。**社区旧口径（涵盖 2019-12-24 之前的帧对齐）在**当前客户端二进制里找不到对应指令**。**

### 本轮工具局限（复用须知，**新增**）

1. **capstone 的 `ins.address` 按 32 位处理**：`md.disasm(code, rva)` 传 >2^31 的 RVA 会得到负数地址、且 `code_size` 被截断；**必须以"段内相对偏移"为 base，最后再加段 RVA**。（本轮 v7/v11/v13 三次踩坑）
2. **操作数顺序**：`mov reg, [reg+disp32]` 的 capstone 操作数是 `[REG, MEM]` —— **只看 `operands[0]` 会漏掉全部"读"**。
3. **ModRM 位序**是 `[mod:2][reg:3][r/m:3]`，mod=10 ⇒ 数值高位 `0x80`；**`0x89` 是 opcode 不是 ModRM**（本轮早期版本据此漏扫全部写点）。
4. **按 disp 裸筛必然爆量**：`disp32=0x1A0` 在可执行段出现 4106 次、精确命中 2821 条、跨 2606 个方法 —— **必须结合"方法所属类"二次筛**。
5. `read_cpp.py xref` 仍会 `IndexError`（67a 已记）；本轮改用自写 E8 调用点全表缓存（`.tmp\t200a_calls.pkl`，237024 个目标）——**强烈建议合并进 `read_cpp.py`**。
