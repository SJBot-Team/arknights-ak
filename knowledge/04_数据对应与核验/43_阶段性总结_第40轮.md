## 四、当前唯一硬阻塞与恢复后第一步

**阻塞**：模拟器（MuMu）窗口处于**不渲染**状态。`adb exec-out screencap -d 2` 只返回静止的最后一帧
（实测相邻帧差异**精确为 0.0**），`SetForegroundWindow` 未能恢复 ⇒ **需人把模拟器窗口恢复为可见**。
已落地 `plugins/capture/render_guard.py` 作为所有实机脚本的强制第一道关（不通过即退出，绝不把静止帧当游戏状态）。

**恢复后第一步（无需改代码）**：
```bash
cd ak/code/vision && .venv/Scripts/python apps/phase_precision_test.py 8
```
它已具备：渲染前置 → 点击生效校验 → 章节回切 → 立刻密集采样 → 相位↔墙钟精度比对。
通过后接 `paused_protocol.same_frame_batch()` 做「暂停→读相位→同帧多操作→按相位恢复」闭环。

## 五、本阶段最有价值的六个根因（都已修复并留档）

1. **地图行序反了**：`mapData.map` 的存储行序与关卡 `row` 相反（用门/传送点地块四重证据定位）；
2. **检查点被整段跳过**：`position` 被存成裸整数 ⇒ 敌人绕过全部检查点直奔终点（整条流水线偏快 7s）；
3. **令的模组**：`tokenAttributeBlackboard` 给弦惊 **cost −5** ⇒ 23→18 费，此前"放不下"是假命题；
4. **暂停才是帧级精度来源**（用户指正）：延迟不进误差，唯一要对齐的是恢复瞬间，且要用**游戏内量**对齐；
5. **抓屏坐标系**：桌面抓屏 ≠ 帧缓冲坐标；且会被上层窗口遮挡（曾抓到 DSH 文本）；
6. **低置信度误判**：把编队按钮笔画当成费用数字（conf 0.328 vs 正确 0.962）⇒ 强制置信度阈值 + "画面在变"自检。
