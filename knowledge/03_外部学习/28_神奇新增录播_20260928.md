## 1. 0927 出怪帧（BV1cmaa6VEPR）——新增结论

### 1.1 出怪帧的定义与"逐帧错开"（本场最核心）

- **出怪帧 = 出"影子"的那一帧**（作者定义）：因为需要索敌目标的技能（崖心二技能 / 歌蕾蒂娅三技能 / 见行者二技能）此时已可开启 ｜BV1cmaa6VEPR [685] [688]
- **一帧一出怪**：JSON 里同样定义在 0 秒的多只怪，实际出生时刻是**逐帧错开**的（0 帧 / 2 帧 / 3 帧 / 4 帧）｜[648] [663]
- 即使 map 定义里全是"0 秒出生"，其**真实时间也要一帧一出**｜[668] [676]
- 理论上同刻的怪（如 0 秒两只、5 秒两只）实际**至少是"理论时刻 + 1 帧"**｜[712] [719] [1129]
- 案例：0 秒那一组出现"0 帧、2 帧"，5 秒那一组出现"5 帧、5 帧"——**多出来的帧不是误差**｜[730] [738]

### 1.2 调度的三层结构与基准点（**修正/收紧 `04/27 §三.2` 的表述**）

- JSON 格式：`waves`（波次）→ 一个波次含多个 `fragments`（**兵团**，PRTS.wiki 译名）→ 一个兵团含一堆 `actions`（**小队**）｜[768] [776] [817] [829]
- **波次之间**是"上一个波次出完才出下一个波次"（但"还有卡的东西"，见 §1.4）｜[838] [842]
- **兵团（fragment）的 `preDelay` 基准 = 本波次开始时间**；各兵团以"上一个兵团**出完** + 本兵团 `preDelay`"串行｜[888] [906] [963]
- ⚠️ **小队（action）的 `preDelay` / `interval` 基准 = 本兵团开始执行的那一刻**，**不是**上一只怪出完的时刻｜[995] [1001] [1003]
- `count` = 出怪数量、`interval` = 出怪间隔（作者原话把 interval 说成 "interview"）｜[944] [949] [964]

### 1.3 本质：**"安排间隔"而不是"安排绝对时间"（N 条衍生结论的总纲）**

- JSON 里写的 5 / 9 / 14 / 23 / 30 等数字，**描述的都是"间隔"**：23 那只出完后过 7 秒出下一只、14 那只出完后过 9 秒出下一只｜[1070] [1091] [1117] [1120]
- ⇒ 整个程序运行的是**相对间隔**，因此上游任何一只怪的时刻变动都会**顺移后面全部怪**｜[1081] [1085]
- **每两个出怪之间 = 理论间隔值 + 1 帧**｜[1129] [1148] [1156]
- 攻略实测踩坑案例：某图因"最后一只怪被隐藏"导致兵团提前结束、下一兵团提前出，**实际比测试晚出怪约 10 秒**，技能轴全崩｜[2880] [2902] [2916]
- 直接可用的操作结论：**合约中测出怪时间时，TAG/点选要尽可能点全**，否则测得的轴不可用｜[2836] [2841]

### 1.4 路线预言、牌子、隐藏组与卡波次

- **路线预言（routePreview / 路线掩饰）也是出怪**：它占出怪时间、参与出怪排序｜[2717] [2719]
- 路线预言安排在**出怪前理论时间的 3 秒与 2.7 秒**（两条路线 ⇒ 两个光标）｜[1264] [1271] [1274]
- 最后一只怪出生后 2 秒（+1 帧）出第一条路线的预言｜[1290] [1293]
- **牌子（预兆）同样是同刻可占位的"出怪"**｜[2722] [2725]
- **排序规则**：把全部 `count` 展开、再把牌子和路线预言按各自时刻一并加入，**统一排序**（因此"排序总数 ≠ count 之和"）｜[2734] [2748] [2759]
- **被隐藏的同刻出怪不占时间**：合约因 TAG 而隐藏的出怪，等价于 JSON 里根本没写这两行｜[2766] [2781]
- **若兵团里时刻最大的那只怪被隐藏 ⇒ 该兵团提前结束 ⇒ 下一个兵团提前出**｜[2794] [2827] [2831]
- **卡波次默认开启**：只要本波次的怪没死光，下一波次的怪就不出生（作者称默认参数为 0、"不卡"未开启）｜[2966] [2975] [2990]
- 兵团结构是**离散**的：上个兵团结束才执行下个兵团；可用参数改成"上个兵团全灭才执行下一个"｜[3033] [3040] [3053]

### 1.5 顺带讲到的高地与阻挡（跨章内容，属新增 → **已全部代码核验，见 V5**）

## 2. 0926 属性，伤害（BV1xRho6DEAQ）——新增结论

### 2.1 总框架：属性 vs 非属性

- **属性**可以在局内按四则运算调整（直接加 / 最终加等），**非属性**不具备这些、只看设计效果本身｜[791] [815] [830] [844]
- 攻击力、防御、法术抗性、物理穿透、法术穿透……属"属性"；剧作家/藏品一类效果属"非属性"｜[803] [808] [819]
- **伤害一律是乘算的**：肉鸽那种"加算伤害"更应理解为鹰角把藏品数值**整理成一个 buff 乘区**后统一乘算｜[846] [852] [857] [872]
- 作者明确引用花佬（`21`/`22a` 的专栏口径）作为属性认知基准｜[932] [938]

### 2.2 基础公式与真伤的本质

- 物理 = 攻击 − 防御；法术 = 攻击 × (1 − 百分比法抗)；元素伤害与法术等同处理｜[658] [666] [680] [696] [650]
- 真伤/治疗的本质：**跳过抗性结算流程**｜[744] [748] [777]
- ⇒ 鹰角**无法以"不改代码"的自然方式加一个"真伤抗性"**让敌人减真伤｜[750] [755] [758]

### 2.3 「攻击力倍率」≠「攻击力提升」（本场最易错点）

- **攻击力倍率**是在**攻击力属性结算完成之后**再做的倍率提升（"属性 × 倍率"）｜[4504] [4511] [4513]
- **攻击力倍率仅对"普通攻击（含余震）"生效**，不外溢到其它内容｜[4557] [4561]
- 对照案例：EW 的 1.85（爆炸/晕眩伤害）**不作用于** 1.25，1.25 也不作用于 1.85，这才是正常表现｜[4626] [4631] [4677]
- 而**攻击力提升**会直接应用到所有吃攻击力的乘区，二者从结果上常看不出差别，但机制不同｜[4546] [4616] [4621]
- 判读规则：**PRTS 未标注时，优先默认"不应用到主效果以外的位置"**｜[4651] [4658] [4697] [4722]

### 2.4 保底、上下线与结算顺序（**修正常识**）

- **0.05 保底属于"抗性结算流程"，不是"最终伤害"的保底**；它给出的是**初始伤害**｜[4754] [4758] [4761] [4764]
- 因此后续减伤可以继续削它：减伤 99% 时可打出 **0.005 × 攻击力**的伤害｜[4769] [4775] [4784]
- **属性结算流程有上线下线**，抗性结算流程在此之后｜[5247] [5258] [5266]
- **法抗先被夹到上限 100，再算穿透**：150 法抗在"法穿 10"下按 `100 − 10` 结算，**不是** `150 − 10`｜[5274] [5281] [5291] [5301] [5311]
- 参与物法抗性结算的共 **6 个属性**（攻击力 / 防御 / 法术抗性 / 物理穿透% / 法术穿透% + 固定穿透两条线）｜[5198] [5200]
- 防御侧流程：防御属性结算完 → 按百分比物穿再结算 → 得到抗性结算所需的防御力；另有固定穿透｜[5103] [5110] [5115] [5206]
- 总流程顺序：**攻击力结算完 → 防御（含穿透）结算完 → 做减除运算并下限夹 0 → 抗性结算**；"取整有自己的位置、加数值有自己的位置、减数值有自己的位置"｜[5219] [5224] [5242] [5325] [5340]
- **伤害只在第 3 阶段（伤判）算**，减伤也在同一环节｜[6658] [6660] [6663]

### 2.5 真伤并不免疫伤判（**修正 `26`/`21` 的粗口径**）

- **真伤只跳过抗性结算流程，不跳过伤判流程**｜[6691] [6693]
- ⇒ 真伤**可以吃脆弱**（如零蓝的脆弱），也可被**全类型减伤**削减｜[6698] [6702] [6706] [6708]
- 我方干员的屏障、格挡、"200 伤害"等多按真伤口径结算（真伤盾普遍存在）；同时干员也有针对真伤的减伤（并非只有物法减伤）｜[6721] [6730] [6732] [6741] [6769]
- 反例：**生命流失**能打无敌、却**吃不到脆弱**（不能靠它被脆弱放大）｜[6880] [6885] [6890]

> ### ✅ 裁定（2026-09-28 本会话）：**「真伤不吃脆弱/减伤」判为错误**，不再是"待核 T2"
> PRTS《伤害分类》原文（存档 `_raw\prts\伤害分类.wikitext.txt` L23–25）：
> 「**真实伤害**：基本伤害类型，造成伤害时**不计算任何防御属性**。造成的基础真实伤害 = 使用属性」
> 「**不指定伤害类型的伤判效果可以对真实伤害生效**，也即**真实伤害可以被减免、格挡或闪避**。」
> ⇒ 真伤的正确定义 = **只跳过"防御属性结算"这一环，伤判环节照走**；它与"生命流失"（跳过伤判全部事件，
> `02a §207/§444` 的 `SKIP_MODIFIER_EVENT`、`65 §life_loss`）**不是一回事**，此前被并成一条才产生"不吃脆弱"的错觉。
> **代码侧仍缺的一环（建议排一轮）**：`脆弱`/伤害修改（`ba.fragile` 等）的**施加点是否按 `damageType` 过滤**——
> `PURE/HEAL` 同分支只证明"跳过抗性结算"，**不证明"跳过伤判"**；见 §4-6。

### 2.6 弹道、离弦与"缓存攻击力"

- **弹道是一个"数据包"**：记录来源、攻击力、倍率、技能效果等｜[7908] [7934] [7945]
- 命中时的取值规则：**倍率随弹道缓存（存下发时的值）**，**攻击力加成默认实时向来源索取**｜[8210] [8216] [8223]
- ⇒ 产生 **正离弦 / 反离弦**：技能期内发射的箭在技能结束后才命中，**吃不到攻击力加成**（黑开技能期就是"正离弦"反例）｜[7967] [7971] [7977] [8197] [8403]
- 实测：同一串伤害中最后一下 182 vs 常态 355（1.95 倍差），即"吃到技能倍率、没吃到攻击力加成"｜[8160] [8170] [8194] [8199]
- **缓存攻击力原本只是"来源已死"的保底机制**，不是普遍机制；一旦缓存，**红字（暴击显示）就很难出**（埃拉当时的修补即由此而来）｜[8312] [8340] [8360] [8378] [8383]
- 敌人**死亡状态机**（约 30 帧、变灰特效）期间敌人依然存在，但**已清空自身全部局内 BUFF**｜[7839] [7852] [7858]
- ⇒ 由死亡状态机触发的结算（如风滚草）**注定吃不到局内加成、只吃局外加成**；出弹道时虽记录了带加成的攻击力，但"没有应用"｜[7866] [7876] [7902] [7911]
