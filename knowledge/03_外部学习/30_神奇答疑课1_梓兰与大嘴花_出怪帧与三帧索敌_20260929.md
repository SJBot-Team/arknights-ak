## §1 一句话结论

**该视频"再部署就不被大嘴花吃"是**运气**，不是再部署本身的机制**：能否躲开花，只取决于「**花的索敌帧**」与「**梓兰可被索敌的帧**」两者是否错开；而**花的索敌帧 = 其出生帧 + 2，之后每 3 帧一循环**，出生帧又随**同刻出怪的总数与顺序（一帧一出）**漂移——所以三局"同一个位置"的花出生帧各不相同，"0/1/2 三帧部署"三次全错属必然。此外作者**否证**了评论区两种解释：① 骗过前摇会让索敌帧**概率化、不可复刻**（不是可算的）；② 「梓兰天赋延长落地隐」虽属事实，但**不影响该在哪帧部署**（因为延长的 21 帧恰为 3 的整倍数，索敌相位不变，只需改"开技能帧"）。

### §2.A ★帧级对齐专节（本文最核心，单列）

#### A1 出怪帧 / 调度（`Scheduler` / `ActionItem` / `timeOffset` / "每两个出怪差 1 帧"）

- **出怪帧不是写死的绝对时刻，而是"间隔"的涌现**：JSON 里若干怪都写"0 秒出生"，实际出生时刻**逐帧错开**（一帧一出）。｜§三次失败的原因 ·「map 上写着理论同时的那些怪要**一帧一出**」
- **每两个出怪之间 = 理论间隔 + 1 帧**（本文口径）；作者用"**至少**"限定：任何一只怪早出生，**至少**让所有比它晚的多 **1 帧**。｜§三次失败的原因 ·「不同时的那些，多一个怪早出生，就**至少**让所有比他晚的多**一帧**」
- ⇒ **整个调度跑的是相对间隔**，因此上游任何一只怪的时刻变动都会**顺移后面全部怪**。｜§三次失败的原因（"出怪帧也是理论可算的东西，但本文姑且不引申怎么算只给结果"）
- **出怪帧会因"出怪情况"改变**：任何**路线上 / 时间上 / 数量上**的变化——**源石宝箱、零件箱、萨卡兹的刺**的出生——都**可能**影响**其他所有怪**的出生。｜§三次失败的原因
- **map 上"理论同时"的怪有确定的排序**（该图开局）：6 怪 `456123`、8 怪 `65872143`、9 怪 `769852143`（编号规则：上排左→右 = 1/2/3，下排从左到右递加；`456123` 意为上左/上中/上右是第 4/5/6 个出）。｜§正确的帧数计算过程
- **狗出生 → 下一帧召唤花 ⇒ 额外 +1 帧**（30 怪与 33 怪的上怪是狗；32 怪上三是真花，不 +1）。｜§正确的帧数计算过程
- **每多一个箱子额外 +1 帧，但对花的出生顺序无影响**；**鸭 / 狗 / 熊 / 鼠对出生时间和顺序都没有影响**。｜§小结论
- **同一只花在不同局里的出生帧**：30 怪 / 32 怪 / 33 怪 → 上中花出生帧 **6 / 5 / 7**，对应索敌帧 **8 / 7 / 9**。｜§小结论
- **"开局出怪数"口径要分清**：本图的 30/32/33 指**开局出怪 6/8/9**；**不要**把"开局 8 怪 + 结尾 1 鸭狗熊"当成 33（开局 8 怪就按 32 算）。｜§正确的帧数计算过程 ·（原文加粗）
- **紧急关**：少 2 怪，按开局一波出 6/8/9 与普通同样处理 ⇒ **紧急 28 = 普通 30**。｜§小结论
- **本文未给出帧级算法**（只声明"出怪帧是理论可算的"）；对应的代码侧算法本库已有（见 §3、§4）。｜§三次失败的原因

#### A2 三帧索敌

- **敌方索敌帧 = 出生帧 + 2 起，每 3 帧一循环（3n）**。例：该花 **7 帧出生** ⇒ 索敌帧 **9, 12, 15, …**。｜§花的索敌帧 ·「花的索敌帧，是从出生开始后**2 帧**开始，**三帧一循环**的」
- **"3 帧一次"只在"能索敌的状态"下才推进**：索敌帧会因出生后的**抬手 / 眩晕 / 攻击**等流程而改变。｜§澄清第一 ·「**索敌帧不是每三帧一次，是能索敌的状态才能转**」
- **"以出生帧 + 2 计算敌方索敌帧"仅限第一次抬手**。｜§澄清第一 ·（原文加粗）
- **骗前摇会让索敌帧产生"概率"**：这种操作下"即使局内出怪完全一致、操作按帧复刻，也不保障现象可复刻"⇒ **必须规避**。｜§澄清第一
- **"躲索敌"与"是不是再部署"无关**；**骗过前摇才是打乱帧数的变量，而且不可算**。｜§澄清第一
- **一帧一出怪 ⇒ 索敌帧必定因出生而错开**；在没有东西对齐索敌帧时，**梓兰没法同时躲两个怪的索敌**。｜§澄清第二
- **"出生"的判定口径**：怪**出影子**定义为出生；但**黑流树海特殊**——影子刚出现时是**小黑狗**出生，**影子变得更暗**才是**花**出生（看不准就去看贴图的出生帧）。｜§花的索敌帧 ·图8 图注

### §2.B 干员侧（被索敌帧 / 落地隐 / 骗前摇）

- **梓兰可被索敌的窗口 = 2 帧**：在**部署后第 31 帧手动开技能**的条件下，可被花索敌的帧是**部署后第 32、33 帧**；据此（三帧索敌）**花的索敌帧必须是第 31 和第 34 帧**才能躲掉。｜§被索敌帧
- **不手动开技能是无解的**（视频里 up 主三次都正确手动开了）。｜§被索敌帧
- **落地隐（不可被索敌窗口）的两个长度**：不触发天赋 ⇒ **落地后 31 帧开技能**，**32/33 帧**可被索敌；触发天赋 ⇒ **落地后 52 帧开技能**，**53/54 帧**可被索敌；**差值 21 帧 = 3 的整倍数** ⇒ **无论是否触发天赋，都应在同一时间部署**，只是要改"开技能帧"。｜§澄清第二
- **"落地隐变长是对的，但用它解释是错的"**：评论区的"梓兰触发天赋会延长落地隐"结论本身对，但**与"应该哪帧部署"无关**。｜§澄清第二
- **正确操作（该图、无箱）**：30 怪 **1 帧部署 / 32 帧开**；32 怪 **0 帧部署 / 31 帧开**；33 怪 **2 帧部署 / 33 帧开**。｜§小结论 ·（原文加粗）
- **33 怪 + 1 宝箱**：应 **0 帧部署 / 31 帧开**（宝箱 +1）。｜§教学案例
- **视频中 up 主的选择全错**：30 怪 2 帧部署、32 怪 1 帧部署、33 怪 0 帧部署 ⇒ 全死；而"第二次部署（再部署）没被吃"**只是运气**。｜§小结论 / §再部署不被吃单纯运气
- **实测/计算状态如实标注**：30 怪无箱（1 部署 32 开）与 33 怪 +1 宝箱为**实测成功**；**32 怪与紧急的情况是纯计算、未实测**（作者称概率低、难凹，欢迎带视频反馈）。｜§教学案例
