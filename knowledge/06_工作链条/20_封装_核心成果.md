## 一、方法论级（改变工作方式）

### K1 共用轴表（`ak/axis/<stage>.yaml`）
- **内容**：`squad`（编队与练度）+ `deploys`（操作，含 `cost`=单位费用 / `cost_anchor`=显示费用）
  + `expect`（校验期望事件）+ `video_axis`（视频锚点）；**帧号一律游戏帧**
- **价值**：模拟器复刻、打图端执行、校验器对齐**读同一份文件** ⇒ 三方天然对齐、改动一处即全链生效
- **证据**：结论索引 A、B29、B30；`sim/draft/test_axis_io.py` ✅

### K2 费用尺逻辑帧时钟
- **内容**：`totalElapsedFrames`（费用条循环累计帧）作为绝对逻辑帧基准；180px ↔ 30 帧 ⇒ 6px=1 帧
- **价值**：**免疫"费用满/净消耗"**，解决 PRTS+ 依赖费用单调的固有缺陷
- **证据**：B1/B2/B4/B17；`plugins/clock/cost_ruler.py`、`cost_bar.py`

### K3 五语义分离（①碰撞 ②受击 ③范围 ④阻挡 ⑤AoE）
- **内容**：每个语义有独立载体与独立用途，**禁止混用**（硬约束写死在代码里）
- **价值**：**消除了一整类"用一个错误补偿另一个错误"**（本项目多次发生的失败模式）
- **证据**：B23~B26；`verify_semantics.py` A1~A9 ✅

### K4 统一阻挡模型（半径 0.7071 + 每 3 帧扫描 + 代码化阻挡偏移）
- **内容**：`Consts.BLOCK_RADIUS = 0.7071`（角色侧，敌人无）；`FIND_BLOCKEE_TICK = 3`；
  `CalculateBlockOffset` 四步 + 0.2s tween + 稳定阻挡位置；**扫描相位随该角色的创建帧**
- **价值**：**单调、可解释、与外部知识（B站专栏 + 反汇编）一致**；取代此前自造的格判定近似
- **证据**：轮 108/109/110/112；`knowledge/04/37`、`60` 的 L2-03/L2-04

### K5 索敌口径 = 攻击范围区域的**外接圆**（半径由范围表导出）
- **内容**：`R = max(由干员中心到任一范围格最远角的距离)`；2 格范围 ⇒ **1.5811**
- **价值**：1-1 两条链（正面逼近 / 斜向逼近）**首次同时成立**；伤害平均 **4.50→2.06**、最大 **25→7**；
  半径**零拟合参数**、对任意干员可自动计算
- **证据**：轮 115/116；`knowledge/04/61`；`cmp_target_models.py`、`sweep_tol_circum.py`
- **⚠️ 状态**：与用户此前明确指定的"方格范围 ∪ 受击圆∩范围格"语义**冲突** ⇒ **待裁决**；
  实现为可选模型 `targeting_model='range_circumradius'`，**默认未改**

### K10 严格事件配对口径 `(类别, 受害者, 攻击者, 序号)`
- **内容**：事件对齐必须带**组内序号**，避免把"同组第 n 次"误配到别处
- **价值**：松口径会把准确率从 **6.89 虚高到 14.94 帧** ⇒ 口径本身即精度前提
- **证据**：C4；`replay_verify5.py`

## 二、工程级（可复用工具）

### K6 两段式部署
- **内容**：拖卡片→目标格**松手**（进入朝向选择）→ 从格拖向朝向点**松手**（提交）
- **价值**：**实机部署的唯一可行通道**（此前 4 类注入通道在该环节全部失败）
- **证据**：轮 84；`action/deploy.py::deploy_two_step_px`

### K7 格点真源 `grid_px.py`
- **内容**：`x = 559 + 124.5·col`、`y = 502 + 138·(row−3)`；列**左→右从 1**、行**下→上从 A**
- **价值**：**唯一真源**（模拟器/打图/校验共用）；`self_check()` **14/14**；三重互证
- **证据**：轮 85/89；`sim/draft/test_axis_io.py`

### K8 干员识别 = **名称 OCR** + **头像判别扫描**
- **内容**：点卡读**详情面板名称**（ROI `(20,250,150,330)`、`--psm 6`、与候选名单包含匹配）；
  头像用**逐位置扫描 + 判别性分数**（`NCC(本人) − max NCC(他人)`）
- **价值**：**不依赖费用**（练度影响费用、同费用不唯一、局内可变）；编队页 11/11
- **证据**：轮 98/101/103；`recognize/operator_name.py`、`operator_card.py::locate_operator_card`

### K9 客户端 AB 实测数据通道（UnityPy + LZ4AK）
- **内容**：`CompressionHelper.DECOMPRESSION_MAP[LZHAM] = ak_lz4ak.decompress_lz4ak` 后即可直读 AB；
  已导出 **2123 个敌人**的逐敌碰撞体
- **价值**：**把"拟合值"换成"实测数据"**（例：猎狗半径实测 0.1，推翻了 0.8 的拟合值）；
  并**更正了知识库旧口径**（旧分布把非敌人对象一并计入）
- **证据**：轮 107/117/118；`scripts/export_all_enemy_radii.py`、`data/derived/enemy_colliders.json`

### K11 打图端"同帧多操作"冻结模式
- **内容**：同一目标帧的连续操作归为一组 ⇒ 冻结 → 步进对齐相位 → 连续下发 → 恢复
- **价值**：把"操作前先步进/暂停定位帧"落成可审计的机制
- **证据**：B31；`plugins/clock/frame_lock.py`、`task/axis_runner.py`

## 三、纠错型成果（推翻既有认知）

| # | 曾经的认识 | 更正后 | 触发方式 |
|---|---|---|---|
| R1 | 敌人受击半径"一律 0.1"只是近似，个别可达 0.8+ | **实测 97.5% 就是 0.1**；0.8 是**拟合值**，已撤销 | 用户质疑 + 客户端 AB 实测 |
| R2 | 阻挡是"进入阻挡者格/邻域"（自造格判定） | **统一半径 0.7071 的中心距判定 + 每 3 帧扫描** | 用户："阻挡按玩家常识应当全部统一" |
| R3 | 我读取的格子里 A 行在最上 | **列左→右从 1、行下→上从 A** | 用户更正 |
| R4 | 格点 `x` 随 col 递减（镜像） | **`x = 559 + 124.5·col`（随 col 递增）** | 用户观察实机落在 D4 而非 D6 |
| R5 | ★3 干员可练到精英2/LV90 | **上限 = 精英1/LV55** | 用户："应从游戏数据读常识" |
| R6 | 卡片选人需图像识别 | **费用升序可作起点，但判据须用名称 OCR/头像**（费用不足以识别） | 用户指出练度/同费用/局内变动 |
| R7 | 阻挡判据 `margin 1.0`（伤害最优） | 该"最优"是**用提前吸附补偿了"受击体积"的错误** | 双观测（阻挡帧 + 伤害帧）联合判据 |
| R8 | 敌人 #2 到达偏晚 ⇒ 路径问题 | **路径假说被证伪**；问题在**索敌口径** | 两观测联合证伪 |
| R9 | 扫描是全局 `frame % 3` | **每角色 ticker，相位随其创建（部署）帧** | 用户提醒 + 字段速查表 |
| R10 | 知识库旧记录"敌人半径分布 0.1/0.5/1.0/1.5…" | **口径有误**（含非敌人对象）；逐敌实测为 0.1(2070)/0.25(6)/0.3(18)/… | 本轮批量导出 |
