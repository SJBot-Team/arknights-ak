## 五、持续更新机制（**结构不会烂掉的保证**）

### 5.1 何时必须下沉（触发条件）

| 触发 | 动作 |
|---|---|
| 单篇核心文本 **> 300 行** | 把最长的明细章节拆为子文件 `NNx_*.md`，正文只留**结论摘要（≤10 行）+ 子文件地址** |
| 单篇 **> 600 行** | 强制拆分为**多篇同级文档**（如 `38`/`39` 这样的并列结构） |
| 某表格 **> 80 行** | 表格整体移入子文件 |
| 某章节只服务**单一专题**且内容 > 50 行 | 升为同级文档并在本页/`04/00_目录.md` 登记 |
| **查表型 / 流程表格型文件**（全篇为表格/schema、无叙事） | **例外：放宽到 400 行**，但头部必须标「**查表文件 / 流程表格型**」并说明"按什么列、按什么链查"。理由：一次读完 300~400 行表格是可行且必要的，强行切开会把"一次查完"变成"翻三个文件"。当前适用：`04/65 机制参数总表`、**`04/67 索敌完整流程`（319 行，2026-09-28 裁定不拆）** |

### 5.2 下沉后必须做的事（回填三件套）

1. 原位置保留：**一句结论 + `→ 详见 <子文件路径>`**；
2. 在**本页 §一 或对应目录的索引**里登记子文件；
3. 子文件头部写明**"本文件是 <母文件> 的子文件，母文件：<路径>"**（保证双向可导航）。

### 5.3 新增知识时的固定动作

1. 先查**本页 §一** 与 `04/00_目录.md`，确认是否已有结论（**避免重复劳动**）；
2. 写入对应领域，头部按 `meta/流程规范.md` 标注 **来源 / 置信度 / 任务号 / 日期**；
