## 1. 网络访问（GitHub / B站 / PRTS）★2026-09-13 更新

### GitHub：Steam++（Watt Toolkit）hosts 加速 —— ✅ 已在本机验证可用
- 本机已安装并运行 **Steam++**（进程 `Steam++.exe` + `Steam++.Accelerator.exe`，加速服务监听 **80/443**）。
- 它通过改写 hosts（`C:\Windows\System32\drivers\etc\hosts`，github.com / api.github.com / raw.githubusercontent.com 等 → `127.0.0.1`）+ 本地反代实现加速。
- **关键坑**：走本地反代后，Windows schannel 做**证书吊销检查失败**（`CRYPT_E_NO_REVOCATION_CHECK 0x80092012`），导致：
  - `curl https://github.com` → code 000；加 `--ssl-no-revoke`（或 `-k`）→ **200** ✅
  - `git clone` → 需 `git -c http.sslVerify=false clone ...`（或全局 `git config --global http.schannelCheckRevoke false`）
- 结论（本机 GitHub 访问标准写法）：
  ```powershell
  curl.exe -s --ssl-no-revoke --max-time 25 "https://api.github.com/repos/<owner>/<repo>"
  git -c http.sslVerify=false clone --depth 1 https://github.com/<owner>/<repo> <dst>
  ```
- 若 Steam++ 未运行时：hosts 仍指向 127.0.0.1 会导致**所有 GitHub 访问失败**；需启动 Steam++ 或清理 hosts。

#### ★ 直播录播抓取三条关键经验（2026-09-23，T-061 实测）
1. **多分P 是最大的坑（曾导致 5 场录播少抓约 19 小时）**：`x/web-interface/view` 返回的 `cid` **只是 P1**。
   直播录播（尤其 3~9 小时场）几乎都是多分P，每 P 上限约 **7200 s**。若直接用 `data.cid` 取 playurl，
   **只会拿到前 2 小时的音频**，表现为"转写只覆盖开头、后面没内容"，极易被误判成"音频缺失/静音"。
   **正确做法**：遍历 `data.pages[].cid`，逐 P 取 playurl 下载，转写时把各 P 时间戳按累计时长
   **归一到整条 BV 的全局时间轴**（并把分P边界写进文件头注释）。
   **现成脚本**：`ak/code/tools/bili_parts_transcribe.py`（逐分P下载 + faster-whisper 增量转写 + 音频用完自删，`KEEP_AUDIO=1` 保留）。
2. **`x/space/wbi/arc/search` 分页会随机 -412**：同一会话里 pn=1 被 ban、pn=2 正常是常态。
   对策：**每页独立重试（15/30/45s 退避）**，不要因为一页失败就放弃整个 UP。
   兜底最稳的是 `x/web-interface/search/type?search_type=video&keyword=...`，再**按 `mid` 字段过滤**目标 UP；
   注意 video 搜索结果项同时含 `author` 与 `uname` 两个同义字段，按 `mid` 判归属才不会写错分支。
3. **UP 名不等于上传者**：本库关注的机制教学录播由第三方账号（Lapis___，mid 592610）上传，
   而 UP 本人（神祇读神奇 mid 374873950）主页只有测评/攻略。**找录播要先定位上传者 mid**，
   可用 `search_type=bili_user` 搜 UP 名拿到候选 mid，再逐个查其投稿列表。

## 4. 踩坑记录（按任务追加）

- **whisper 转写（2026-09-02）**：①HuggingFace 连不上 → 用 hf-mirror；②hf-mirror 分片 401 → 手动 curl 下载 model.bin 等 4 文件；③`cublas64_12.dll is not found` → 把 `课设\comp_physics\.venv\Lib\site-packages\torch\lib` 加入进程 PATH；④脚本需把已下载音频 glob 后再跑，否则新下载的漏转。
- **B 站爬取（2026-09-01~02）**：连续请求触发 -352（风控）/-412（封禁）；对策：curl_cffi 指纹 + 请求间隔 ≥4s + 失败退避重试 + 分日补抓。
- **QQ 压缩包解压（2026-09-13）**：QQ 接收文件在 `E:\QQ\`（非 Tencent Files）；zip 内可能含中文路径，用 `Expand-Archive -LiteralPath`。
- **★ 同一 RVA 可能有多个方法（"同构方法折叠"，2026-09-28 实测）**：IL 体逐字节相同的方法/lambda 会被合并到**同一地址**。
  实例：`Scheduler.<_DealFragment>b__108_0`、`Scheduler.<_DealBranchPhase>b__109_0` 与**无关类** `IRoguelikeGameShopVisibility.<_GenerateDalayTweens>b__23_0` **共用 `0x62F8C0`**。
  ⇒ ①`read_cpp.py who` 现已改为**列出全部同名地址的方法**（旧版只留一个、恰好给了无关类，害我一度误判 T-076 的核验结论是错的）；
  ②**引用 RVA 时必须同时写"类.方法"**，否则读者无法判断说的是哪一个；③遇到"高 RVA 标签看起来驴唇不对马嘴"时，先怀疑本坑，而不是怀疑数据。
- **PRTS 抓取（2026-09-28，T-075）**：无浏览器头 **403** ⇒ 必须带 `User-Agent` + `Accept`；用 `action=raw` 取 wikitext（避免把渲染 HTML 读进上下文）。`curl_cffi` 在本机可能因证书报 `(77) error adding trust anchors` ⇒ 回退 `urllib.request` 即可（`glossary_import_prts_events.py` 已内置回退）。
