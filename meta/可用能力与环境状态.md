## 一、⚠️ 跨端会话共享（最重要的操作约束）

**2026-09-14 起，Web 端与桌面端已启用「全量共用」**：桌面端的数据目录 `%APPDATA%\dsh-desktop\harness` 已改为**目录联接**，指向 `C:\Users\23922\.dsh`（即 Web 端的 `DSH_HOME`）。

| 项 | 内容 |
|---|---|
| 效果 | 会话、工作区、插件、技能、设置、凭证**全部互通**（32 会话 / 5 工作区） |
| **铁律** | **同一时间只开一端**。两端同写一份存储会互相覆盖甚至损坏会话 |
| 启动器 | `management\跨端启动\`：`启动桌面端.ps1`、`启动网页端.ps1`、`跨端状态.ps1`（检测到另一端在跑会**拦下**；`-Force` 可强开但不推荐） |
| 体检 | `python management\session_bridge.py shared`（联接状态 / 会话数 / 异常） |
| 备份 | 桌面端原数据：`E:\__file\_dsh_sharing\backup-20260914-111522\harness`（195MB） |
| 回滚 | 删除联接 → 把备份移回 `%APPDATA%\dsh-desktop\harness` |

**对 AK 会话的实际影响**：
1. 本会话（Web 端）与桌面端看到的是**同一份数据**——在任一端继续 AK 知识库工作都可以。
2. **切换端之前必须关闭当前端**（关掉 `dsh web` 所在终端窗口即停止服务），否则违反铁律。
3. 插件/设置/凭证也已共享：换 API Key 或装插件会同时影响两端；**装完新插件需重启当前端**才生效。
4. 会话桥 `session_bridge.py`（`list/share/sync/…`）在全量共用下**不再需要**，仅作应急（例如临时改回独立存储时搬运会话）。

## 二、★ 新增能力：`ak\code\vision\` 可插拔视觉控制内核（T-038）

**这是我们 ak 目录下的自建工具**，内核 + 插件分离，设计范式参考 MAA 与 prts+。

### 2.1 能做什么

| 场景 | 入口 | 说明 |
|---|---|---|
| ① **识别并操控本地游戏客户端**（纯 GUI，不读内存） | `apps\run_client.py --window "明日方舟" --pipeline …` | 锁定窗口 → 只抓客户区 → 流水线识别 → SendInput/DirectInput 操作。安全默认：`--dry-run` 只识别不动鼠标 |
| ② **从攻略视频提取操作步骤** | `apps\analyze_video.py --video <mp4> --pipeline …` | 把视频当帧源（只换采集插件）→ 逐帧识别 → 输出**时间线 JSON**（帧号/时间/标签/分数/位置/动作） |
| 自检 / 性能基准 | `apps\selftest.py` / `apps\bench_fps.py` | 无需窗口与游戏即可跑 |

### 2.2 ★ 性能实测与关键结论（本机 7945HX + RTX 4060，1080p，64×64 模板）

| 场景 | 单次 | 折算 |
|---|---|---|
| 全帧 1920×1080 模板匹配 | **124 ms** | 8 次/秒 ❌ |
| 全帧 + OpenCL | 48 ms | 21 次/秒 |
| 降采样 0.25× | 8.3 ms | 120 次/秒 |
| **ROI 140×140** | **0.87 ms** | **1150 次/秒 ✅** |
| 抓屏（bettercam/DXGI） | 0.4 ms | ~6788 FPS |
| 端到端 | — | **60.0 FPS 稳定** |

> **结论：60 FPS 的关键不是算法而是搜索范围。**
> ① 每个流水线节点**只在自己小 ROI 内匹配**（与 MAA 做法一致）→ 单帧可跑几十个识别点；
> ② 需要全屏找目标时：**先降采样粗定位，再在候选区原分辨率精匹配**。

### 2.3 扩展方式（唯一入口）

| 类型 | 装饰器 | 必须实现 |
|---|---|---|
| 采集 | `@capture("name")` | `open()` / `grab(region)->Frame` / `close()` |
| 识别 | `@recognizer("name")` | `run(image, spec, ctx, origin)->list[Match]` |
| 动作 | `@action("input:name")` | `click/move/drag/scroll/key/text` |
| 任务 | `@task("name")` | `run(engine)->dict` |

新增能力 = 在 `plugins\` 下加一个模块并注册；`engine.open()` 自动发现并加载（**单个插件报错不影响内核**）。

### 2.4 模板资源可复用 MAA

`D:\__soft\MAA\resource\template\` 有 **2149 张模板**，可直接按需挑选拷入 `templates\`（**不要整目录拷贝**）。
模板名 = 相对路径去扩展名（`templates\main\start.png` → `main/start`），运行中**热加载**。

### 2.5 环境

`ak\code\vision\.venv`（Python 3.13.5）：numpy 2.5.3、**opencv-python 4.14**（5.0 实测慢 2 倍已回退）、bettercam 1.0.0、dxcam 0.3.0、mss 10.2、pydirectinput 1.0.4、pywin32 312、pyyaml、comtypes。

### 三之补、MAA / prts+ 的驱动要点（T-063，2026-09-23）

| 项 | 结论 |
|---|---|
| 驱动方式 | **`MaaCore.dll` 无 CLI**（`MAA.exe` 是 GUI 单实例）⇒ 用 Python `ctypes` 直调导出函数 |
| 装配顺序 | `AsstSetUserDir → AsstLoadResource(**MAA 根目录**) → AsstCreateEx`；顺序错返回空句柄 |
| 原生单步 | **`SingleStep`** 任务（`subtype` = `stage`/`start`/`action`），粒度 = 一个战斗操作；⚠️ `details` 必须是 `{"actions":[<单个 action>]}` |
| 结果读回 | ①`AsstCreateEx` 回调 JSON ②`debug/asst.log`（与回调逐字相同）③`AsstGetImage` |
| prts+ | **不可步进**（跑到轴表结束）；但它**读写的 xlsm 就是控制面**——外部写 `中转站!B1='停止中'` 即可暂停 |
| ⚠️ 版本 | 2026-09-23 为查 CLI 执行过 `MAA.exe --help`，**触发 MAA 自带更新器**，`MaaCore.dll` 就地升到 **v6.17.5**（导出表 33 项与旧版一致）。**教训：不要用命令行参数探测 `MAA.exe`**；要版本就读 `AsstGetVersion()` |

## 四、对 AK 工作的直接意义

1. **批量视频分析**：B 站机制教学视频（`_raw\bilibili\`）目前靠 whisper 转写文字；有了 vision 内核，可以**按帧提取画面证据**（如"部署时序""出怪坐标"），与代码结论互证。
2. **视频→操作步骤→模拟器测试用例**：场景② 输出的时间线 JSON 可作为模拟器回归测试的输入。
3. **纯 GUI 复现**：需要验证"某操作在真实客户端下的表现"时，可用场景① 且**不读内存**（合规更稳）。
4. **模板资产复用**：MAA 的 2149 张模板能直接用于阶段/界面识别，省去自建。
