# 流程规范（来源标注 / 核验 / 去冗余）

> 规则（用户 2026-09-01 定，2026-09-02 结构重构后修订）。本文件是知识库流程的唯一权威；管理侧同步于 `management/AI_GUIDE.md`。

## 1. 来源标注

外部获取内容（PRTS / B 站 / 本地文件等）与既有知识**简单比对无明显错误** → 注明出处并加入 knowledge。

- **标注粒度**：按"知识块"标注（一个机制/一张表/一篇笔记的头部），非逐条小项。同类知识用同一流程代码核验过的，只在该类知识的**上层目录**（如 `knowledge/01_基础数据/README` 或知识块头部）注明一次即可，小条目不必重复。
- **出处格式**（每个来源均标注，多来源全标）：
  ```
  > 来源：PRTS·游戏数据基础（2026-08-31 抓取）；B站专栏 cv41544634（神祇读神奇）；舟数据《干员输出表.xlsx》
  > 核验：✅ 解包验证（data/gamedata_akgd/character_table.json，字段 maxHp/atk）
  >       🟡 待核验（K-###）
  >       🔴 需 IDA（代码层，见 meta/解包经验.md）
  > 核验代码：code/tools/extract_operator_data.py
  ```

## 2. 核验状态三档

| 状态 | 含义 | 依据 |
|---|---|---|
| ✅ 解包验证 | 已在 gamedata/客户端资源找到对应数据且比对一致 | 记录对照的数据文件与字段 |
| 🟡 待解包核验 | 有专栏/实测结论，尚未在游戏数据定位 | 登记到 `knowledge/04/23` 的 K-### |
| 🔴 需 IDA | 机制实现在程序逻辑（阻挡/偏移/对象池/计时器等），数据与组件层无法核验 | 需反编译/反汇编（合规，在备份上解读） |

## 3. 数据来源与优先级

- 本地备份/解包验证过的数据（`data/gamedata_client/`、`raw/client_res/`）**优先**于 ArknightsGameData（`data/gamedata_akgd/`）——能本地获取的不再依赖远程。
- 各数据目录带 manifest（来源/日期/版本/校验和），不混放。

## 4. 知识用途定位

- 关注**关卡中发生的战斗**；基建仅了解、不深入、不作为模拟重点。
- 战斗知识按 PRTS 领域组织于 knowledge/；B站社区深挖在 03_外部学习，待深化整合入 01/02。

## 5. 去冗余（用户 2026-09-01 定）

- 下载的互联网学习资料**仅保留文本**（B站专栏/转写等）；经代码核验的仅保留 knowledge 内总结整理的文本知识，**多余文件清除**（走 trash 流程：登记 trash_registry → 用户确认 → 移入 E:\_TrashArchive 30 天）。
- 表格/公式类内容应转结构化数据（data/）或 Markdown 文本，不保留原始二进制冗余。

## 6. 知识库使用规则

- 会话执行任务优先访问 `E:\__file\ak_kb\` 仓库（kb=knowledge 镜像、gamedata、client_res、downloads）。
- 新获取 ArknightsGameData 数据 → 存入 E 盘仓库 `gamedata\` 并同步 `data/`。
- 客户端资源 → 只读使用备份；**仅允许更改备份文件**，原客户端永不改动。

## 7. 知识信度分层与写权限（用户 2026-09-02 定）

知识按信度分三层，**写入权限隔离**，防止未检验内容污染权威知识或影响知识权重：

| 层 | 含义 | 位置 | 写权限 |
|---|---|---|---|
| **T1** | 代码/解包验证（✅） | `knowledge/`（各主题） | **仅主会话（AK 知识库会话）与解包程序** |
| **T2** | 高信度社区结论（🟡，多源互证/逆工程/实测复现） | `knowledge/03_外部学习/`（暂存）→ 核验后并入主题区升 ✅ | **仅主会话整理后写入；执行者只读** |
| **T3** | 组合/应用推导（❌ 正确性不保证，保留来源链+假设） | `composed/`（平行区，见 composed/README） | **所有任务执行者**（记录/修改，登记台账） |

- **knowledge/ = 唯一权威源**：执行 agent 不得直接改写（防止长期积累未检验内容）；发现知识问题 → 记录到 composed/ 或任务台账，由主会话/解包程序审议修订。
- **composed/ = 组合知识区**：agent 把"从基础知识组合出的方案/推导"写这里，头部必须含引用条目 + 推导链 + 假设 + 验证状态（格式见 composed/README）。
- **03_外部学习语义**：T2 社区来源知识暂存区（等灯等灯/神祇读神奇/调零等）；已互证的逐步并入 01/02 主题并升 ✅，避免长期按"来源"堆积。
- **升级流转**：T3 经模拟验证（sim/reference）或实战复核 → 主会话审议 → 升 T2 并入 knowledge（标注原 composed 来源）；长期未验证/被推翻 → 标废弃保留追溯。
- **AI skill 权威速查**：仅从 T1/T2 生成；composed/ 内容可作参考但不入权威速查表，引用时标 "T3 假设"。

### 8.2 ★方法论性错误（**最值得反思，开工前必读**）

| # | 错误 | 表现 | 对策 |
|---|---|---|---|
| **M1** | **用拟合值替代机制**（最严重） | 猎狗受击半径设 0.8，只因"让两个观测看起来同时满足"；**被用户质疑"与常识不符"** | **任何参数都必须能回答"它从哪来"**；引用反推值必须标 `⚠️拟合` 并主动求证 |
| **M2** | **用一个错误补偿另一个错误**（历史上 3 次） | margin 补偿受击体积；每帧扫描补偿判窗；半径 0.8 补偿索敌口径 | **双观测联合判据**（如"阻挡帧 + 伤害帧"）——单观测几乎总能被某个错参数对上 |
| **M3** | **未先读自家知识库** | 阻挡模型绕很久，而 `04/37` 早已写明权威规则 | **动手前先普查**（`00_Agent入口 §〇` 三条主线 + `04/00 §开工三问`） |
| **M4** | **过度相信单一识别路线** | 卡片识别在"头像模板匹配"上连试 5 种度量 | 先做**目视/最小对照**定位真因，再决定投入；**先查有没有现成工程**（MAA/prts+） |
| **M5** | **口径不严导致"看起来对"** | 松口径把准确率从 6.89 虚高到 **14.94 帧** | 严格口径 `(类别, 受害者, 攻击者, 序号)` |
| **M6** | **宣布结论过快** | 未做"开关对比/最小复现"就下结论 | 结论只写"已验证"的部分；新开关先冒烟 |

### 8.3 流程性反思

| 方面 | 观察 | 改进 |
|---|---|---|
| **用户指正的价值** | 某轮 ≥10 项认知纠正**全部**由用户质疑或数据实测触发 | 主动请用户审视"反直觉参数" |
| **数据源优先** | 打通客户端 AB 实测通道后，一轮推翻两个长期假设 | **能实测就不反推** |
| **双观测判据** | 连续证伪 4 个候选假说，最终定位到单一机制 | 默认使用多观测联合 |
| **知识库维护** | 旧记录会**污染后续判断** | 新数据出现时**主动回溯更正**旧文档并标日期 |
| **单线深挖** | 暂停打图线后，模拟线两轮内解决 3 个长期 OPEN 项 | 多线卡住时**收敛到单线** |
