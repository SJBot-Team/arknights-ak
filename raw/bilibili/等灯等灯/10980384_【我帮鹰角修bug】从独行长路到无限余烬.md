# bug表现的研究

在上文提到的贴子中贴子中，可以看到楼下的测试出现了2种不同的结果
绝大多数人会正常触发这个bug，巫恋娃娃到时间自动撤退时，独行长路无法重新生效
然而，部分人无论怎么测试都无法触发这个bug，独行长路会在巫恋娃娃到时间自动撤退时重新生效

这个结果的不同困扰了我很长时间，直到hxiaiya告诉我苏苏洛在编队时这个bug会直接失效
苏苏洛的天赋微创治疗属于deckbuff，即使苏苏洛在场下，也会对场上的单位生效，而且微创治疗的buff是可以添加给娃娃的

之前贴子中无法触发bug的，队伍里也确实带了银灰

# 相关机制的研究

首先，这个bug和独行长路相关，那么需要知道独行长路的机制是什么
独行长路使用的触发控制器是AdjacentAllyToggleChecker，使用同样机制的还有清道夫的天赋单独行动者
单独行动者和独行长路除了数值加成外没有任何区别，在bug表现上也完全相同
这种触发控制器，会在场上有单位出生/结束时进行判定，根据设定开启/关闭buff

非常简单有效的机制，单看完全看不出任何存在bug的可能性
我随后检查了单位出生/触发的事件判定，也没有发现任何可能导致漏判目标/无法触发事件的漏洞

那么问题很可能不在独行长路上
思考一下这个bug的其它奇怪之处，为什么只有巫恋娃娃在自然撤回时才可以触发？巫恋娃娃的设定和自然撤退方式是否和其它召唤物/其它撤退方式存在不同？
然而很遗憾，我查看了巫恋娃娃的设定，并没有发现娃娃/自然撤退的设定和其它召唤物/撤退方式存在显著的不同

接下来是第三个问题，为什么触发了bug后，在独行长路范围内再放人，可能会出现这么多奇怪的现象？
查看这些现象的共性，可以发现，导致这些现象的，都是buff的消失
眩晕是buff，无敌是buff，隐身是buff，加攻是buff，持续加速也是buff
而且丢失的buff数量正好为1，等于独行长路记录buff数
**那么有没有可能，这些buff，是因为某种原因，被记录到了独行长路中，然后因为独行长路范围内放了人，触发器失效，导致这些buff被独行长路清除呢？**

# bug原理的研究

因为实在无法准确定位问题就推演了整个撤回流程，结果推了几遍还真的发现了问题

在说明问题前，需要解释一些概念
**为了节约内存资源，战斗中所有buff的object是循环利用的**
打个比方，buff的object类似一个盘子，里面装着各种菜，也就是buff的设定
为了节约盘子数量，每个人吃完了菜，不会把盘子直接扔掉，而是洗一下，放回去，再装别的菜
buff也是类似的，**当buff失效后，会将buff的object的指针移到一个通用的栈中**，这个过程程序中命名为recycle
**如果谁想创建新的buff，就从这个栈里，取一个buff的object拿来用**，这个过程被称为程序中命名为allocate
至于栈是什么，可以理解为盘子叠高高。因为盘子都叠在一起，因此每次拿盘子只能从最上面拿，放盘子也只能从最上面放

那么回到bug的解释上
巫恋娃娃的自然撤退，是在撤回buff到达最长时间结束时执行的
这一块的代码如图

[图]

在执行RunActions函数的过程中，会触发撤回自身的action {
而撤回自身的过程中，会清除自身所有的buff，随后将buff的object全部放进通用栈中
buff清除完了之后，会触发单位结束事件，独行长路触发，创建一个buff
但是注意，因为**娃娃身上只有一个buff，也就是撤回buff，在之前清除的时候被最后放入了通用栈
所以这个时候，独行长路buff取用的object，就是撤回buff的object**
注意，**这个时候我们还在RunActions函数里面，因此撤回执行完成后，会从RunActions函数退出，继续执行下面的操作**
}
而接下来的操作，可以看代码，获取了buff的持有者，随后从buff持有者身上移除了这个buff附加的属性效果
不过，在这里，因为**这个buff的object，在之前的撤回过程中已经被分配给了刻俄柏的独行长路**
**因此移除的，是刻俄柏身上，独行长路的属性效果**

如果仅仅是这样还好，只少了独行长路的属性
不过，因为buff已经完成了结束过程，所以**接下来它会被再次回收至通用栈中**，虽然它实际上根本没有结束
**而接下来创建的buff，会从通用栈中获取独行长路buff的object作为自身的object**
注意在这时，独行长路的记录里，还记录着自身buff的uid，并且记录为当前生效中
因此，再次在独行长路范围内放置我方单位时，独行长路会从生效切换至失效状态
这时，它通过记录的uid从自身buffContainer的m_buffUidMap中获取buff object的指针
随后通过指针直接将这个buff结束
**因此，接下来创建的这个，使用独行长路buff object的buff，控制权捏在独行长路手里，可以被独行长路的失效直接结束**

那么还有一些问题，为什么只有巫恋娃娃可以触发这个bug？为什么银灰天赋可以使这个bug失效？
回到之前说的，这个**bug只有可能在结束时触发撤回的buff中生效**
除此之外还有两个条件：**撤回buff必须由Tick函数结束，撤回buff结束时必须为娃娃身上唯一的buff**

从以上逻辑中可知：

如果撤回buff在结束时不是娃娃唯一的buff，那么随后buff列表不会为空，自然无法触发立刻回收buff的逻辑

如果撤回buff没有由Tick函数在遍历中结束，立刻回收buff那一步由于没有事先的缓存，获取的会是空列表，无法获取到撤回buff，也自然无法立刻回收
巫恋的娃娃只包含一个buff，在撤回buff结束时自然是娃娃身上唯一一个buff
除了巫恋之外，W地雷的120s自动消失也可以触发这个bug
地雷虽然包含两个buff，但第二个buff同样为有限时长，在到达最大持续时间时会因为倒序遍历的原因优先于撤回buff被结束
而无论对于哪个，银灰的deckBuff都会使撤回buff在结束时不是召唤物身上唯一的buff

因此，**无论是巫恋娃娃还是W地雷，只要队伍中存在银灰/苏苏洛，由于他们天赋提供的buff，在撤回buff结束时，撤回buff就不再是召唤物身上唯一的buff，自然无法触发bug**

以上就是对这个bug的完整解释

只要知道了场上buff的施加/结束顺序，可以利用这个bug，随意地删除场上任意一个buff
