## 1. 属性体系

### 1.1 属性状态层次
- **原始属性**：数据文件直接定义的基本值；信赖、潜能、模组提供的数值通常先计入（记为「原始属性+」）。
- **基础属性**：原始属性经过**符文运算**、取上下限后获得。部分机制以此数据为判断标准。
- **（实际）属性**：基础属性经**属性计算器**（属性基本公式）完整处理后获得；最终呈现给玩家、绝大多数机制以此为判断标准。
- **属性上限/下限**：由属性类型定义，个体上下限可被机制更改。

### 1.2 属性修饰器（AttributeModifier）四类
| 修饰器 | 内部名 | 参与位置 |
|---|---|---|
| 直接加算 | `ADDTION` | 对基础值直接加 |
| 直接乘算 | `MULTIPLIER` | 对「直接加算」结果乘 |
| 最终加算 | `FINAL_ADDITION` | 对「直接加算+直接乘算」结果加（游戏内描述为「获得额外附加的基础属性加成」，即鼓舞） |
| 最终乘算 | `FINAL_SCALER` | 对前三者结果整体乘 |

### 1.3 符文运算（rune，入场前修改，用于突袭/合约/活动机制）
- 基础值取**原始属性** α。加算优先于乘算：
  - 符文加算结果 \(R_p = p_1+p_2+\cdots+p_n\)
  - 符文乘算结果 \(R_t = t_1 t_2 \cdots t_n\)
  - **基础值** \(A = R_t(\alpha + R_p)\)
- **藏品符文**（集成战略收藏品）：加算 \(C_p\)、乘算 \(C_t\)（乘算是**倍率叠加**而非叠乘）；先按关卡符文得 \(A\)，再 \(A_+ = C_t(A + C_p)\)，以 \(A_+\) 为基础值继续。
- 注意：符文 ≠ 符文运算；非符文运算的符文修改（Buff 方式）走常规属性基本公式。

### 1.4 属性基本公式（核心）
设：直接加算结果 \(D_p=\sum p_i\)，直接乘算结果 \(D_t=\sum t_i\)（**相加**），最终加算结果 \(F_p=\sum p_i\)，最终乘算结果 \(F_t=\prod t_i\)（**相乘**；任一项 <0 时该项补正为 原值+1）。

**最终属性**：
\[
A_f = F_t\big[(A + D_p)(1 + D_t) + F_p\big]
\]
其中若 \(1+D_t < 0\)，则 \((1+D_t)\) 补正为 0。之后经**数值范围**上下限截断得到最终结果。

### 1.5 从源实体获得基本属性（fetchBaseValueFromSourceValue）
- 仅辅助「吟游者」（空、浊心斯卡蒂等）使用：其鼓舞修饰器被**重写**——最终乘算重写为最终加算（数值处理：修饰器值 <0 时 +1），其余按原方式。

## 2. 倍率（不是属性！）
- 倍率是修饰值，用于修改属性最基础的出力结果，**不影响属性值**。
- 同种倍率叠乘：最终倍率 \(M = m_1 m_2 \cdots m_n\)。
- 三类：**攻击力倍率**（「攻击力提高至 380%」）、**伤害倍率**（「受到的法术伤害 +55%」→ 155%，只对对应伤害类型生效）、**治疗倍率**。

## 3. 伤害公式（核心）

基本伤害 = 攻击力 × 攻击力倍率 + 附加攻击力（「治疗」也是伤害类型；固定值伤害/基于防御的伤害内部也把对应数据当攻击力用）。

记 \(A\) = 基本伤害，\(D\) = 目标对应防御/法抗/元素抗最终结果，\(I_p\) = 百分比穿透，\(I_v\) = 数值穿透。

- **物理伤害**：\(\mathrm{DMG}_p = \max\big(0.05A,\; A - (1-I_p)\cdot\max(0,\; D-I_v)\big)\)
  - 即「攻击力 − 防御力」加减成，5% 保底（抛光）。
- **法术伤害**：\(\mathrm{DMG}_a = \max\big(0.05A,\; 0.01A\cdot\max(0,\; 100-(1-I_p)\cdot\max(0,\; D-I_v))\big)\)
  - 即「攻击力 ×(1 − 法抗%)」，5% 保底。⚠ 算法中 0.01 实际略小于标注值（约 −0.3e-7，定点数误差，见 `定点数与浮点数`）。
- **元素伤害**：\(\mathrm{DMG}_e = \max\big(0.05A,\; 0.01A\cdot\max(0,\;100-D)\big)\)，\(D\) 为元素抗性；元素损伤同理，\(D\) 改为损伤抵抗。
- **真实伤害**：\(\mathrm{DMG}_{pu} = A\)（无视防御法抗）。
- **治疗量**：\(\mathrm{DMG}_h = A\)。

### 3.1 伤害红字（暴击显示）
- 最终伤害 ≥ **期望伤害** × 1.5 时显示红字（非真实增伤，仅显示）。
- 期望伤害计算时：不考虑防御/法抗贯穿、各类后置增益（脆弱等）、伤害重设、屏障吸收、特殊生命值机制；目标无敌时期望 ×0。
- 强制红字：部分技能无视规则必出红字；被屏障/护盾抵挡时转蓝字/黄字 BLOCK。显示取整使用**就近取整（四舍六入五成双）**。

## 4. 攻速公式
实际攻击间隔 \(T = T_0 / \big(\mathrm{clamp}(S,10,600)/100\big)\)
- \(T_0\)：理论攻击间隔（干员数据）。攻速显示区间：非常快 <0.8s、快 0.8–1.0、中等 1.0–1.2、较慢 1.2–1.6、慢 ≥1.6。
- \(S\)：攻击速度，默认 100；clamp 到 [10,600]；但攻速属性实际下限被限制为 20（见数值范围）。
- 每秒攻击次数 = 1 / 实际攻击间隔。

## 6. 移速
- 每帧移动 \(\text{移动速度} \times m \div \text{帧率}\) 格（沿寻路最短路径），\(m\) = `move_multiplier`（默认 **0.5**，即实际速度是面板一半，二倍速下视觉相等）。
- 移动速度数值下限 0.1（面板），无上限；我方干员/装置/召唤物移动速度默认 1.0（不可移动）。

## 7. 阻挡半径
- 地面阻挡半径 = 0.70709997（平方 0.49999037）。
- 飞行阻挡半径 = 0.8944 × 阻挡半径倍率（平方 = 0.79995137 × 倍率²）。
- 装置覆写阻挡半径平方数；巨型装置固定 0.49999037。

## 8. 闪避
- 仅有闪避伤判效果时，多个闪避叠乘：\(P = 1-(1-P_a)(1-P_b)\cdots(1-P_n)\)。
- 更精细定义见 `伤判效果` 子页面。

## 9. 维持技能状态
- 技能开启后不普攻、持续执行技能效果（星熊 3「力之锯」、伊芙利特 3「灼地」等）。
- 时间模式：跟随攻速 / 跟随动画（Spine 动画周期）/ 特定情况 / 从 Blackboard 加载。
- 特性：免疫攻速加减速；眩晕、冻结等硬控提前结束状态进入技力恢复。

## 10. 基建数值公式（模拟基建产出用）

### 10.1 贸易站
- 实际每小时心情消耗 = 1 + 贸易站基础加成（进驻 2 人 −0.05、3 人 −0.1）+ 后勤/中枢加成（中枢每名干员 −0.05）+ 对当前干员生效的后勤加成。
- 实际订单效率 = 1 + 基础加成（每进驻 1 人 +1%）+ 后勤技能加成。
- 订单（龙门商法）：赤金2 → 龙门币1000 / 2:24:00（1 级）；赤金3 → 1500 / 3:30:00（2 级）；赤金4 → 2000 / 4:36:00（3 级）。开采协力（3 级）：源石碎片2 → 合成玉20 / 2:00:00。
- 赤金订单出现概率（1/2/3 级贸易站）：2 赤金 100/60/30%；3 赤金 0/40/50%；4 赤金 0/0/20%。【裁缝】【手工艺品】技能提高高费订单概率（α：3 小时累计，β：5 小时累计；多个同时进驻各判一次取需求最多）。

### 10.2 训练室
- 专精基础用时：R1 8h、R2 16h、R3 24h。
- 实际训练时间 = 基本训练时间 / (1 + 0.05 + 协助干员后勤技能加成)（任意未涣散干员进驻协助位 +5%）。

### 10.3 会客室
- 线索获取加成 = 宿舍氛围累计（0-1999:0% / 2000-2999:5% / 3000-3999:10% / 4000-20000:15%）+ 进驻干员星级（1-3★:0% / 4★:2% / 5★:4% / 6★:5%）+ 精英阶段（0:0% / 1:8% / 2:16%）+ 会客室等级（1:7% / 2:9% / 3:11%）+ 非涣散 5%。涣散时仍触发精英化/星级加成。

### 10.4 宿舍
- 每小时恢复心情 = 1.5 + 0.1 × 宿舍等级 + 0.0004 × 实际氛围 + 宿舍内干员技能加成。

### 12.5 信赖值（信赖点数 ↔ 信赖百分比）

- **信赖百分比**（游戏外显「信赖值」）影响信赖加成属性及附属资料解锁；**信赖点数**（内部）决定信赖百分比，对应关系见下表。
- **作战获取**：每次作战完成后，作战编队中所有干员每人获得**等量**信赖点数。自「未许之地」版本（2025/12/5）起，统一为**实际消耗**的理智数量；剿灭作战「全权代理」不获得信赖点数。
  - 已过时算法（2025/12/5 前）：3 星及以上评价 = 消耗理智数；2 星及以下评价普通关卡 = 消耗理智数 − 1；2 星及以下评价资源收集关卡 = 消耗理智数 / 2（向下取整）；剿灭作战 = 实际消耗理智数量（不含全权代理）；不消耗理智的关卡 = 0。
- **基建获取**（需手动收取）：
  - **进驻信赖**（橙）：干员进驻任意设施（活动室除外），每日 4:00 产生；点数按基建内所有宿舍总氛围值计算，最高 **100**/次。
  - **副手信赖**（蓝）：干员被任命为基建副手时，每日 4:00 及 16:00 产生；中枢副手按所有宿舍总氛围值计算，最高 **500**/次；楼层副手按主管楼层内单间宿舍氛围值计算，最高 **125**/次。
  - **活动信赖**（黄）：干员被安排到活动室时，每日 4:00 及 16:00 产生；按使用的活动室氛围值计算，最高 **125**/次。
  - 同一干员单次可获多种信赖（如进驻任意非活动室的基建副手），但无法单次获得多个同种信赖。手动收取顺序：**副手信赖 → 活动信赖 → 进驻信赖**；未收取的信赖会在对应获取时间被新的同种信赖替换。
- 干员信赖值达到 **100%** 后，属性加成达到上限。
- 自「未许之地」版本（2025/12/5）起，**助战信赖加成限制全部取消**，助战干员的信赖值与其在持有者的状态完全同步（旧规则：助战信赖值除以 2 再向下取整计算加成；精英阶段 0 时存在 50% 信赖值上限）。
- 异格干员与本体信赖值共享；同时参与行动/进驻基建时各自独立计算产生的信赖值。

### 12.6 就近取整（四舍六入五成双）

- 明日方舟使用 Unity 引擎，多处使用 `Mathf` 对小数（float）取整：
  - `Mathf.Floor(x)`：向下取整（返回 ≤ x 的最大整数）。
  - `Mathf.Ceil(x)`：向上取整（返回 ≥ x 的最小整数）。
  - `Mathf.Round(x)`：就近取整，**并非四舍五入**，而是「**四舍六入五成双**」（.NET `MidpointRounding.ToEven` 规则）。
- 对 \(x\) 的小数部分 \(x_f\)（\(0 \le x_f < 1\)）：
  - \(x_f > 0.5\)：向上取整（例：7.6→8，9.72→10）。
  - \(x_f < 0.5\)：向下取整（例：7.4→7，4.4999→4）。
  - \(x_f = 0.5\)：返回 \(x\) 两边整数中的**偶数**（例：7.5→8，6.5→6，1999.5→2000）。
- 站内提及「就近取整」即指此规则。
- 实例（集成战略「探索者的银凇止境」，文化比较研究全完成后高难度 9+ 下 +23% 攻击力与防御力，以符文写入，符文加成后数据**就近取整**）：
  - THRM-EX（1 星，30 级满信赖），原攻击力 350：350 × 1.23 = 430.5 → **430**。
  - 12F（2 星，30 级），原防御力 50：50 × 1.23 = 61.5 → **62**（五成双取偶）。

### 12.7 伤判效果（闪避/格挡/护盾/屏障判定）

- **定义**：通常在**计算完防御/法术抗性之后**、增加或减少伤害或直接让伤害归零的 BUFF 统称；**不包括**无敌与重设伤害效果。
- 共 6 种通常为伤判效果的效果（也存在不为伤判效果的情况）：
  1. **伤害修改**：脆弱、庇护、屏障（屏障量 < 伤害时）、敌方「特定条件下伤害减少」等。
  2. **过量治疗**：休谟斯的转化为屏障、集成战略藏品食腐者权杖的溢出伤害等。
  3. **抵挡**：护盾、屏障（屏障量 ≥ 伤害时）、星熊的概率伤害抵挡等；※早期文本中的「格挡」即指**抵挡**。
  4. **闪避**：焰尾的次数闪避、概率闪避等；※从伤害规避角度闪避与抵挡「相同」，但是两种不同效果，在部分判定条件中区别明显。
  5. **不受伤**：打光道具等装置的「受到伤害时不受伤…」能力。
  6. **反伤**：龙舌兰天赋、玛恩纳天赋等。
- **处理顺序**：依次按**事件优先级**与 **BUFF 获取顺序**处理每个伤判效果（**事件优先级 > 获取顺序**）。
  - 每个伤判效果单独处理自己的条件与效果（血量要求、触发概率、应对伤害类型、屏障量、护盾次数等），条件满足才可正常规避/增加/减免伤害。
  - 若伤害被某效果**成功归零/取消**（成功闪避、成功格挡、伤害减至 0），后续**一部分**伤判效果（各类检测伤害予以闪避的效果、各类计次格挡效果）将不再处理，**绝大部分**效果（反伤、受伤计数等）仍可处理。
  - 若所有伤判效果均处理完且伤害未归零，本次伤害才视为「**成功造成伤害**」，可触发「成功造成伤害时」节点；反之按伤害情况（成功抵挡/成功闪避）触发对应效果（如焰尾天赋）。
  - **无视闪避**：具有无视闪避能力的攻击会在处理伤判效果前赋予此次伤害「无法因闪避而取消」的效果，此时仍会判定闪避的概率、次数等，但无论如何都无法被闪避取消。

**常见伤判计算特殊优先级**（事件优先级）：

| 事件优先级 | 效果来源 | 效果描述 |
|---|---|---|

**实例要点**（判定顺序影响战局）：
- 先获护盾再获闪避：受伤只触发护盾，护盾消失后才正常触发闪避；反之先算闪避、失败才消耗护盾（赤冬「信影流·十文字胜」+ 深海色「视觉陷阱」）。
- 泥岩（敌方）屏障 vs 铃兰「狐火渺然」脆弱：屏障先于脆弱判定则伤害优先被屏障挡下、无法享受脆弱；脆弱先判定则屏障被更快击破。干员泥岩的护盾是**在已有护盾之上补充层数**（剩余 0 层也如此），不会改变 BUFF 获取顺序（几乎永远最先被获得）。
- 被抵挡/闪避的伤害无法触发「成功受到伤害」/「成功造成伤害」类效果（雷蛇「战术防御」、阿米娅「情绪吸收」等）。

### 12.8 定点数与浮点数（0.01 精度误差）

- 游戏为 Unity/C#。数值类型：整数（int）、浮点数（float，IEEE-754）、以及明日方舟自定义的**定点数（FP）**。
- **浮点数**：指数范围 −127~128；无法准确表述分母因子含非 2 质数的值（如 0.1、0.01），且误差随数值增大而增大。程序计算内已大规模弃用，但 JSON 数据库仍以浮点数存储数据，误差仍然存在。
- **定点数（FP）**：64 位数据类型，基数（最小单位）为 \(2^{-32} = \frac{1}{4294967296}\)；第 1 位正负号，第 2~64 位为数值绝对值，上限 \((2^{63}-1)\cdot 2^{-32} = 2^{31} = 2147483647\)。同样无法准确表述分母因子含非 2 质数的值，但**不论整数部分大小，误差相同**。
- 定点数和浮点数只能准确表达**分母为 2 的幂**的数值（如 1/2、325/8、799/512、360/65536 等）。
- 误差可能在类型转换/处理中被继承甚至被取整逻辑放大，导致呈现值与理论值差 1。

| 4% | 略小 | 0.04 | 171798691 | 0.039999999804422 | 贝娜流失 4% 生命值 26 次才足以致死 |

### 12.9 生命值（常规/溢出/负生命值三部分）

截至简体中文 2.6.21 版本，生命值分为三部分：**常规生命值、溢出生命值、负生命值**。

- **常规生命值**：通常所指的「血条」（我方蓝条、敌方橙/红条）。下限 0、上限为最大生命值；**最大生命值变化时生命值同时变化，使生命值比例不变**；所有与生命比例相关的判定均判断常规生命值（如「扣挠之手」的基于当前生命比例伤害，不把溢出/负生命值计入）。
- **溢出生命值**（超出最大生命值的部分，「额外血条」，将进酒版本加入，最初用于岁相吸收磷火）：
  - 角色类单位和巨型敌人存在与最大生命值相关的**溢出生命值上限**：巨型敌人固定为 **100%** 最大生命值；角色类单位默认为 **50%** 最大生命值，可后续调整。
  - 仅在应用 `modifier` 时被判定（与常规生命值一同计算扣减/储存）；不应用 `modifier` 的生命值调整（如生命恢复）无视溢出判定。
  - 增加生命值的 `modifier` 需携带特殊 Flag：`HEAL_CAN_GENERAL_SHIELD_FLAG` 才能产生溢出生命值；**过量治疗**的处理通常会**临时启用**溢出生命值。
  - 休谟斯天赋处理顺序：①调整自身溢出生命值上限，将治疗调整为可产生溢出生命值；②产生溢出时记录溢出量，并以生命流失形式扣除；③生成等同于此溢出量的屏障。
- **负生命值**（「归零」后在表现上以负数值参与计算，墟版本加入，最初用于斩业星熊「我执」判定）：
  - 并非常规生命值降至负数，而是以一段新的「负数血条」计算，该数值实际为**正值**。
  - 任何实体类单位均存在负生命值上限，默认 **0 × 最大生命值**，可后续调整；**最大生命值变化时负生命值不变化**。
  - 上限 > 0 时的重设生命值判定：目标值 > 0 时，若目标值 > 当前常规生命值则用负生命值抵消部分增加并重算目标值，否则仅计算在常规生命值上；目标值 ≤ 0 时，若当前常规生命值 > 1 则设负生命值 = |目标值| − 当前常规生命值，否则负生命值 += |目标值|；收尾判定：若负生命值 ≥ 负生命值上限则触发「生命值归0前」（`OnBeforeTrySetHpZero`）事件。
  - 计算完成后：负生命值 clamp 到 (0, 负生命值上限) 区间；持有不死时区间上限变为 负生命值上限 − 1；设置常规生命值（下限为 1）；若负生命值 = 负生命值上限，视为生命值归零。
  - 负生命值上限 > 0 时，在 `OnBeforeTrySetHpZero` 事件中无法直接阻止当次生命归零，`OnPostTrySetHpZero` 通常也无法正常生效，**免死效果几乎无法正常生效**；`force` 属性可无视负生命值机制直接设置常规生命值为 0。
  - 负生命值上限为 0 时可视为负生命值机制未激活，不参与各类判定。

### 12.10 部署费用

**关卡部署费用相关属性**：
- **初始费用**：行动开始时预先充入的费用量，大多数关卡为 10 点，也有 0 点（通常代表敌人有入场环节，如 5-10）。
- **费用回复间隔**：自然回复 1 点费用的时间（秒），通常为 1（每秒 1 点）。「部署费用速度降低」条件实际通过符文调整**费用恢复速度倍率**：回复间隔′ = 回复间隔 × 1/恢复速度倍率。剿灭等「部署费用不会自然回复」实为把回复间隔调至极长（如 **999999 秒，约 11.5 天**）。
- **费用点冷却**：距下 1 点费用回复的冷却进度（当前费用下方白条），所需时间 = 费用回复间隔。
- **最大费用上限**：通常为 **99**，仅剿灭或类似关卡（如雾色行动）为 **999**；费用到达上限后停止回复，溢出丢弃。第 12 章「限制最大费用上限/鉴定平民获取上限」实为利用环境效果将 99 上限压缩至「初始 20」，并非修改上限。
- **部署费用下限**：通常为 0。

**负数当前费用**（可露希尔实装后，费用下限可降至 0 以下）：
- 当前费用回复至 0 前，费用恢复速度**减半**（与费用回复速度等数值乘算），除此之外没有其它特殊效果。
- 几乎所有费用判定（部署、特性、技能、天赋耗费）都可正常「透支」消耗负数部分；出现负费图标提示。
- 特殊能力对「当前费用」的检查需启用负费处理（`_considerNegativeCost`）才能与费用下限交互，判断标准改为 **费用下限 + 写出费用值**（例：判断「持有 10 费」且费用下限 −6 时，标准变为 −6+10=4 费）；未启用则只考虑正数部分（标准零上判定）。大多耗费机制已启用（特种-行商特性耗费、琳琅诗怀雅第二天赋等），未启用的如老鲤第二天赋、保全派驻「可充能督战音响」额外耗费、界园志异「部署费用 99 及以上」判定。
- 部分单位「清空费用」机制实为将部署费用**重置为 0 点**，负数费用会被「补充」到 0。

**待部署区单位的部署费用**：
\[
\text{部署费用（属性）}=(\text{初始部署费用}+\text{基础费用增减})\times\text{费用倍率}+\text{实时费用增减}
\]
- **初始部署费用** = 部署费用（属性）的基础值；通常在没有符文干扰时等于战斗外干员列表按费用排序提示的费用，**包括精英化的额外费用、潜能的费用减少、模组的基础费用减少**（琳琅诗怀雅特限模组除外）；地图「费用翻倍/变 3 倍」为符文加成，直接作用于初始部署费用。
- **基础费用增减**：换费效果与小部分无限制自我费用减少天赋，等效**直接加算**。
- **费用倍率**：默认 1.0，通常只由**再部署惩罚**提供，等效**直接乘算**。
- **实时费用增减**：大部分费用减少效果，等效**最终加算**。
- 待部署区单位若当前费用不足以支付部署费用，无法被拖选；已拖选并放置也无法正常部署。

**再部署惩罚**：
- 干员每次退场（包括撤退、被击倒）累积一层，**上限两层**；每层为待部署区「自己」（由 UID 严格一一对应）提供 **0.5** 额外费用倍率。
- 第二次部署费用 = 初始的 **1.5 倍**（之后向下取整），第三次 = 初始的 **2.0 倍**，之后不再变化。
- 部分离场方式（如乌尔比安与 Mon3tr 的移动）不累积再部署惩罚。

**基础部署费用** = 初始部署费用 + 基础费用增减（作为「打乱费用」「费用交换」参考值，也作为撤退返费上限）。

**撤退返费**：
- 干员从场上撤退（手动/强制/自动撤退等）时通常返还 **50%** 本次部署所消耗的费用。
- 关键量：**部署费用（属性）**（本次部署实际消耗）；**返还上限**（通常 = 基础部署费用，除非有「无视返还上限」）；**返还倍率**（大部分召唤物、装置、特种-行商分支为 **0%**，先锋-冲锋手为 **100%**，其他大多数干员为 **50%**）。
\[
\text{返费量}=\left\lfloor\min(\text{部署费用（属性）}\times\text{返还倍率},\ \text{返还上限})\right\rfloor
\]
- 例：部署费用属性 15、基础部署费用 10、返费率 50% → ⌊min(7.5, 10)⌋ = **7**；部署费用 34、基础 3、返费率 50% → ⌊min(17, 3)⌋ = **3**（部署费用属性可受实时费用增减影响，基础部署费用始终不会）。
- **可返费**：除手动部署 + 手动撤退外，大部分其他部署/撤退方式都会标记「不可返费」，撤退不返还任何费用；但该设计存在漏洞（例：新约能天使 3 技能投递部署费用 70 的干员，本次部署未被标记不可返费，撤退时仍返还 70 的 50%）。
- **无视返还上限**：先锋-冲锋手 CHG-X 模组将返还上限改为与部署费用（属性）相同，实现返还「该次部署费用」（返费量 = min(X×1, X)）；特种-处决者 EXE-X 模组做相同操作，并额外提供 **80%** 返还倍率。

### 12.11 待部署区（手牌区排序与规则）

- 待部署区为画面底部排列的干员头像区（首次在保全派驻模式中被明确定义）。
- **基础排序规则集**（依次）：
  1. **初始部署费用升序**（从小到大）——注意这里的「初始部署费用」**计入符文效果**（如突袭费用增加）。
  2. 费用相同则按**职业枚举值**排序：**近卫 > 狙击 > 重装 > 医疗 > 辅助 > 术师 > 特种 > 召唤物 > 装置 > 先锋**。
  3. 职业相同则按**单位 ID 文本升序**：从左侧第一位数字逐个对比，第一个相异的数字小的在左侧；下划线（`_`）永远在数字的左侧。分支不影响排序。
     - 例：char_444_robrta 与 char_472_ironmn（8>0）→ 白铁永远在罗比菈塔左侧；char_202_demkni 与 char_2025_shu（`_`<5）→ 塞雷娅永远在黍左侧。
- **行动开始时**额外按初始分类规则排序：**玩家携带的自有队伍 > 关卡初始预投放的装置（如障碍物）> 助战干员**；排序完成后作为初始顺序**固定**，撤退再部署不改变顺序，而是插回原位。
- 关卡中途额外投放的召唤物/装置：仅按 **费用升序 > 单位 ID 文本升序** 插入，不经过职业枚举值排序。
- **待部署 Buff**（卡片特殊标记）：吞噬（最早由萨卡兹枯朽吞噬者应用，被吞噬干员在吞噬单位离开前无法部署）、源石封印（升级版，阻断玩家点选）、水月与深蓝之树的排异反应（紫）/进化（金）水雾、岁的界园志异的伺烛客标记与皮影系列「最左/右干员额外效果」粉青色边框、策士技能标记、耀骑士临光「双剑」标记、玛露希尔魔力回复（绿色充填边框）、新约能天使「投递坐标」标记等。
- **单位数量溢出**：一般情况下单位数量不作限制（部分标记可能错位或点选宽度计算错误）；**保全派驻**模式待部署区有 **12 个**单位数量限制且无法超出；**生息演算**模式可通过右下角翻页，部署第一个单位前分页最大单位数为 **15 个**，部署第一个单位后改为与 UI 宽度相关。
