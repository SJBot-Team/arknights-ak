# 99 来源与验证状态标注规范

> 规则（用户 2026-09-01 定）：**外部获取的内容（PRTS / B 站 / 本地文件等）与既有知识简单比对无明显错误 → 注明出处并加入知识库**；凡经**解包会话验证过**的机制与程序，额外标注「解包验证」，以便结论出错时排查错误/缺失知识。

## 1. 标注格式

知识库条目（笔记中的机制/数值/结论）统一使用来源标记：

```
> 来源：[PRTS·游戏数据基础](https://prts.wiki/w/游戏数据基础) 2026-08-31 抓取
> 来源：B站专栏 cv41544634（神祇读神奇）2026-09-01 抓取
> 来源：舟数据《干员输出表.xlsx》（用户本地）2026-08-31 分析
> 验证：✅ 解包验证（ArknightsGameData 字段对照一致）
> 验证：🟡 待解包核验（见 23 笔记 K-###）
> 验证：🔴 需 IDA 代码层核验（客户端组件/数据层无法验证）
```

- **出处**：来源名 + 页面/文件 + 抓取/分析日期；多来源则每个来源均标注。
- **验证状态**三档：
  - ✅ 解包验证：已在 ArknightsGameData/客户端资源中找到对应数据且比对一致（记录核验笔记号）
  - 🟡 待解包核验：有专栏/实测结论，但尚未在游戏数据中定位对应字段（登记到 `23_B站专栏_解读比对与待核验清单.md` 的 K-###）
  - 🔴 需 IDA 代码层核验：机制实现在程序逻辑中（如阻挡/阻挡偏移/寻路 nextnode 顺序），客户端数据层与 prefab 组件层无法核验，需反编译/反汇编（遵守客户端合规准则，在 `ak_kb\client_res\` 备份上解读）

## 3. 基建内容定位（用户 2026-09-01 定）

知识库**关注关卡中发生的战斗**；基建（贸易站/宿舍/制造站等）不是关注点，`01` 笔记 §10 与 `21` 笔记基建篇**仅作了解，不深入、不作为模拟重点**。

## 4. 入库流程

1. 新内容（PRTS/B站/本地文件/解包）先做简单比对（与既有知识无明显冲突）。
2. 无明显错误 → 写入对应笔记，按第 1 节格式标注出处（多来源全标）+ 验证状态。
3. 解包验证的机制在笔记中加「✅ 解包验证」并注明核验笔记号（15/16 等）。
4. 无法在数据层验证的 → 登记 K-### 待核验清单（`23` 笔记），标注 🟡 或 🔴。
