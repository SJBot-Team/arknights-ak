## 1. 逐篇要点

### 1.1 军械库弩炮加攻（cv6376991，2020-06-10）

**核心机制**
- 「弩炮是我方单位」的说法错误：拆包显示弩炮属**敌方阵营**，但实体类型是 **character**（character 下有派生 token、trap 等）；拥有路径、会向目标点移动的才是 **enemy** 类型。
- 危机合约词条的「敌方/我方」筛选指**实体类型**而非阵营。词条筛选共两道：
  1. 对象筛选：character 类 / enemy 类 / 关卡选项 / 关卡数据 / 地图；
  2. selector 筛选：职业、部署位、实体、技能、地砖 id 等。
- 职业筛选 `professionMask` 是**二进制掩码**，共 10 位，依次为：WARRIOR 近卫、SNIPER 狙击、TANK 重装、MEDIC 医疗、SUPPORT 辅助、CASTER 术师、SPECIAL 特种、TOKEN 召唤物、**TRAP 机关（第 9 位 = 256）**、PIONEER 先锋。判定方式：`professionMask & 目标职业 == 目标职业`。
- 军械库东的加攻词条 mask = **767 = 1023 − 256**（未排除 TRAP），降攻词条 mask = 1023 排除 TRAP（别的地图词条均为 1023）。

**结论**：弩炮/冰晶等地图机关通属 TRAP 职业；鹰角此前已专门调整军械库降攻词条排除 TRAP，却漏调了加攻词条，属配置遗漏而非阵营 bug。

**可编程要点**
- 模拟中区分「阵营（我方/敌方）」与「实体类型（character/enemy）」两个独立维度；词条/符文按实体类型过滤。
- 职业掩码按位运算：`(mask & profession) == profession`。

### 1.2 无限持续的钙质化（cv7020907，2020-08-03）

**核心机制（AuraAbility 光环能力，不含全场光环）**
- 光环为被动能力，不可开关，只有 attach/detach；光环技能/天赋添加的 buff 全部是**无限持续时间**，结束由光环能力自己控制。
- 依赖 Unity 碰撞检测：进入（OnTriggerEnter2D）/离开（OnTriggerExit2D）时触发事件。
- 条件筛选：`TargetValidator`；登记表 `m_targetMap`（键=实体指针，值=buff uid 类）。
- 更新：OnTick 每帧执行，**每 10 ticks（10 帧）**调用 `_UpdateInvalidTarget`，重新检查 `m_invalidTarget` 列表（用于处理隐身目标进入后解除隐身的情况）。
- 进入流程：OnTriggerEnter2D → OnTargetEnter → OnRealEnter → `_DoTargetCheckAndEnter`：VerifyTarget 通过则 DealTargetTouched 加 buff 并登记 m_targetMap（返回 1），否则加入 m_invalidTarget（返回 0）。
- 离开流程：OnTriggerExit2D → OnTargetExit → OnRealExit → `_DoTargetExit`：查 m_targetMap 成功则 DealTargetLeft（`removeBuffWhenTargetLeave=True` 时移除 buff）并删除键值对。
- 撤销流程：DoDetach（`removeBuffWhenAbilityDetached=True` 时遍历 m_targetMap 移除 buff）→ 清空 m_targetMap。

**bug 成因**
- 无敌单位进入光环：不满足 TargetValidator → 进 m_invalidTarget；离开范围：不在 m_targetMap → 无事发生；**无敌解除后**，OnTick 的 `_UpdateInvalidTarget` 检查通过 → **在范围外**也被加 buff 并登记 m_targetMap；再进入范围时 OnTriggerEnter2D 再加同名 buff（同名 buff 默认不叠加，只表现一个）→ m_targetMap 键相同、值被替换为新 buff uid → **旧 buff uid 丢失，脱离光环控制**（类内存泄漏）。此后旧 buff 无限持续且无视范围。
- 触发面比测试更广：**无敌、隐身单位均适用**；因「空」能给敌方加无敌，几乎所有单位可触发。

**可编程要点**
- 光环模拟必须保留「候补列表」的清理路径：目标离开范围时须同时从 m_invalidTarget 移除（修复方案 1），或加「是否在范围内」标志（修复方案 2）。
- 光环 buff 结束的触发条件（`removeBuffWhenTargetLeave` / `removeBuffWhenAbilityDetached`）应显式建模。

### 1.3 秋季活动客户端解包（cv7726160，2020-09-25）

**核心内容**
- 新召唤物获取方式：**直接作用于 deck（队伍）而非召唤物持有者**，可用于获得无持有者的物品（箱子/地雷/伐木工等关卡道具）。
- **睡眠机制调整**：由「无敌+眩晕」改为「无敌+**无法行动**」——无法行动（STUNNED_NO_AMPLIFY_DAMAGE）是本次更新新加入的异常效果，目的：**防止 W 2 天赋无条件放大睡眠敌人受到的伤害**（睡眠不再被当作可放大伤害的眩晕）。
- 睡眠新增三个机制：①可**无视睡眠状态**造成伤害；②优先选择**阻挡范围内睡眠敌人**的 selector（仅 character 对 enemy，属我方新干员）；③仇恨降序优先睡眠的 FilterType。
- 客户端含三种游戏模式：Default、Roguelike、Multiplayer（当时推测 Multiplayer 制作中、非实时联网）。

**可编程要点**
- 睡眠 = 异常组合「无法行动 + 无敌 + 不可阻挡」；伤害放大类效果（如 W 2 天赋「对眩晕敌人增伤」）判定须按异常 ID 区分，睡眠的「无法行动」不应被误判为眩晕。与 02 笔记 §7.5 异常表 ID 0（SLEEPING）/ID 19（STUNNED_NO_AMPLIFY_DAMAGE）互证。

### 1.4 天外飞仙：重生中的杰斯顿（cv8898116，2020-12-19）

**核心机制**
- 推力实现：对敌人 rigidbody 施加力 → 状态机切换至 **unbalance**（激活物理碰撞箱）→ 仅 unbalance 状态下每帧按**摩擦力**更新移动速度。
- 重生期间敌人处于 **reborn** 状态：状态机**无法直接切换**到其它状态（需 force 属性，直接切换方法无此属性）。
- bug 成因：reborn 中 rigidbody 被施力获得速度 → Unity 按速度位移，但状态机未切至 unbalance、碰撞箱未激活、不按摩擦力减速 → **以初始速度无限匀速位移、无视地形**。
- 为何只有杰斯顿：隐藏机制——**hp 为 0 时单位无法被选中，已锁定的目标也会丢失**。其它会重生的敌人重生时都有一段 hp=0 时间，期间被水炮等锁定也会丢目标；杰斯顿因 `_hpRechargeRatio = 1`（血条从重生一开始即回复）不存在 hp=0 空窗，故可被推动且不丢目标。
- `_hpRechargeRatio`（决定重生期间血条何时开始回复）实测值：霜星/大丑/梅妃鸟/黑蛇首次重生 = **0.5**，左手 = **0.2**，爱国者 = **0.85**，黑蛇第 2 次重生 = **0**，杰斯顿 = **1**；血条开始回复时刻一般对应 boss「站起来」的演出时刻。

**可编程要点**
- 敌人状态机建模：reborn / unbalance / 各异常状态机的切换约束；推力 = 施力 + 状态切换两步，需校验切换成功。
- 锁定/选择目标时检查 `hp > 0`（hp=0 时不可选且清锁）；重生流程中血条回复起点由 `_hpRechargeRatio` 参数决定。
- 位移摩擦只在 unbalance 状态生效——模拟匀速位移/减速需区分状态机。

### 1.5 春节活动客户端解包（cv9417919，2021-01-23）

**核心内容**
- 新干员：夕（dusk），召唤物可为本体叠加攻击。
- **明晦机制**：新地形「明晦之印」（置于其中的干员获得相同明晦属性，属性可能在一定条件下切换）、「朝暮之印」（经过的敌军明晦属性变化）；正常情况下明晦属性**不可同时共存**。
  - 相关 buff：来源与目标明晦**相同**时攻击倍率变化；**相反**时攻击倍率变化（解包时未知哪种增哪种减）。
  - 某种敌人：明晦属性共存时发生爆炸。
- **特殊阻挡条件**：仅当敌人/干员持有特定 buff 对之一时可被阻挡（大概率配合明晦：仅相同/相反明晦可互阻）。
- **致残（cripple）buff**：一段时间后持有者即死；持有者消失（进入地下通道）前即死；持有者被作为**主目标**击杀时，击杀者回复固定量 sp。
- 新 buff 行为：按干员/召唤物**已部署次数**获得不同效果。
- 新攻击能力 **DuoRangedAttack**：继承单次弹道攻击；对除第一个目标外其它目标的弹道发生变化；某种设定下对最后一个目标攻击 2 次。

**可编程要点**
- 明晦是实体属性状态（非异常效果），需建模「地形赋予 → 单位携带 → 倍率/阻挡条件判定 → 可切换」；倍率方向以实装数据为准。
- 致残 buff 的三条触发路径（计时 / 消失 / 被主目标击杀回 sp）可直接编码为 buff 事件。

### 1.6 从独行长路到无限余烬（cv10980384，2021-04-22）★底层逻辑重点

**核心机制**
- 独行长路（刻俄柏天赋 2）与清道夫「单独行动者」使用同一触发控制器 **AdjacentAllyToggleChecker**：场上单位出生/结束时判定，按设定开启/关闭 buff。
- **buff object 循环利用**：战斗中 buff 的 object 不销毁；失效后指针移至**通用栈**（recycle），新建 buff 从栈顶取用（allocate）。栈后进先出。

**bug 流程（巫恋娃娃自然撤退时）**
1. 自然撤退由「撤回 buff」在 Tick 中到最长时间结束时执行，进入 RunActions。
2. RunActions 触发撤回自身 action：清除自身所有 buff → buff object 全部入栈（娃娃身上只有撤回 buff 一个，最后入栈 = 栈顶）。
3. 清 buff 后触发单位结束事件 → 独行长路创建 buff → **取到的 object 正是刚回收的撤回 buff 的 object**。
4. 仍在 RunActions 内：撤退逻辑继续，获取「撤回 buff 持有者」并移除该 buff 附加的属性效果——但 object 已被分配给独行长路，**实际移除的是刻俄柏身上独行长路的属性效果**。
5. 该 buff 走完结束流程后**再次被回收**（实际它并未真正结束）。
6. 之后新建的 buff 又取到该 object；而独行长路记录里仍记录该 buff uid 且视为生效中。
7. 再在独行长路范围内放人 → 独行长路失效 → 经记录的 uid 从 `m_buffUidMap` 取指针**直接结束该 buff** → 新 buff 的控制权被独行长路捏住，可被任意清除。

**触发条件**：①结束的必须是**由 Tick 函数结束**的撤回 buff（非 Tick 结束则无缓存、拿不到立刻回收）；②撤回 buff 结束时必须是召唤物身上**唯一**的 buff。W 地雷 120s 自动消失也可触发（两个 buff 中第二个为有限时长，倒序遍历先被结束）；银灰「领袖」/苏苏洛「微创治疗」属 **deckBuff**（场下也生效、可加到召唤物上），使撤回 buff 非唯一而免疫该 bug。

**结论/应用**：只要掌握场上 buff 施加/结束顺序，可用该 bug 删除任意 buff（余烬强制撤回、黄昏掉血、森蚺阻回、浮士德无敌/不可阻挡、黑蛇火雨等）。

**可编程要点**
- buff 对象池采用栈式复用：`uid` 会因对象复用而「换皮」——模拟中必须区分「buff 实例」与「buff object/uid 槽位」，事件回调里持有的引用可能指向已被复用的 object。
- 自然撤退事件链：`撤回 buff(Tick 结束) → 清 buffContainer → 单位结束事件 → 新 buff 创建`，在同一帧 RunActions 内可能交错分配同一 object。
- 修复方向（理解正确性而非照抄）：清空 buffContainer 时只保留延迟一帧回收（不立刻回收）；光环实现的开/关类天赋不依赖「创建/结束 buff」事件。

### 1.7 异客的一堆 bug 和“bug”（cv14462417，2021-12-17）★底层逻辑重点

**bug 1/2：异常的停顿时间（配置分离问题）**
- 停顿时间存在两处配置：普通攻击读 **attack blackboard**；**瞬发技能**（Skill 直接搭载 RangedAttack，如辉煌裂片）读 **skill blackboard**（普攻式切换技能如聚焦指令初雷则仍走 attack blackboard）。
- 不带模组的异客，辉煌裂片停顿 **0.2s**（2021-08-03 加强前数据；加强只改了 attack blackboard，漏改 skill blackboard）。
- 带专属模组后：模组数据优先级高、覆盖 skill blackboard，提供 **0.8s** 停顿 → 辉煌裂片正常；但**没做名称区分**，把同为瞬发技能的 1 技能电能之触停顿也覆盖成 0.8s（描述 1.5s）。
- 停顿 buff 的 durationKey 在 buff_table 里写死为 `sluggish`，难按 buff 区分；修复建议：给 ability 加 blackboardPrefix（断罪者式）区分。

**bug 3：缓存攻击力（快照）机制**
- 定义：普通弹道每次命中**实时取来源攻击力**；使用缓存攻击力则弹道生成时确定攻击力，之后不变。
- 机制演进：`_useCachedAtkOnly`（强制缓存攻击力）早期照搬「来源不存在」方案 → 弹道**无来源伤害**（W D12：不跳红字、目标无受击变红特效、吃不到防空符文加成、打进化本质 12 阶段不被方向减免、不触发反甲）；2021-04（遗尘漫步）新增 `_useCachedAtkOnly + _transferSource`（强制缓存 + 有来源伤害），**当时仅在辉煌裂片使用**。
- 弹道伤害实现：能力初始化时配置好行为（Action）；生成弹道时 `PreprocessActionsForProjectile` **缓存来源攻击力**并导入弹道设定。
- **链术师例外**：`ChainLightningHitBehaviour` 每弹射一次衰减倍率 → 创建新伤害行为替换旧的 → **再次预设置（重新缓存当前攻击力）** → 辉煌裂片实际攻击力**实时更新**，与设定不符。
- 迷迭香对策：`_deliveryParaWhenReplaceActionNode` 在替换前把旧行为缓存的攻击力传给新行为（保撤回后弹道有伤害）；但异客存活时预设置仍会随后覆盖，该机制救不了异客。

**bug 4：法术伤害恰好致死不死（定点数精度）**
- 表现：理论法术伤害刚好等于剩余生命值时不死（例：2400 血 0 法抗风笛受 2×600 火球 + 1200 灼燃毁损，显示剩 0 血但不死）。
- 成因：铅封行动版本后大部分数值计算从 32 位单精度浮点换成 **64 位定点数**（高 32 位整数部分、低 32 位小数部分，最小精度 2⁻³²）。**0.01 在二进制是无限循环小数**，定点数只能存 32 位小数 → 实际值比 0.01 略小（≈0.00999999978）。
- 法术伤害公式（与 PRTS/01 笔记一致）：基本法伤 = MAX(0.01×攻击力×攻击力倍率×MAX(0, 100−(1−百分比无视法抗)×MAX(0, 法抗−数值无视法抗)), 0.05×攻击力×攻击力倍率)。
- 误差传播：乘法保持**相对误差**不变 → 绝对误差随乘的常数放大；2⁻³³ 级误差经攻击力×(100−法抗)放大到 2⁻³² 以上被记录 → 实际伤害**略小于理论值**。物理伤害公式无此类不精确常数，故不受影响；贝娜 2 技能按最大生命值流血同理。
- 修复建议：比较时加可容忍误差，或更换数据类型。

**可编程要点**
- 快照/实时两套弹道攻击力模型：`_useCachedAtkOnly`（生成时缓存）+ `_transferSource`（有来源）；行为替换（链术师弹射）会重新预设置缓存 → 模拟链术师时攻击力按「每次命中前来源当前攻击力」计算。
- 法伤公式常数用定点近似 `0.00999999978` 而非 0.01 时，恰好在剩余生命值边界上会产生「剩 0 血不死」；模拟死亡判定需容差（与 01 笔记 §12.8 表完全对应）。

### 1.8 buff 遍历逻辑引发的一系列 bug（cv17305212，2022-06-28）★底层逻辑重点

**核心机制：三个设计决策及后果**
1. **缓存列表（cachedBuffer）**：遍历 buff 池前把原列表 internalList 拷一份遍历缓存；遍历中可直接改原列表。但**缓存只允许一次**——已缓存时再取返回旧缓存。
   - 后果案例：42 自动撤回与黑夜图视野扩大同帧触发 → 新视野 buff 未被结束、buff 列表清空后仍处于「弄丢」状态 → 视野常驻。
2. **嵌套逻辑**：buff 结束事件（OnFinish）里创建新 buff 与清空逻辑嵌套。
   - 后果案例：贝娜+古堡的子嗣（我方出生创建 100s 计时 buff → onBuffFinish 创建永久加防 buff）→ 傀儡师切替身清 buff 不彻底 → 每次切换叠一层加防 → 上万防御。官方修复是改古堡的子嗣实现绕开（治标）。
3. **延迟结束**：除清空 buff 池外，任何时候结束 buff 只是**标记为已结束并失效**，正式结束/移除/回收统一在**各事件末尾**检查执行。
   - 后果案例 1：初版令 3 技能召唤物可攻击自己——模式切换靠本体光环，buff 结束事件延迟到下一事件；若下一帧是普攻开始（OnBeforeAttack），在攻击事件上切模式导致攻击目标变 0 → 攻击自己。
   - 后果案例 2：火球术士火球爆炸后部分单位停止攻击（将进酒版本才出现）——火球有「限时生命 buff，结束时退场」，爆炸 action 提前结束该 buff 被延迟；将进酒新增老鲤 1 天赋引入 **OnOwnerBlockeeChanged** buff 事件；火球是可阻挡敌人，若在 OnOwnerBlockeeChanged 中退场，RegisterBlocker 后仍被加入阻挡列表 → 之后变 null，角色阻挡了不存在的单位 → 攻击目标为 0 → 打自己。
   - 同类：老鲤 2 技能撤回伤害判定、流明 2 天赋可同时奶 2、流明+老鲤 buff 回收错乱。

**修复建议（理解性记录）**
1. 清空 buff 池改用非 enumerator 方式（对内部列表最后一个元素操作）——但须防「A 结束创建 B、B 结束创建 A」式嵌套无限循环（流明 2 天赋）。
2. 在目标 buff 池 enumerator 外（e_counter==0）结束 buff 时直接结束+移除，而非仅标记。
3. 少用 OnFinish 事件（直接与移除关联），用 OnDisable/OnTrigger 替代。
4. 或让 OnFinish 在首次标记结束时立刻触发。
5. 终极：链表 buff 池实时遍历；或把对 buff 池的修改排队到最外层遍历循环之外。

**可编程要点**
- buff 事件遍历语义：遍历「缓存快照」，事件内对 buff 池的增删不在当轮生效；缓存只拍一次快照 → 同一帧多事件共享同一快照。
- buff 结束分两阶段：标记结束（立即，触发失效）→ 统一移除/回收（事件末尾）。模拟器若逐事件结算须复现此延迟，否则「同帧创建又结束」类时序会对不上。
- buff 事件列表会随版本增长（OnOwnerBlockeeChanged 等新事件）改变既有时序——模拟器应把事件调度做成数据驱动而非硬编码顺序。

### 2.1 印证：法术伤害 0.01 定点数误差（↔ 01 §3.1、§12.8）
- 01 笔记已记录：法伤公式中 0.01 实际略小（≈0.00999999978，定点数基数量 42949672），并注明「法术伤害、元素伤害、元素损伤始终略低于理论值」。
- 异客篇（1.7）给出了该误差的**完整成因链与后果**：64 位定点数（高 32 位整数/低 32 位小数）无法精确表示二进制无限循环的 0.01；乘法保持相对误差、绝对误差被放大到 2⁻³² 以上被记录；最终「理论伤害恰好等于剩余生命值」时单位不死（风笛 2400 血吃 2400 理论法伤显示剩 0 血）。**两处互证一致，模拟死亡判定建议按 01 §12.8 加容差。**

### 2.2 印证：异常效果表与睡眠机制（↔ 02 §7.5）

## 3. 对本知识库「模拟还原」目标的可用结论（可量化的规则列表）

以下规则均来自本批专栏原文（数值以「解包仅供参考」为前提）：

**A. buff 系统生命周期**
1. **对象池栈式复用**：buff object 失效后指针入通用栈（recycle），新建 buff 从栈顶取（allocate）；栈后进先出 → 事件回调持有的 buff 引用可能被复用换皮，必须区分「buff 实例」与「object/uid 槽位」。
2. **自然撤退事件链**（独行长路 bug 流程）：`撤回 buff（Tick 到最长时长结束）→ 清空自身 buffContainer（object 入栈）→ 触发单位结束事件 → 其它控制器创建新 buff（取到栈顶 object）→ RunActions 继续执行剩余步骤`——同一帧内 object 可被分配两次，UID 记录（m_buffUidMap）与实际持有者可失配。
3. **触发控制器 AdjacentAllyToggleChecker**（独行长路/单独行动者）：场上单位出生/结束时判定开/关 buff；实现为「创建/结束 buff」事件的机制存在 uid 失配风险，模拟建议按「光环式重算」实现。
4. **遍历缓存**：buff 事件遍历用「原列表的一次性快照」（cachedBuffer，只缓存一次）；遍历中增删不改快照 → 同帧多事件共享同一快照，新 buff 在当轮事件中不可见。
5. **延迟结束**：除清空 buff 池外，结束 buff 只标记+失效，正式移除/回收统一在各事件末尾执行 → buff 结束事件可能延迟到下一事件（如 OnBeforeAttack），跨事件时序敏感（令召唤物打自己、火球停攻案例）。
6. **清空 buff 池**：按缓存列表遍历结束/清空，可能结束不干净（贝娜叠防）；修复语义为「非 enumerator 逐个清」，并须防嵌套创建无限循环（A→B→A）。
7. **同名 buff 默认不叠加**（进光环/再进光环只表现一个，uid 覆盖丢失）——与 02 §7.10 同名状态一致。

**B. 光环能力（AuraAbility）**
8. 光环为被动（仅 attach/detach）；其 buff 全部为**无限时长**，结束由光环控制。
9. 进入/离开判定基于碰撞（OnTriggerEnter2D/Exit2D）；条件筛选 TargetValidator；登记 m_targetMap（实体→buff uid）。
10. **10 帧**更新一次 `_UpdateInvalidTarget`（处理隐身解除等）；目标离开范围必须同时从 m_invalidTarget 清理，否则范围外补挂 buff（原 bug 根因）。
11. 结束标志：`removeBuffWhenTargetLeave`（离开移除）、`removeBuffWhenAbilityDetached`（能力撤销移除）。

**C. 伤害与数值**
12. **法术伤害公式**：`MAX(0.01·Atk·倍率·MAX(0, 100−(1−穿透%)·MAX(0, 法抗−穿透值)), 0.05·Atk·倍率)`；0.01 实际按定点近似 `0.00999999978` 参与 → 伤害略低于理论；**死亡判定建议容差**（与 01 §12.8 一致）。
13. **元素伤害**：`伤害 = 伤害量 × (1 − 元素抗性 × 0.01)`，5% 保底同法伤；元素抗性 `EP_DAMAGE_RESISTANCE`、损伤抵抗 `EP_RESISTANCE`；**脆弱/干扰地雷类不对元素伤害生效**，不挑类型增/减伤可生效。
14. **敌人版凋亡损伤**：15s 元素免疫 + 每秒 800 无来源元素伤害 + 攻击力最终降至 50%（持续时间内线性恢复至 100%）。
15. **弹道攻击力两模型**：普通弹道每次命中取来源当前攻击力；`_useCachedAtkOnly` 弹道生成时缓存（无来源伤害的旧形态另有 `_transferSource=false` 问题）；行为替换（链术师每弹射重建伤害行为）会**重新缓存** → 实时更新。
16. **停顿时间配置**：普攻读 attack blackboard；瞬发技能读 skill blackboard；模组数据可覆盖 skill blackboard（同 key 跨技能串值）；durationKey 写死 `sluggish`。

**D. 词条/符文/职业掩码**
17. 词条对象筛选：实体类型（character/enemy/关卡选项/关卡数据/地图）+ selector（职业、部署位、实体、技能、地砖 id）。
18. **professionMask 10 位**：近卫=1、狙击=2、重装=4、医疗=8、辅助=16、术师=32、特种=64、召唤物=128、**机关 TRAP=256**、先锋=512；判定 `(mask & 职业) == 职业`；TRAP 机关（弩炮/冰晶）属 character 类型、敌方阵营。

**E. 敌人/状态机**
19. 推力 = 对 rigidbody 施力 + 状态机切 unbalance（激活碰撞箱、按摩擦力更新速度）；**reborn 状态不可直接切换**（需 force）→ 施力后不减速匀速位移。
20. **hp=0 隐藏机制**：不可被选中，已锁定目标丢失；重生血条回复时机由 `_hpRechargeRatio` 决定（霜星等 0.5 / 左手 0.2 / 爱国者 0.85 / 黑蛇二次 0 / 杰斯顿 1）。
21. 睡眠 = 无敌 + 无法行动（非眩晕，不触发「对眩晕增伤」类效果）。

**F. 模式/关卡结构**
22. 波次超时强制清场：`超时 → 场上敌人全部死亡 → 下一波`；完成 ≥1 波即胜利。
23. 熔岩裂隙地块：放置干员触发前方范围法伤（敌方额外受法伤提升）；朝暮之印改变经过敌军明晦属性；明晦之印赋予相同明晦（可切换、不可共存）；特殊阻挡条件需特定 buff 对。
24. 致残 buff：计时即死 / 进地下通道前即死 / 被主目标击杀时击杀者回固定 sp。
25. 弹药补弹：弹药数首次不高于一定比例时按最大弹药数一定比例补弹（**向上取整**）。
26. 明烛台技能 4：持续法伤次数 = 当前金币数量的一定比例（**四舍五入，至少 1 次**）；技能 2 基于目标最大生命%真伤、技能 3 基于目标攻击力%物伤。
27. 围棋 boss：白/黑/空点判定 → 提子 → 无气之子加（疑似秒杀）buff；周围 4 黑棋永晕；黑棋周围我方单位数提升其受物/法伤害。
28. 界园藏品叠加语义：弹药类/开启技能类「无限持续可叠加」与「不可叠加」两类；每阻挡一个单位物/法闪避**加法叠加**（有上限）；首个部署干员属性提升（含抵抗/阻挡数）。
29. DuoRangedAttack：继承单次弹道攻击，非首目标弹道变化，特定设定下对最后目标攻击 2 次。
