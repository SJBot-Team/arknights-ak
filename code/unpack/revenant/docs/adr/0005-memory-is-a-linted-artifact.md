# agent 的记忆文件成为 `lint` 的受检对象，预算与指针都由 revenant 守

`merge-games-re` 的 `.claude/agent-memory/extract-economy.md` 长到 **314,748 字节 / 180,000 字符**（粗估 88k token），81 次提交里**一次都没有变小过**。它由 `_tools/econ-loop/loop.sh:94` 每轮确定性 `cat` 进执行器上下文，所以这个数就是每轮无条件付出的成本。我们决定把「记忆文件的容量与引用有效性」变成 `revenant lint` 的一条规则，而不是继续靠写在记忆自己开头的那句「只写长期成立的东西」自律。

## 为什么自律压不住

那份文件开头就写着判据：「这条如果三轮之后还成立，就写；只对眼下这一格有效，就别写。」171 条编号条目全部通过了它，因为**它只管进不管改**。后果在文件里能直接读出来：

- 条目之间有 **93 处互相回指**，「推翻 / 失效 / 要改 / 升级成 / 限定」合计出现 62 次。修订是**追加**的——第 102 条被第 108 条判为「换代之后整个失效」，第 102 条仍然按原样每轮注入。
- 自指已经断了。第 165 条写「按记忆第 435 行那条跑了 grep」，它指的内容实际在第 493 行；现在的第 435 行是第 134 条。行号锚在追加式文件里必然漂移。
- **171 条里 95% 点名具体游戏，平均 662 字符**——判据与证据焊在同一段里，而证据在 note 里已有更全的版本（第 143 条的 `MergeItemScoreConfig.lua`，`gossip-harbor/notes/econ-10-social.md:47` 与 `:176` 写得更细）。

最后一条正是 `CONTEXT.md` 的 **Ledger** 词条早就写下的那句：「事实层与结论层同文件就再也拆不开。」这不是新原则，是既有原则在一个没人看守的地方被违反了。

## 为什么落 revenant 而不是项目 `_tools/`

按 ADR-0004 那条准入判据——**这段代码里有没有游戏事实**——一个「记忆文件不得超过 N 字节、每条必须带一个能被验证的指针」的检查里一个游戏事实都没有：没有密钥、没有 URL、没有类名清单、没有目录约定（`.claude/` 是 harness 的约定，由 ADR-0001 锁定，不是某一款游戏的事实）。

而且这个病不是 `merge-games-re` 独有的。任何跑回路的项目都会得：只要有一份文档被无条件注入，且写它的人和读它的人是同一个 agent，它就会单调增长。ADR-0003 已经承认过一次「需要它的人自己造了一个」，这次是同一个形状的第二例。

阻尼器那一侧不重复实现。`_tools/econ-loop/dampener.py` 已经在数 lint error，预算超标自然进它现有的回归口径。

## 决定的四件事

**一、`lint` 认「记忆」这类文件，并对它检两样：容量与指针。** 容量超标与指针失效各是一条规则。**没有登记就不受管**——归档文件不进登记表，自动不计预算，不做显式的豁免开关。「豁免」这个词一旦有了就会被滥用；沿用 `[tables] dirs` 那条「点名即语料」的语义反过来用，更干净。

**二、指针的锚是一个出现在目标 note 里的字符串，不是行号。** 字段名、表名、符号名都行。它在编辑下最稳（改行号、改标题都不影响），而且可机器验证——打开那篇 note grep 一下就知道锚还在不在。**行号锚被明确拒绝**：上面那个「记忆第 435 行」就是这个方案的实测失败样本，换个文件再犯一次没有意义。

本条最初写的是「**唯一**出现的字符串」，实现时改掉了，因为那个要求在真实语料上站不住：本 ADR 自己举的例子 `merge_score_race`，在 `gossip-harbor/notes/econ-10-social.md` 里出现 **6 次**（`MergeItemScoreConfig` 出现 5 次）。一篇讲这个字段的 note 当然会反复提到它——要求唯一等于把最合适的锚判成不合格。所以检的是**在不在**，不是**出现几次**。代价说清楚：锚只保证「那篇 note 还在讲这件事」，不保证 grep 一下只落到一处。

**三、补上 `cited-note-missing`。** `lint` 现在验 RVA（`rva-not-found`）、验符号（`symbol-not-found`），唯独 `FILE_REF` 与 `NOTE_REF` 匹配上就算数，指向不存在的文件照样判「有源」（`_cites_something` 只做存在性正则匹配，从不落地查）。三种源里两种验、一种不验，这个不对称没有理由。顺带把 `econ-` 加进 `NOTE_REF` 的前缀表（原先是 `arch|core|elem|rule|diff|cross|schema|plan|ref`）——53 篇 econ note 的互引全靠写全路径被 `FILE_REF` 兜着。

**只查 `.md`，不查别的。**原本的说法是「引用的文件必须存在」，实现时收窄了：`res/` `src/` `lua/` 是解包出来的原料，全在 `.gitignore` 里，一台没跑过 `prepare` 的机器上它们本来就不在。把**我们没装好**报成**作者引了不存在的路径**，正是 `no-index` 那条规则存在的理由所反对的。

**`NOTE_REF` 的简写（`arch-09 §3.2`）不查，这是决定不是遗漏。**「三种源里两种验一种不验」这条不对称的论证同样能推到简写上，所以实现时按它做了一遍，然后撤掉：本仓自己有三条测试当场挂掉，三条断言的都是「一篇只引兄弟笔记的 note 是合规的」——也就是 ADR-0003 说的纯裁决篇；真实语料同时报出 50 条，**每一条都是把 `cross-07-progression` 在 `econ-cross-07-progression` 里面匹配出来的**。没有后缀的前缀跟后缀分不开，而规则 3 的文档注释本来就写着这种形式是「presence only, deliberately loose」。

**bare 名字要全仓库找。**收窄之后先跑了一遍真实语料，54 条命中**全部是假阳性**：这个语料里引用兄弟笔记的主流写法就是光写文件名（`econ-01-currency.md`），跨款汇总篇写「九款的 `econ-03-merge-chain.md`」，同源两款互引对方的 note 也这么写。所以候选根目录是四层：笔记自己所在目录、它的项目、仓库根、以及仓库里每一个 `notes/`（根的和各项目的，边界同 `repo_projects` 只走根与其直接子目录）。改完真实语料上归零，而「引了一个整个仓库都没有的名字」仍然报。

**四、记忆分两层**，跨款的留仓库根、单款的回各自项目的 `re-project` 覆盖层，理由见下面单独一节。

## 预算分两档

记忆与 skill 都每轮无条件进上下文，但增长机理不同，用同一个数会逼着人删错东西：

- **记忆**压得狠。它承载的是习得的、可推翻的经验，涨是因为没人删。
- **skill** 给得宽。它承载恒定的方法论，涨是因为方法论真的在变多——`extract-economy` 那 171 条里有 41 条在三款以上或两类以上数据源上复现过，这批本来就该从记忆搬进 `references/reading-sources.md`（压成一行约 9.8 KB，那份文件从 8.2 KB 涨到 18 KB）。搬家是对的，涨也是对的。

具体的数在实现时定，不在这里写死。

## 落地的规则与登记表

登记表是仓库根的 `.claude/agent-memory/memory.toml`，一张 `[files]` 表，键是仓库相对路径：

```toml
[files]
".claude/agent-memory/gap-loop.md" = { kind = "memory", bytes = 40960, entry_chars = 120 }
"hotel-legacy/.claude/skills/re-project/SKILL.md" = { kind = "overlay", bytes = 61440 }
```

`kind = "memory"` 才检条目；`kind = "overlay"` 只称重，因为覆盖层是关于某一款的散文，不是「判据 + 指针」的清单。文件读不出来或表不在，等同于没登记——**没有豁免开关**。

六条规则，只在 `lint --repo` 里跑（记忆是仓库级的，逐项目跑会把同一条报九遍）：

| 规则 | 档 | 什么时候 |
|---|---|---|
| `memory-over-budget` | error | 文件超过它自己声明的字节预算 |
| `memory-not-found` | warning | 登记了但磁盘上没有——改名不该悄悄把检查关掉 |
| `memory-entry-without-pointer` | error | 条目没有 `→ \`指针\`` |
| `memory-pointer-missing` | error | 指针指的文件不在 |
| `memory-anchor-missing` | error | 锚字符串已经不在目标笔记里了 |
| `memory-entry-too-long` | warning | 指针前的那句话超过 `entry_chars` |
| `memory-registry-unreadable` | error | 登记表在，但读不出来 |

最后一条是评审加的，而且加得对。原本「读不出来等同于没登记」的写法，等于让一个 TOML 拼写错误悄悄关掉全部六条规则——**这正是本 ADR 拒绝提供的那个豁免开关，只不过是靠打错字拿到的**。`config.load_config` 早就为 `revenant.toml` 吵完了这一架并选择了大声报出来，唯一的区别是 `lint` 有比 stderr 更好的去处。

条目既认 `- ` 也认 `1. `。那份触发本 ADR 的文件用的就是编号条目（171 条），只认 bullet 会让指针规则在**唯一促成它们的那个文件**上整套失效。

预算是 error 不是 warning：这个回路的阻尼器数的是 lint error，落进 warning 堆里的预算是没人管的预算。

## Considered Options

- **继续靠记忆开头那句自律。** 已实测失败：81 次提交零一次缩小，且是靠仓库主人偶然注意到才发现的。
- **只做容量检查，不做指针检查。** 容量能被「把两条塞成一条」绕过去，而且不解决「事实层与结论层同文件」那个根因。指针必填才是真正把证据推回 note 的那一手。
- **落项目 `_tools/`。** 过不了 ADR-0004 的准入判据反面——里面没有游戏事实，就该搬。而且第二个项目会重写一遍。
- **把记忆整个取消，全部塞进 skill。** 混掉了「恒定」与「习得」的分界（见 `CONTEXT.md` 新增的 **Memory** 词条）。习得的经验随时可能被下一轮推翻，进了 skill 就没有一个地方允许它被推翻了。

## 记忆分两层，这比预算更管用

`revenant init` 给每个项目写一份 `.claude/skills/re-project/SKILL.md`（`init.py:29` 写、`cli.py:2608` 读、`describe.py:391` 声明「never overwritten」），模板自己写着该放什么：「Traps this specific target has already sprung on you.」

**九个项目里 0 个在用。**八个的 `.claude/` 是空的；`love-and-pies` 那份是模板原样，最后一行 `_(Nothing recorded yet.)_`，建好之后一次没动。而根下那份记忆 171 条里有 **162 条点名具体游戏**。

原因在机制不在人：`loop.sh:94` 只 `cat` 一个地址，`extract-economy` SKILL.md 第 1 步也只点名那一个文件。**回路只给了 agent 一个可写的记忆地址，那所有东西都会写到那里去。**

所以分层：跨款的留仓库根，单款的回各自的 `re-project` 覆盖层，八份缺的补建（直接拷模板，比跑 `init` 干净——`init.py:85` 虽然跳过已存在的文件，但会顺带补 `.gitignore` / `CLAUDE.md` / `settings.json` 里缺的那些）。162 条摊到九份，每份不到 20 条，而且做哪一款只读哪一份。**分层本身就是最有效的压缩，预算从主要手段降级成兜底。**

两层用不同的档：根下那份按记忆档压得狠；九份覆盖层本身就是 SKILL.md，按 skill 档给宽——它承载的是「这一款的事实」，不是可推翻的习得经验。

## 冻结之前要先兑现的勘误

`extract-economy.md` 的「事实性修正」小节 50 条顶层条目，逐条核对下来：**18 条已回写进 note，16 条至今没改，16 条根本不是事实性修正而是放错地方的方法论。**未改的那 16 条里有 6 条作者当时就自己标了「该改」。

典型的三处：`notes/econ-cross-03-merge-chain.md:115` 的小节标题仍写着「九款零命中：『每级需要几个』不在任何一款的配置层」，而记忆里已攒了四个反例；`love-and-pies/notes/core-02-merge-mechanics.md:463` 仍写着该款「九款里数值静态可得性最差（0%）」，而同款 `core-03-cms-data.md` 早已写了整套 CMS 基线随包；`flambe/notes/econ-08-liveops.md:207` 的「兑换率：不存在」已被硬编码在结算函数里的 1 体力 / 4 代币推翻。

**所以那 62 KB 不是冗余的旧记录，是一份没人执行的勘误单。**直接冻结等于让这 16 处错误永久留在 note 里，而唯一记得它们错的那份文件被移出了 agent 的视线。回写排在整个改造的第一步，在拆记忆与改接线之前。

这也暴露了记忆当前承担的第四种角色（前三种是习得经验、方法论、lint 补丁）：**待办清单**。记忆不适合当待办清单——没有任何机制会检查一条「该改」有没有被改。这一部分兑现完就不再回来。

## Consequences

- `CONTEXT.md` 的 Agent 栈一节新增 **Memory（记忆）** 词条，两条分界写明：与 skill 按「恒定 vs 习得」划，与 note 按「查不查得到」划。
- 登记表落在仓库根、按约定路径收，不进 `revenant.toml`。`merge-games-re` 仓库根没有 `revenant.toml`（九个游戏目录各有一个），给它加一个就把它变成 project 了，而 `CONTEXT.md` 明写「一个没有 `revenant.toml` 的仓库根不是 project」。这与 `lint --repo` 收仓库根 `notes/` 是同一道题——判据都是「这东西不属于任何一个项目」——用第二套解法只会让「仓库级的东西归谁管」有两个答案。
- **预算按文件各算，不设总量。**九款互不相干，总量会让某一款查得深就逼另一款删东西。
- 存量的 `extract-economy.md` 冻结成 `notes/archive/_econ-loop-memory.md`。挪出 `.claude/agent-memory/` 是因为那个目录名本身在向 agent 传达「这里的东西你该读」；文件名带下划线前缀是因为 `collect_notes`（`lint.py:951`）用 `os.walk` 递归子目录，不加前缀它会被当 note 检——`lint.py:956` 那条「下划线开头不算 note」正是为这种情况准备的出口。**冻结之前必须先把未回写的勘误兑现**（见上）。
- 生成的 `re` skill 多两行，把记忆的格式教给 agent——规则打在一个没人教过的格式上，产出的是没人能照着改的 finding。ADR-0002 那个 80 行代理本来就在报警（ADR-0003 已经明文接受过这笔代价），本次 180 → 182 行。
- `extract-economy` SKILL.md 第 5 步那张「写不得」表里 `ObjCoinConf`（表名不带后缀）那一行是**错的**——实测它走 `CAMEL_IDENT` 被当成符号收下，判「有源」，最多出一个 `symbol-not-found` warning。删掉那一行，理由见 ADR-0006。
