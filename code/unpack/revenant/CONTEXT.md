# Revenant

一套把 Unity IL2CPP + xLua 游戏二进制复原成可读源码的工具集：`revenant` CLI 负责数据准备，只读 MCP server 把分析能力交给 agent，复原工作本身由 agent 在项目目录里完成。

## 什么东西够格搬进 revenant

判据只有一条：**这段代码里有没有游戏事实。** 没有就搬，有就留在项目脚本里。

游戏事实指这些东西：密钥；URL 与构造它的规则；项目 / 环境 / 桶 id；具体的类名与命名空间清单；目录约定；文件命名约定；按名字推语义的规则。构件要用到其中任何一样，就把它作为参数吃进来，或者干脆不搬。

**重复不是准入前提，只是通用性的一种证据。** 完整叙述（判据的三次变化、为什么不采纳更窄的版本、误判的形状、以及 playbook 那条另算的线）在 `docs/adr/0004-*`；这里只留每次开工都要看的这两段。

`revenant status` 会报出项目里、以及同级项目共用的上一级 `_tools/` 里已被内置构件取代的脚本，这是报告不是闸门，与 ADR-0002 的代理告警一致。

### 搬一样东西进来时，各部分放哪

- **构件**：能上命令面的落 `revenant/<名字>.py`（`protobuf.py`、`flatbuffers.py`）；只供项目脚本 import、不上命令面的落 `revenant/contrib/`。
- **命令**：默认十四条是 ADR-0002 定的，不动。新增一律落 **query 层**（`help --all` 才列），照 `pb-schema` / `pb-tags` 的先例。MCP 只暴露对已建索引的只读查询，批处理类命令不进。
- **测试**：`tests/test_backflow.py`（构件本身，跑合成输入，不碰真实游戏包、不联网）与 `tests/test_command_tiers.py`（层级与告警）。落在既有文件里，不新建。
- **项目里留什么**：游戏事实，以及编排——落地路径、命名约定、怎么数一行、按业务归类。留下来的脚本改成薄封装，不是删掉。
- **映射表**：`cli.SUPERSEDED_TOOLS` 补一条，写明是被命令取代（删掉副本）还是被可导入构件取代（改薄封装）。

## Language

### Agent 栈

**Harness**:
驱动 agent 的运行环境——负责加载技能、执行斜杠命令、管理工具权限、连接 MCP server。**两个**：Claude Code 与 Codex（ADR-0001 及其修订）。落地物由各自的 `Renderer` 从同一份 `Description` 渲染，所以方法论只有一份；harness 之间的差异只在文件位置、front-matter 与加载方式，不在内容。
_Avoid_: 客户端、agent 框架、CLI（`revenant` CLI 不是 harness）

**Model**:
harness 背后的语言模型。与 harness 是两件事：更换 model 不改变技能与命令的组织方式。
_Avoid_: AI、LLM 与 harness 混用

**Skill**:
写给 agent 的方法论文档（`.claude/skills/re/SKILL.md`、`.codex/skills/re/SKILL.md`），由 harness 按 description 自动加载。承载"怎么做才对"的约束，不承载入口。**两个 harness 都是按需加载**——列一张 name + description 的目录，正文选中才读，所以篇幅不是每轮成本。Codex 另有一条**常驻**通道（`AGENTS.md`，从 git 根往下逐级拼接、深的覆盖浅的、上限由 `project_doc_max_bytes` 定，默认 32 KiB），那条按 **Memory** 词条的规矩管：常驻即每轮付费，容量是设计约束。Claude Code 从启动目录一路往上找到仓库根，所以同一仓库里的多个项目共享上一级的那一份；`revenant status` 会说清它在哪一层。
_Avoid_: prompt、指令集

**Command**:
人主动发起的工序入口（`/re-deep` 等），一次调用对应一段确定的复原流程。与 skill 的分工是：command 是入口，skill 是每次都要遵守的约束。

**「入口」这层语义由 Claude Code 提供，不是所有 harness 都有。** Codex 的自定义 prompt 只存在于用户主目录，没有项目级通道，所以同样的内容在那边落成按需 skill——由模型按 description 选中，而不是由人敲。差别有后果：人敲是确定执行，模型自选是概率性的，同一段工序在两个 harness 上的可靠性不一样。
_Avoid_: 快捷指令、宏

**Memory（记忆）**:
回路每轮确定性注入执行器的那份文件，承载**习得**的经验——只有真跑过才知道、且随时可能被下一轮推翻的东西。与 skill 的分工按"恒定还是习得"划：恒定的方法论约束进 skill，习得的经验进记忆；一条经验稳定到不再变，就该搬进 skill 而不是留在记忆里。与 note 的分工按"查不查得到"划：**记忆只放下一轮开工前必须已经知道的东西，任何查得到的都退回 note，记忆里只留一行指针。**它无条件占上下文，所以它是唯一一处容量本身就是设计约束的文档。
**记忆分两层，按"跨不跨款"划。**跨款的那一份放仓库根下——它不属于任何一个项目，与 `lint --repo` 收仓库根 `notes/` 是同一个判据。单款的经验回各自项目的 `.claude/skills/re-project/SKILL.md` 覆盖层，那个槽位是 `init` 写的内置件、`describe` 声明它"never overwritten"，本来就是为"这一款把你坑过的地方"准备的。**只给一个可写地址，所有东西都会写到那里去**——一份 171 条、162 条点名具体游戏的根下记忆就是这么长出来的，分层本身比任何预算都更能压住它。
_Avoid_: 上下文、笔记、日志、经验库（"记忆"特指被注入的那一份，不泛指 agent 知道的东西）

### 逆向工作

**Target**:
当前项目正在逆向的那个游戏，由 package / version / 架构三元组标识，全部自动检测（`re_status`）。换 target 只需换 apk 重跑流水线，不改代码。
_Avoid_: 游戏、app、包

**Project**:
一个 target 对应的工作目录，以 `revenant.toml` 为标记。持有数据与配置；代码在已安装的 `revenant` 包里。
_Avoid_: 工作区、workspace

**Evidence tier（证据档位）**:
一条结论的证据**来自哪一层**，按取证手段命名，四档：反汇编坐实 / 脚本源码坐实 / 托管代码坐实 / 结构推断。全局固定，项目不得自定义——跨游戏比对的前提是尺子一样。
只量「来源」这一根轴：来源客观可验，推断强度是主观的，塞进同一个分级会给它一层假的客观性。原先的「推测」档已废（22 篇实测用了 0 次）。
note 里可以写别名（`[Lua坐实]` `[原生T1]` `[C#签名]` `[DEX普查]` `[推断]`），别名表只在 `methodology.TIER_ALIASES` 一处，`lint` 读它、skill 列它；旧的 `T1/T2/T3` 只认不教。
_Avoid_: 置信度、可信度；也不要与 **cell state**（格子填成什么样）或 **gap marker**（结论成立但某部分拿不到）混用——这三样是三件事

**Scaffold**:
`src/<version>/` 下由 `revenant seed-src` 从 DiffableCs 预填的类骨架（字段 + 方法 stub + `[Address(RVA=...)]`）。复原是在 scaffold 上原地替换方法体，不是新建文件。
_Avoid_: 模板、桩代码（"模板"在本项目专指 `revenant/templates/`）

托管源码有**两个根**，同一套命令覆盖：scaffold 的 `src/<版本>/`，以及从热更程序集恢复出来的 `src-hotupdate/<版本>/`。九款里有四款（两款 HybridCLR、两款 IFix）的业务逻辑最终形态就是 C# 文本，而 Lua 一侧从一开始就有五条命令、C# 一侧一条都没有，读它只能退回裸 `rg`——`search` / `lookup` / `xrefs` 读的是 IL2CPP 索引，索引里没有源码树。于是有 `cs-list` / `cs-get` / `cs-grep` / `cs-refs`，形状照抄 `lua-*`。

两个根里只有第一个是 revenant 的：`src/` 由 `seed-src` 写出来，所以 revenant 有资格给它起名；恢复出来的源码落在哪里是**那个项目的事实**，按开头那条判据不该写死在这里。`src-hotupdate` 是默认值（现有的项目都这么写，白给），`[csharp] roots` **取代**这个列表，同 `[tables] dirs` 取代自动发现。

两个根**平等对待但绝不悄悄合并**：一边是掏空的 stub、一边是真正发出去的方法体，所以每一行输出都标出自哪个根，`cs-get` 撞上两边同名时列出两个、让人自己用 `--from` 说（不是 `--root`——那是全局标志，`normalize_global_args` 会在任何位置把它提走，而且对其他命令它指的是 RE 产物根）。

`cs-refs` 按整词匹配（`ItemConfExtra` 不是 `ItemConf` 的引用），并把声明与引用分开报。判据是**符号在不在名字位上**：声明里符号前面站着一个类型 token，所以 `private ItemConf _cfg;` 声明的是 `_cfg` 不是 `ItemConf`，`Reward(1, 2);` 是调用不是方法声明。两条最初都判反了——前者会把一个被广泛使用的类型的每个使用方都算成它的定义处，后者会把「谁调用了它」这一栏系统性地清空，而那正是 `refs` 被问的问题。但它终究是**文本**不是解析出来的调用图：注释、字符串字面量、另一个 namespace 里的同名类型都会命中，跨行的签名可能落错栏，这句话跟在输出里。

这一族**不设深度/目录上限**，与 `table list` 的有界扫描相反：那边扫的是没人指名的目录，这边是读者点名要搜的树，悄悄停在第三层就是在回答另一个问题。真会咬到的上限只有条数限制，而且分栏报成 `2 of 15`——截断后的数当成总数打印，读起来就是一个答案。目录本身不在、或者在但一个 `.cs` 都没有，四条命令一律说「去跑 seed-src」并以非零退出——同 `table refs` 那条线。

**Reconstruction**:
从汇编推回可读 C#/Lua 的过程。区别于 Cpp2IL 的机械输出——后者是地图，汇编才是地形。
_Avoid_: 反编译（decompile 专指 Cpp2IL / unluac 的工具输出）

### 冷启动与深挖

**Fingerprint（指纹）**:
开包即可采集的包级**观察清单**（引擎版本、构建机路径、清单声明的程序集与 metadata 的差集、`.bytes` 字面量、原生库导出符号），纯静态、跑在 Cpp2IL 之前。它只陈述看到了什么，不判定这是哪种热更方案、也不给同源打分——那是 agent 读观察之后的判断（见 ADR-0002）。
_Avoid_: 画像、特征、判定

**Corpus（语料）**:
探针或检索实际匹配的那批东西——IL2CPP 索引、元数据字符串、或解出来的脚本源码。玩法代码在热更程序集里的游戏，在 IL2CPP 索引上搜什么都是零，所以「代码在不在这份语料里」是开工前要先看的事实。
_Avoid_: 数据源、数据集

**能力与来源分开，来源可扩展。** 九款游戏的冷启动审计里，九处缺口有五处是同一个病：能力早就有，入口只认一种输入。`extract-scenes` 只认压缩包、`lua-extract` 只认包内、`superseded_tools` 只认项目内两个目录、`layout` 声明的路径没人读，后来又添了一处：`lint --repo` 只认带 `revenant.toml` 的目录，于是仓库根 `notes/` 下的跨款汇总篇全在视野之外（#67，同一形状的第六次）。第七次出现时应当考虑把它变成一条守卫，而不是再补一个入口。所以 `extract-scenes` 的来源现在有三种并列：包（默认）、`--ggm`（构建烤进播放器的那些序列化文件）、`--from-dir`（已经落盘的一批 bundle——从设备拉的、从 CDN 取的）。**落点也是调用方的**：`--out` 三种来源一律生效，相对路径按当前目录解。有一款的下游脚本读的是它自己那份提取脚本产出的路径，解法是让落点可指定，而不是让 revenant 学会那一款的目录名——目录约定是游戏事实。

但 `--out` 只移动**根**，这句话要说全：根以下的形状（按类型分的树、TextAsset 的 `.bytes`、清洗过的文件名）是 revenant 对每一款统一的布局，为了对上某个项目旧脚本的 `*.bin` 去掰弯它，正是这个标志要避免的那件事。所以那个脚本能删，但读它旧路径的三个下游脚本要改一次前缀与扩展名——这是项目侧一次性的编辑，不是 harness 该长出来的三个旋钮。

汇总行报的是**真正写进去的那个根**，不是习惯写的那个，也不是某一份报告的父目录：`--all` 时报告横跨多个组，取第一份的 `dirname` 会点名一个「多个之一」的目录。给了值却不用、或者报错地方，都是 note 会照抄的假话。`--out` 给了却没有值当场拒绝而不是退回 `res/`——把调用方的落点丢掉再把这次运行报成成功，与同一条命令上的 `--from-dir` 行为相反；指向一个已存在的非目录也在这里说清楚，而不是从导出里面抛一个 traceback 出来。三条走的是同一个 `assets.export_blob`，因为「拉回来的 bundle 和包里的 bundle 数出来的数要能比」正是分层的意义；`--from-dir` 直接调 `contrib.cache.export_bundle_dir`，那份实现本来就在，缺的只是命令入口。目录里不是 bundle 的文件（每个 Unity 缓存都有 `__info`）**计数但不隐藏**——包括点开头的目录，那里正是 Unity 自己的缓存所在，而根目录下的点文件本来就在计数，两边不一致且都没打印。读不动的单个文件记在那一条的报告上、不掀掉整批：调用方指的是从 CDN 拉回来的 1,259 个文件。目录本身不存在会报错——「路径写错了」和「这批下载里没有 bundle」是两件事，`os.walk` 对两者返回同样的空。

判「读进来了」看的是**这团字节解开了没有**，不是「导出了几个东西」：只装 AnimationClip 的 bundle 会写出名字清单、但一个计数都不加，按导出数分栏就会把它报成「不是 bundle」——又是把我们自己的缺口说成文件的内容。解压出来的形态另记一栏，不混进 `exported`：那个 Counter 的键是 Unity 类型名、会原样进 `_bundle.json`，塞一个 `TextAsset.gunzip` 进去等于伪造了一个类型。

Lua 一侧同一条：`lua-extract` 是一串动作（从包里抽 → 解密 → 解包 → 反编译），入口焊死在包上（`extract_scripts()` 直接开 APK）。有一款的 3,608 个 `.lua` 是从 CDN 取回来的、就摆在目录里，于是最后那一环只能手工跑。`lua-decompile <目录>` 只做那一环——解密和解包是包的问题，已经落盘的文件两样都过完了。是不是 Lua 按**魔数**判，`\x1bLua` 和 `\x1bLJ` 自动分流到 unluac 与 ljd2。不是字节码的 `.lua` 原样拷过去：把源码喂给反编译器会每个文件都失败、读起来像「这棵树坏了」，而只数不拷会让一棵树里已经能读的那一半对 `lua-grep` 隐形——落点默认是 `lua/<版本>/` 正是为了避免这个半个答案。扩展名在这里只决定**拷不拷**，不决定它是不是 Lua，那个问题魔数已经答过了。

四个桶全部报出来：字节码、明文源码、既不是字节码也不是 `.lua` 的、以及**我们读不动的**。最后一个必须单列——读不动是我们的缺口，混进「不是 Lua」就成了在陈述那个文件的内容。

相对路径**原样保留**，不绕道点号模块名。第一版把 `a/b.lua` 转成 `a.b` 再转回 `a/b.lua`，于是它和 `a.b.lua` 落到同一个文件、报告数了两个而磁盘上只剩一个；CDN 上的树满是 `main.9f2a.lua`。两个输入抢同一个落点时报出来、不覆盖——包含两个的计数是一个磁盘上没有东西支撑的数字。索引建在**真正写进去的那棵树**上，不是默认那棵：给了 `--out` 却索引默认目录，既让 `--out` 搜不了，又会往一个没人写过的目录里盖一份空索引，运行产物就是这么混进 commit 的。

有没有反编译器**只问一次**，不是每个文件问一遍：两样都没有的话，3,608 个文件就是 3,608 次注定失败的 JVM 启动，而答案每次都一样。$REVENANT_LJD2 缺失时报出原因而不是静默降级。

顺带清掉 `layout.PackageLayout.lua_roots`：声明在表里、没有任何消费方，是 #41 / #45 / #47 之后同一个缺陷的第四次。这次选删不选接：`bundle_roots` 必须挑一个根（下游全靠它拼路径）、`ggm_paths` 是精确文件名，而 Lua bundle 是**按形状**在整个包里找的，本来就不需要根——字段没有消费方是因为它没有活干。接上去反而会把根列表之外的脚本搜丢，那是拿整洁换来的退化。

A/B 实验名册整份随包：有哪些实验、各自动了哪些条目的哪些字段、以及**两个取值**，全在构建里；服务端只留「这个玩家分到哪个变体」。所以它是可读的，`contrib.experiments` 读它——一批 variant，每个点名一个条目并带一份 JSON patch，改动的字段写成 `[control, test]` 两元组。**那三个字段名是调用方给的**：它们是某个 CMS 中台 schema 里的具体名字，按 ADR-0004 属游戏事实，所以当参数吃进来，同 `contrib.fetch` 把 HTTP 调用注入；`CMS_KEYS` 只是个默认值，不是本模块声称的知识。

**哪个 guid 是哪个条目、哪个实验是哪个玩法、test 那一臂算不算变强，全是判断和游戏事实，留项目**，解析器只交出 guid 与字段路径就停——同 `table refs` 那条线。两元组的判据是**两个都得是标量**：`[{"coins":[1,2]},{"gems":[3,4]}]` 不是一次改动的两个取值，把它当成改动就是凭空造了一条没人写过的实验臂。不是两元组的叶子单独报出来，不静默丢掉。文档里出现几批 variant 就分几组，不合并——两份名册并成一个桶，读起来就是一份大一倍的名册。

形状来自 #48 那次审计对某一款 CMS 的转录，本仓没有实包样本、也没有仓外可查的上游，所以它与 `docs/playbooks/` 里那种转录自开源上游的格式参考**不是一回事**：那种在上游可查，这种目前**没有任何包坐实过**，模块 docstring 里明写着这一点和第一份真实名册能settle 什么。

加固自己的分块解密 wrapper 由 `contrib.decrypt.decrypt_blocks` 驱动：写块进 scratch、按 wrapper 的调用约定摆好寄存器、从 entry 跑到 ret、把结果读回来。**模拟器是注入的**——四个方法连签名一起写死在 docstring 里，那是 Unicorn 的签名，所以 `Uc` 实例原样就满足；revenant 一行都不 import 它，没装的人不受影响，注入一个纯 Python 的假执行器就能测。四个方法**在第一块跑之前先查**：调用方的对象少一个、或者 `emu_start` 少收一个参数，就直接说出来，而不是变成几千行一模一样的「block failed」——把我们自己的契约错误报成数据的问题，就是 `no-index` 那条错。

地址、寄存器分配与顺序、scratch 地址、块大小，以及**跑之前必须先放进内存的字节**（程序块、密钥块、跳转表——跳转表在文件里通常是空的，得从活进程里读一次），全是 per-build 的事实，全部当参数吃进来，字节走 `preload`。

三条关于「别把不知道说成知道」：某一块跑挂了记下来、后面照跑，那一块的字节原样留着密文（57 MB 是几千块，死在第一块会丢掉后面全部，而且分不清是块坏还是 entry 给错了）；**读回来的字节数不对就算这一块失败**——往 `bytearray` 里切片赋值时短读会让它收缩，后面每一块的落点全错，而结果看起来完全正常；读回来的地址单独一个字段，wrapper 不在原地解密时从 `body` 读会拿回密文而没有任何东西说这件事。跑完没报错也**不等于**解出来了，只等于没抛异常且字节数对得上，那是读的人自己判断的事。

导出时按**魔数**认 gzip 的 TextAsset：某款的 26 个 CMS 库有 7 个是 gzip 过的 JSON 而不是 FlatBuffers，导完之后没有任何东西说它是什么，得挨个 `file` 一遍。原始字节原样落盘（note 引用的是它的大小和 md5），解压后的形态写在旁边，名字是原名加上对它做了什么。magic 说是 gzip、body 却解不开的，报出来而不是丢掉——那是「这个文件不是它头部声称的东西」的唯一信号。

**Dig（深挖）**:
人指方向的那条支线。一条指令 = 业务问题 + 完成判据 + 可选入口线索；结束时判据逐条勾掉、每个候选都交代去向。只有「开」和「收」两个动作。
_Avoid_: 任务、调查（"task" 太泛）

#### 终态：一个问题查到什么程度

不是术语表条目，是四个取值。它回答「关于这个问题我们现在知道什么」，与问题从哪儿来无关——广度扫描的槽位是一种载体，一篇 note 也是。原先只写在下面冻结那一节的 Cell 词条里，等于把词汇锁在了 pack 后面（见 ADR-0003）。

| 取值 | 含义 |
|---|---|
| `meets_threshold` | 已填且达标 |
| `insufficient_evidence` | 已填但证据不够 |
| `confirmed_absent` | 查过，确认不存在 |
| `out_of_reach` | 证据够不到 |

「够不到」必须说清是哪一侧：`input_missing`（输入侧缺，补上输入之后应当自动回队）或 `output_doubtful`（输出侧存疑，补不了）。两者补救相反，混成一个就没法用来调度。

**gap marker** 是另一回事：结论成立，但其中某一块拿不到——`server_side` / `native_blackbox` / `stripped_symbols` / `not_in_package`。开放词表。

note 用一行读者看不见的注释自报终态，`revenant lint` 读它：

```markdown
<!-- re-state: axis=econ slot=05 state=out_of_reach reach=input_missing gap=server_side -->
```

`axis` 与 `slot` 由项目自己定义（有哪些维度是「我们选择研究什么」的事实，不是 revenant 的事），revenant 不校验取值；`state` 与 `reach` 用上表的词，写错会被 `lint` 报出来。`revenant lint --repo --json` 把仓库根以下每个项目的这些声明汇总成一份机读输出。

**仓库根的 `notes/` 也是 note。** 一个没有 `revenant.toml` 的仓库根不是 project（项目的标记是 `init` 写的那个，不做第二次判断），但它下面的 `notes/` 里放的是跨款汇总篇——九款各自的 note 被逐篇检查，而汇总它们、并且最容易写错的那一批一篇都没查过。所以 `--repo` 单独收一次仓库根的 `notes/`，发现挂的不是某个项目名，而是本仓已有的那句「这东西不属于任何一个项目」（同共享 `_tools/`）。根**恰好**带 `revenant.toml` 时不查两遍，判据是路径相同。

#### 跨款结论声明它靠哪些格子

四种失效里只有一种在写下的那一刻就可判定：一篇声称覆盖九款的 note，去查那九个格子填了没有，是一次查表。另外三种（一款推翻另一款、后一个维度推翻前一个、汇总回写单款）要的是一张「哪条结论依赖哪条证据」的图，而 note 是人写的散文，那张图只能靠人维护——不做，理由记在 #67。

```markdown
<!-- re-rests-on: axis=econ slot=07 expect=9 -->
```

与 `re-state` 同形、同一条解析路径（两个长得一样的标记配两个正则，只在没人改过它们的时候一致）。`expect` 是**这一轮研究有几款**，必填：仓库里有几个项目 `lint` 自己数得出来，但那不等于这一轮覆盖几款——并排放着一个品类不同的项目，自动数出来的数会悄悄变大。声明与实际不一致时相信声明、报出差异，因为那正是要暴露的东西；没有它，一篇声称九款的 note 在只找到一款时会安静通过。

判断放在整个 `--repo` 扫描之后——那是唯一一处同时握着所有项目终态的地方，`lint_note()` 看见的是一个文件。两种失败**分开报**，因为补救相反：格子在但**不是 `meets_threshold`**（warning，去补证据），与格子**数量少于 `expect`**（warning，去写那一篇）。数量**按项目数**，不按 note 数，并且在输出里说出来：`expect` 数的是款，一个项目把同一格写成两篇就会替一款没人看过的游戏占位（同 Lua 行数按文件计那条）。**只报少、不报多**：`expect` 存在的理由正是「仓库里有几个项目 ≠ 这一轮覆盖几款」，报「找到 10、声明 9」就是在这个字段唯一为之而生的场景里不相信声明。未达标的三种状态各报各的名字、不合成一句「未达标」：`confirmed_absent`（查过，这一款没有这个机制）本身可以是合法的依据，该不该据此下笔留给读的人——同 `census` 只报事实不下判断。标记本身写错（`expect` 不是数字、缺 `axis`/`slot`/`expect`、重复标记、指向一个一个格子都没有的 axis+slot）是 error，与 `unknown-state` 同一档；`lint` 仍然返回 0，这条是报告不是闸门。

### 配置与数值

**Table（配置表）**:
一张解出来的配置表，有行有字段，不管它原来是 protobuf、FlatBuffers、Luban、Lua 还是裸 JSON。把容器解开是 `pb-schema` / `fb-read` 那一层的事，经济分析发生在那之后——而那一步一直是手写的：53 篇经济 note 里 `revenant` 作为命令只出现在 1 篇，`json.load` 出现 86 处、`glob` 72 处、`Counter` 60 处。`revenant table list` 报出这个项目有哪些表、各多少行多少字段、以及**由哪个 reader 读的**；`revenant table census <表>` 逐字段报填充率、去重值数与高频取值，是读一张陌生表的第一步；`revenant table diff <表A> <表B>` 比两张表，路径可以指向另一个项目；`revenant table refs <表>` 数这张表在各语料里被点名几次——每个 C# 源码根各算各的，加上元数据字符串与 Lua 树，从不相加。可导入面是 `revenant.tables.rows(表)`，顶层 wrapper 键已展开。
_Avoid_: 配置文件、数据表（"表"指解出来的行与字段，不指它在包里的那个文件）

reader 那一列是刻意的：语料靠自动发现，猜错必须看得见。四个落点：protobuf-JSON 的 id→行映射（`json-idmap`）与裸 JSON 的行数组（`json-rows`）各有一个内置 reader；**二进制 blob** 按项目说的走 `luban` 或 `flatbuffers` 两个 reader 之一；**Lua 表构造式**走 `revenant/luatable.py`——有两款把配置写成 Lua table，`lua-extract` 早就把它解出来了，所以 `lua/` 也进了扫描根。那不是完整的 Lua 解析器，只读「一个表构造式」和里面会出现的值；读不动的东西报错而不是跳过，因为一个返回函数的模块不是配置表，悄悄丢掉读不了的字段会把它报成一张少了几列的表。读的是文件**返回**的那张表，不是它写下的第一张：先定义 `Defaults` 再定义 `Config`、最后 `return Config` 的文件，按第一个 `{` 锚定会交出 `Defaults`——两百行变一行，自信且无声，而「给一个自信的错数字是更坏的选项」这条在这里最要紧。文件里出现 `function` 或 `require`（在字符串与注释之外）就直接判为源码而不是配置，交出一个空表比报错更糟。

判定一个目录是不是 Lua 语料靠**形状**不靠名字：`lua/<版本>/` 是整个反编译出来的游戏。形状要两半都成立——「表里套表」加上「没有代码」：只看嵌套字面量的话，任何带表常量的类（`UIPanel.LAYERS = { hud = { z = 1 } }`）都会中招，而且是被当成读出来的两行表，比报成读不了更糟；只看关键字的话，位置式的 `return { {id=1}, {id=2} }` 又会漏掉。

Lua 那边的行数**按文件计**，并且在输出里说出来：有一款把同一张表的变体拆成 62 个文件而游戏只加载 47 个，全加起来会多算 34%；哪些会被加载是那一款 loader 的事实，所以这里报的是「读了几个文件」，不是「有几张可加载的表」——给一个自信的错数字是更坏的选项。**没有 reader 的形状一律报错，绝不返回空表**：「这张表是空的」与「这张表我们读不了」是两个不同的事实，把后者报成前者就是凭空造了一个结论。

两个二进制 reader 划出的是同一条线，也是「什么进 revenant」最清楚的一个例子。**格式通用，进 revenant**（`revenant/luban.py`、`revenant/flatbuffers.py`，与 `protobuf.py` 并列）；**schema、外层容器与密钥、哪个 `.bin` 装的是哪个 root、CMS 的泛型容器名，全都是游戏事实，留项目**——schema 是一份具体的类名与字段清单，容器是某一款的加解密。所以 `[tables] luban_schema` 指一份 JSON、`luban_container` 指一个暴露 `decode(bytes) -> bytes` 的 Python 文件（照 `[metadata] decryptor` 的先例）；FlatBuffers 侧对应 `fb_schema` + `fb_roots` + `fb_containers`，一个 root 里有多个 vector 时用 `Root#Field` 指定哪个是行。项目一旦在这些键里点了名，那个目录**即使只有 `.bin`** 也算语料——CMS 库正是这个形状，而「点名」就是自动发现那条嗅探规则本来要替代的证据。schema 短一个字段时，行照样解得出来而且全是错的，唯一的信号是字节没用完——所以「剩余字节」是报在那张表上的错误，不是脚注。

census 只报事实不下判断：一个 `cost` 字段里 652 行是同一个值、其余是八位数，那是资源 id 不是数量——但「这是 id」是读的人的结论，写进 note，不写进命令的输出。

跨游戏比数值之前必须先化到同一格式，这件事在经济分析里栽过两次、两次都得出**相反的结论**：同源不同 codegen（`costId` 对 `CostId`）直接比，八张核心表全被判成「不同」，归一化之后逐值全同；另一次是一侧的 tag 没还原、字节被渲染成十六进制串，`[1]` 撞上 `["01"]`，报出「929 行全不同」，解回 varint 后 929 行逐值相同。

所以 `table diff` 分两件事做。名字对不齐用 `--normalize-names` 修。**两侧不是同一种东西的那一列修不了**——那是解码问题——但它绝不能被报成内容差异：这种列单独列出、标明「这读起来是解码差异不是内容差异」，并且**不计入**上面的差异行数——被它压掉的那些行报成 `undetermined`（无法判定）而不是「相同」，因为「我们比不了」不等于「它们一样」。判据是整列的取值形状而不是单行：一行 `[1]` 对 `["01"]` 说明不了什么，929 行都这样说明两边的解码器不一致。而且判据要窄：**一侧是文本、另一侧不是**才算，`int` 对 `float` 是两个能好好比较的数，把它算成不可比会把真实差异藏起来——那是同一个坑反过来踩。

行怎么对齐也靠结构不靠名字：取第一个在两侧都「每行都有且不重复」的字段做键，没有就按位置对齐并说出来。挑「叫 id 的那个」是按名字推语义，属游戏事实。

`refs` 有一条硬规矩：**只报事实，绝不判「死表」。** 九款里四款有「列名完全可读、引用为 0」的表，所以「拿一张表当证据前先数它被引用几次」成了规矩；但零引用不等于没被加载——有一款的 `TableParser` 在解析任何表之前先读一批覆盖行，专属引用天然为 0。所以命令的输出里不出现 dead / unused 这类词，只给数字，「这张表是死的」是判断、写进 note，与 ledger「确定性代码只写事实」同一条线。各语料**分开报、不合并成一个数**；语料本身不在时说「查不了」而不是报 0——把我们自己没装好报成作者的零，就是 `lint` 的 `no-index` 那条错。判据同 `no-index`：看**有没有真的加载到东西**，不是看目录在不在——`src/<版本>/` 存在但一个 `.cs` 都没有，说明 seed-src 没跑过，报成「0 次」就是把我们的缺口说成作者的答案。C# 一侧有几个根，问 `csharp` 要，不在这边重抄一份：托管源码本来就是两个根（scaffold 与热更恢复出来的那个），`[csharp] roots` 还会整体取代这一对，各算各的一行。抄第二份的代价是实测过的——`refs` 一度只读 `src/<版本>/`，于是一款把加载逻辑放在热更程序集里的游戏，明明有树可搜，拿到的是「查不了」。表名与行类名一起查，因为 codegen 出来的两个名字常常不同，只查一个会查出零来；行类名从 schema 的**声明**里取（FlatBuffers 是那个 vector 的元素类，不是 root 类），所以这条查询一行也不解码。两个名字各自命中几次要报出来，包括 0——「4 次全是行类名、表名一次没有」和「一半一半」不是同一件事。

有三处「说不出来」也必须说出来：本项目已知的其他表少于 5 张时，「点名很多表的站点」这条分法根本触发不了，于是通用加载器的命中与专属引用打印得一模一样；扫描撞到文件数上限时，那个数是这些文件里的数、不是整棵树的；以及路径指向另一个项目时——表按**它自己项目**的 schema 解（同 `table diff`），但版本号与 metadata blob 只能从你**当前站着**的项目读，所以搜的语料是这边的，输出里直说。三条都写在输出里。

发现靠形状，不靠名字。目录约定与文件命名约定都是游戏事实（见开头那条判据），不写进 revenant；判据是「这个目录里有没有能当表读的文件」。发现也是有界的：只走 `res/` 与 `decompiled/`，深度、打开的目录数、单个目录读的条目数各有上限，任何一条咬到都会在输出里说出来——`status` 与 `table list` 都是查询命令，纪律同 `superseded_tools` 的共享目录扫描。落点不在扫描范围内时，`revenant.toml` 的 `[tables] dirs` 直接指定并**取代**自动发现；但不依赖它，#50 的教训是「靠人记得配不管用」。

### 广度扫描（可选扩展，冻结中——见 ADR-0002）

这一族术语描述的是「一份提纲反复用在多款游戏上」的扫描机制。它设计完整（决策见 #1 地图）但尚无第一份真实的领域包，因此冻结：术语保留、代码保留、默认不出现在命令表与 skill 里，`[packs]` 启用后才可见。第一份真实的包出现时再决定它回主线还是退役。

**Domain pack（领域包）**:
一份可反复用在不同游戏上的调查提纲，落到磁盘是一个目录。harness 读其中的机器部分，agent 读其中的正文。三层叠加：内置、项目覆盖层、第三方。
_Avoid_: 模板、schema、配置

**Slot（槽位）**:
提纲里的一道题目，例如「归因怎么做的」。增长变现那份包有 24 个。**派活的单位**——一个 agent 会话负责一整个槽位。
_Avoid_: 章节、模块、领域

**Facet（切面）**:
每个槽位固定分六段作答：职责边界、API 契约、数据模型、核心机制、桥接与后端、平台差异。六段属 L2 全局共享，包只能裁剪不能新增第七段。
_Avoid_: 小节、维度

**Cell（格子）**:
一个槽位的某一个切面，24 × 6 = 144 个，**记账与证据门槛的单位**。它的状态用上面「终态」那四个取值，不是 Cell 独有的一套。「跑没跑过」不是第五种状态，是独立字段——它说的是我们干了什么，不是我们知道什么。
_Avoid_: 条目、单元格

**Probe（探针）**:
包里预置的、harness 直接执行的检索模式（类名正则、字符串常量、方法签名），跑完自动产出命中/零命中记账。必须是模式，不能是精确类名——写死类名的包无法复用到下一个游戏。人给深挖指的方向也编译成探针，走同一个执行器。
_Avoid_: 关键词、检索线索、搜索词

**Ledger（台账）**:
与 `notes/` 物理分离的机器可读文件，记录每个格子的探针集、索引版本、状态与证据条目。代码只往里写事实，agent 的判断经 CLI 回填。事实层与结论层同文件就再也拆不开。
_Avoid_: 报告、日志、索引
